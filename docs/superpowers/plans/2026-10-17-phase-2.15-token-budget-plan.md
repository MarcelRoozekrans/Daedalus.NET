# Phase 2.15 Token Budget Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A manufacture run completes on the shipped configuration, each agent turn is stopped by a per-role token
ceiling sized from measured turns, a stopped turn's spend reaches `/costs`, and the budget is documented.

**Architecture:**
- `BudgetedSubagentRunner` picks a ceiling per agent name from a new `Thalos:Workflow:TurnBudgets` section, instead of
  stamping `DetachedRuns:MaxTotalTokens` on every workflow turn.
- A failed node's turns are captured by a Daedalus `IAgentNotificationPublisher`. It is called inside the turn's
  async flow and writes into an `AsyncLocal` scope that a new runner decorator opens around each node dispatch. The
  decorator records the captured usage as an ordinary `node-usage` record, which cost analytics already counts.
- No Thalos change.

**Tech Stack:** .NET 10, Thalos.NET 0.17.0, xUnit with AwesomeAssertions and NSubstitute, EF Core on Postgres, and
Aspire for the live steps.

**Spec:** `docs/superpowers/specs/2026-10-17-phase-2.15-token-budget-design.md`

## Global Constraints

- **The cap counts every token**, input plus output, with cache reads at full weight. Thalos' counting does not
  change, owner 2026-10-17.
- **The sizing rule:** ceiling = the larger of 1.5 × the measured maximum and 2 × p90, rounded up to the next
  25,000.
- **Initial ceilings, from the 75 turns of 2026-10-14/15:** `implementer` 875000, `reviewer` 600000, `Default`
  875000. Task 3 recomputes them from the larger sample.
- **Deadline:** every workflow turn keeps `DetachedRuns:DeadlineSeconds` (300). `DetachedRuns:MaxTotalTokens` stays
  the scout's (150000) and no longer reaches workflow turns.
- **Agent names:** they are the catalog's `AgentDefinition.Name`, matched case-insensitively: `implementer`,
  `reviewer`, `Daedalus Architect`.
- **Configuration and packages:** no `Version` on a `PackageReference`. Every new `[Validate]` DTO is registered in
  both places, per CLAUDE.md.
- **Logging:** `[LoggerMessage]` for new logging, with no message content in log values, only counts and ids.
- **Commits:** body lines ≤ 100 characters, no nested parentheses, the trailer
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, no session URLs.
- **Tests:** every assertion carries a `Red:` line in its doc comment naming the change that turns it red, and that
  change is applied once and seen failing.
- **Integration tests** run with `DOTNET_USE_POLLING_FILE_WATCHER=1`. Without it the VM's inotify limit fails about
  125 tests.

## Review Focus

1. **A run with the squad off.** Every node runs as `Daedalus Architect`, which must get `Default`, not 0 and not the
   scout's 150000. Task 1 pins it.
2. **A lens pass that fails after two passes succeeded.** All three turns' usage is recorded once, in one record.
   Task 2 pins it.
3. **A node that fails with no notification seen,** such as a validation failure before any model call. Nothing is
   recorded, and nothing throws. Task 2 pins it.
4. **Two node dispatches of different runs on one host at once.** Each scope sees only its own turns, because
   `AsyncLocal` flows per dispatch. Task 2 pins it.
5. **A redelivered failed node at the same seq.** The unique index dedupes it to one record, and the second append
   reads as "already recorded". Task 2 pins it.

**Interfaces:**
- Consumes: Thalos `IAgentNotificationPublisher.PublishAsync<T>`, `TurnCompletedNotification.Usage`,
  `TurnFailedNotification.Usage`, and `WorkflowCaller.Run`, which supplies `Id`, `CurrentSeq` and `CurrentNode`.
- Produces:
  ```csharp
  internal sealed class NodeTurnUsageScope            // AsyncLocal<NodeTurnUsageScope?> Current
  {
      public static NodeTurnUsageScope Begin();       // sets Current; Dispose restores the previous value
      public void Add(TurnUsage usage);               // thread-safe
      public IReadOnlyList<TurnUsage> Turns { get; }
  }
  internal sealed class TurnUsageNotificationPublisher : IAgentNotificationPublisher
      // adds TurnCompleted/TurnFailed usage to NodeTurnUsageScope.Current when one is open; never blocks or throws
  internal sealed class FailedNodeUsageRunner(ISubagentRunner inner, NodeUsageRecorder usage) : ISubagentRunner
  // NodeUsageRecorder:
  public ValueTask<bool> RecordFailureAsync(Guid runId, long seq, string node, string? startedById,
      IReadOnlyList<TurnUsage> turns, CancellationToken ct);
  ```
- Behaviour:
  - `FailedNodeUsageRunner` opens a scope only for a `WorkflowCaller` request. It runs the inner runner and returns
    its result unchanged.
  - On a failure with at least one captured turn, it calls `RecordFailureAsync` with the run's `Id`, `CurrentSeq`,
    `CurrentNode` and starter.
  - `RecordFailureAsync` sums the turns. When there are two or more models, it builds the per-model split the way
    `HoldPasses` does, through `NodeUsage.WithSplit`. It counts `ManufactureTelemetry.RecordTokens` per part and
    appends a `node-usage` record through the existing `AppendAsync`, including its unique-index dedupe.
  - On success, nothing changes: the completion path records as today.
