# Phase 3.4 Controllers to Minimal APIs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Daedalus.Api` serves its whole HTTP contract from minimal API endpoints instead of MVC controllers, the
same on the wire, with source-generated JSON, so MVC leaves the API and 3.6 can publish it native.

**Architecture:** First a checked-in snapshot of the endpoint table and a set of body-shape tests, both green on MVC.
Then shared endpoint infrastructure beside MVC, then one controller per task with both stacks live (the controller is
deleted in the task that maps its endpoints), smallest first, and MVC removed last. Each controller becomes a public
static endpoint class: one `Map…Endpoints` extension that builds the route group, and one static handler per endpoint
returning typed `Results<…>`, which the ported tests call directly.

**Tech Stack:** .NET 10, ASP.NET Core minimal APIs with the request delegate generator, `Asp.Versioning.Http` 10.2.1,
System.Text.Json source generation, ZeroAlloc.Validation, xUnit, FluentAssertions, NSubstitute, Testcontainers
Postgres, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-31-phase-3.4-minimal-apis-design.md`, and the impact analysis
`docs/superpowers/specs/2026-10-31-phase-3.4-minimal-apis-impact-analysis.md`, which corrects the design on six points
and records four owner decisions of 2026-10-31. Where the two differ, the impact analysis wins. Its "Affected Files"
table is the file list; its "Risk Register" is what reviewers check against.

## Global Constraints

- **No contract change.** Status codes, bodies, `Content-Type`, `Location`, `api-supported-versions`, policies and
  rate limits stay as MVC serves them today, including #366 (problem bodies as `application/json` on 12 controllers)
  and #326. The 14 `catch (Exception)` blocks stay, body `{ "error": "Internal server error" }` (#426).
- **The snapshot file changes only through a named ruling** in `docs/plans/2026-10-31-phase-3.4-rulings.md`; the
  allowed kind is a response type name where MVC declared none.
- **No route is served by both stacks:** a controller is deleted in the task that maps its endpoints.
- **No reflection fallback** in the endpoints' JSON resolver chain; `ApiJsonSerializerContext` is first and alone.
- **No local Native AOT publish on the agents VM** (CLAUDE.md, owner 2026-10-22). CI's `aot-analysis` counts.
  `eng/aot/baseline.json` moves only to the count CI reports, in the task whose push changed it.
- **No suppressions or workarounds as fixes:** no `#pragma warning disable IL*`, no `<NoWarn>` for IL2xxx/IL3xxx or
  RDG diagnostics (`RDG0xx`), no `UnconditionalSuppressMessage`.
- **Two-place validator registration stays** (CLAUDE.md): every `[Validate]` DTO keeps its `IValidationAdapter` line
  in `Program.cs`; `Integration/Architecture/CleanArchitectureTests` stays green.
- **Every new or ported assertion carries a `// Red:` line** naming the handler change that turns it red, applied once
  and seen failing. Ported tests keep their cases one for one.
- **Central package management:** versions only in `Directory.Packages.props`, with a history comment in the file's
  format.
- **Commits:** conventional, release-please parseable; body and footer lines at most 100 characters; no nested
  parentheses; **no `Co-Authored-By` trailer, no Claude signature, no session URL** (owner's global rule, 2026-10-25,
  which overrides older plans); `dotnet format` before committing.
- **Branch:** `phase/3.4-minimal-apis`, pushed after every task with `git push origin HEAD:phase/3.4-minimal-apis`.
  Release-please stays on hold (owner, 2026-10-31).
- **`dotnet build` and `dotnet test` one at a time** on the shared VM.
- **Rulings:** every call a task makes that the spec does not is appended to the rulings doc as `R<n>`, with what it
  costs if wrong.

## Review Focus

1. **A malformed query value,** `GET /api/schedules/{id}/runs?take=abc`: MVC answers 400 `ValidationProblemDetails`
   with "The value 'abc' is not valid for take."; minimal APIs answer a bare 400. Pinned in Task 2, built in Task 5.
2. **An empty body, or the JSON literal `null`, on a POST:** MVC answers 400 with "A non-empty request body is
   required." and the parameter's implicit-required error. Pinned in Task 2, built in Task 5.
3. **An `api-version` the API does not have,** `?api-version=2.0`: today's status and body, not a 404 from the new
   stack. Pinned in Task 3.
4. **A client that disconnects mid-stream** on `POST /api/agents/sessions/{id}/turns/stream`: no 500, no unhandled
   exception logged, and with `Accept-Encoding: gzip` no `Content-Encoding` on the stream. Pinned in Task 16.
5. **`Accept: application/xml`** on a JSON endpoint: MVC serves JSON (no XML formatter, no 406); the endpoint does too.
   Pinned in Task 3.

|---|---|---|

| `ProblemContentType` | `public sealed record ProblemContentType(string Value)` | Group metadata; `ProblemContentType.Json` = `application/json`, `ProblemContentType.ProblemJson` = `application/problem+json` |
| `ApiProblem` | `public static class` | `ApiProblemResult Of(HttpContext context, int statusCode, string? detail = null, string? title = null, IReadOnlyDictionary<string, object?>? extensions = null)`: the same `type`, `title`, `status`, `detail`, `traceId` that MVC's `ProblemDetailsFactory` writes, with the `Content-Type` from the endpoint's `ProblemContentType` (default `application/problem+json`). `ApiProblemResult Validation(HttpContext context, ValidationProblemDetails problem)` |
| `ApiProblemResult` | `public sealed class : IResult, IStatusCodeHttpResult, IValueHttpResult<ProblemDetails>, IContentTypeHttpResult` | Writes its `ProblemDetails` through `ApiJsonSerializerContext` |
| `ErrorBody` | `public sealed record ErrorBody(string Error)` | Replaces every `new { error = … }`; serializes as `{"error":"…"}` |
| `ApiLocation` | `public static class` | `string For(HttpRequest request, string path)`: the exact `Location` string MVC's `CreatedAtAction` emits, as Task 3 pins it |
| `ApiBody<T>` | `public sealed class : IApiBinding where T : class` | `static ValueTask<ApiBody<T>?> BindAsync(HttpContext context, ParameterInfo parameter)`; never fails binding; `T? Value`; `ValidationProblemDetails? Problem` with MVC's input-formatter and implicit-required errors |
| `ApiQuery<T>` | `public readonly struct : IApiBinding where T : IParsable<T>` | `static ValueTask<ApiQuery<T>> BindAsync(HttpContext context, ParameterInfo parameter)`; invariant culture; the parameter's default when absent; `T Value`; `Problem` with "The value '{raw}' is not valid for {name}." |
| `IApiBinding` | `public interface` | `object? BoundValue { get; }`, `ValidationProblemDetails? Problem { get; }` |
| `ZeroAllocValidationEndpointFilter` | `internal sealed class : IEndpointFilter` | For each `IApiBinding` argument: a `Problem` answers first; otherwise the `IValidationAdapter` for `BoundValue`'s type, same `ValidationProblemDetails` as the MVC filter. | `WorkflowEngineEnabledEndpointFilter` | `internal sealed class : IEndpointFilter` | ctor `(WorkflowConfig config)`; disabled answers `ApiProblem.Of(ctx, 503, DisabledManufactureRunStarter.DisabledMessage)` |
| `AgentErrorResults.ToProblem` | extension in `src/Daedalus.Api/Agents/AgentErrorResults.cs` | `ApiProblemResult ToProblem(this AgentError error, HttpContext context)`: same title, detail, status and `code` extension as `ToActionResult` |

### Port recipe (Tasks 6 to 19)

Every port task follows these steps; its own section lists only what is particular to that controller.

1. **Read** the controller, its tests and its snapshot lines. The snapshot lines are the target.
2. **Port the tests first,** to call the handlers (`await XEndpoints.Handler(args…)`) and assert on the typed result
   (`result.Result.Should().BeOfType<Ok<T>>()`, `.Value`, `ApiProblemResult.StatusCode`). A handler that needs the
   user takes `ClaimsPrincipal user` or `HttpContext context`; tests pass a `DefaultHttpContext` with `User` set and
   `RequestServices` from a `ServiceCollection`. Drop `AddMvcCore().AddApiExplorer()` setup. Cases one for one; each
   assertion keeps or gains a `// Red:` line.
3. **Run them, expect compile failure** (the handlers do not exist).
4. **Write the endpoint class.** Group: `app.MapGroup("<route>").WithApiVersionSet(versions).HasApiVersion(1.0)`,
   `.RequireAuthorization("<policy>")` (bare `[Authorize]` is `.RequireAuthorization()`),
   `.WithMetadata(ProblemContentType.Json)` when the controller had `[Produces("application/json")]`. Per endpoint:
   the verb, the route template exactly as MVC's (constraints included), `.RequireRateLimiting("<policy>")`, and
   `.Produces…`/`.ProducesProblem` matching every `[ProducesResponseType]`. `[FromQuery]` value types become
   `ApiQuery<T>`; `[FromBody]` becomes `ApiBody<T>`. `Ok(x)` → `TypedResults.Ok(x)`; `NotFound()`, `Unauthorized()`,
   `Conflict()`, `BadRequest()` without a body → `ApiProblem.Of(context, <status>)`; `Problem(...)` → `ApiProblem.Of`;
   `new { error = … }` → `ErrorBody`; `CreatedAtAction` → `TypedResults.Created(ApiLocation.For(request, path), body)`.
   Every catch-all stays a `catch (Exception)` returning `500` with `ErrorBody("Internal server error")`.
   `[LoggerMessage]` methods move to a `partial` nested `Log` class, the same messages and event ids.
5. **Register** the class's `Map…Endpoints` in `DaedalusEndpoints.MapDaedalusEndpoints`; register every new request
   and response type in `ApiJsonSerializerContext`.
6. **Delete the controller** and move its helpers; update every comment and `cref` naming it (impact analysis,
   "Cosmetic").
7. **Run:** `dotnet build -c Release` (0 warnings), then
   `dotnet test tests/Daedalus.Tests.Unit`, `dotnet test tests/Daedalus.Tests.Integration`,
   `dotnet test tests/Daedalus.Tests.Playwright.Api`. Expected: all pass; `EndpointContractSnapshotTests` and
   `MvcBehaviourContractTests` unchanged and green.
8. **Commit** `refactor(api): port <Name> to minimal API endpoints`, push, read CI's `aot-analysis`, and lower
   `eng/aot/baseline.json` in a follow-up commit if the Api count fell.
