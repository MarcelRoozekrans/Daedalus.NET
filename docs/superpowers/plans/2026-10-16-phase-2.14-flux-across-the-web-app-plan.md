# Phase 2.14 Flux across the Web app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every page in the Web app keeps its state in a ZeroAlloc.Flux feature and calls the API through a typed
client. Web binds the Application DTOs instead of its own copies, and nothing visible changes except that Home updates
live.

**Architecture:**
- Features follow the 2.12 pattern in `src/Daedalus.Web/State/Tasks` and `State/Runs`:
  - a `[Feature]` state record;
  - `readonly record struct` actions;
  - static reducers;
  - effects as scoped services that call the clients and dispatch.
- Components become `FluxComponent`s that read the store and dispatch.
- Toasts stay in components. Effects report outcomes as state.
  *Superseded by ruling 8 in `docs/plans/2026-10-16-phase-2.14-rulings.md`: writes return their outcome to the component that asked; there is no last-outcome state.*
- The work runs in the impact analysis's order: the DTO copies go first, then the clients, then the shared projects
  feature, then one page at a time.

**Tech Stack:** .NET 10, Blazor WebAssembly, Radzen.Blazor 8.7.5, ZeroAlloc.Flux, ZeroAlloc.Results, xUnit,
AwesomeAssertions, Playwright (Browser).

**Spec:** `docs/superpowers/specs/2026-10-16-phase-2.14-flux-across-the-web-app-design.md`
**Impact analysis (read it per task):** `docs/superpowers/specs/2026-10-16-phase-2.14-flux-impact-analysis.md`. It
holds the affected files, the per-DTO diff, the risk register R1 to R17 and the execution groups. Each task below names
its group and risks; the analysis has the file-level detail.

## Global Constraints

- **No visible change.** The same copy, layout and behaviour at every width, except that Home's run cards refresh live
  on `RunChanged`, which the owner confirmed on 2026-10-16.
- **Browser tests:** existing tests keep what they assert. Only selectors or wiring may change, and each such edit is
  named in the task report.
- **No `HttpClient` in a component.**
  `grep -rn "@inject HttpClient\|HttpClient Http" src/Daedalus.Web/Pages src/Daedalus.Web/Components` finds nothing at
  the end.
- **Effects stay free of UI services.** No `NotificationService`, `DialogService` or `NavigationManager` in an effect.
- **Session renewal:** an effect never stores a `SessionExpiry.SigningInAgain` failure as an error (R9).
- **Lifetimes:** each feature states its lifetime rule on the state record. A page-only feature is cleared by its
  `…Closed` action. `ProjectsState` is never cleared on close (R3).
- **Registration:** each effect is registered in `Program.cs` in the same commit as the first component that injects
  it (R10).
- **Repo rules from CLAUDE.md:**
  - `Result<T>.Success/Failure` explicit;
  - `[LoggerMessage]` for logging;
  - primary constructors;
  - no `Task.Wait`, `.Result` or `async void` outside event handlers. The `async void` handlers in Costs go.
- **Tests:** falsifiability per assertion. Every new assertion has a `Red:` line, with the mutation applied, seen
  failing, and restored.
- **Commits:** conventional; body lines at most 100 characters; no nested parentheses; trailer
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Running browser tests on this host:** use `bash /home/marcel/.cache/daedalus-btest/btest.sh [args]`, which builds
  first, and set `DOTNET_USE_POLLING_FILE_WATCHER=1`.

## Review Focus

1. **Home, then New task, then Tasks, then Home:** projects must never go missing after navigation (R3). Test: Task 3,
   `Projects_survive_home_tasks_home`.
2. **A late Agent stream chunk after a session switch:** it must never land in the other session (R5). Test: Task 9,
   `A_late_chunk_after_a_session_switch_is_ignored`.
3. **A `RunChanged` while Home is showing a card error:** the alert must stay until Retry (R6). Test: Task 5,
   `A_card_in_error_is_not_refetched_by_a_run_change`.
4. **A timed-out repositories read compared with a page-cancelled one:** the first shows "The request timed out.", the
   second shows nothing (R2). Test: Task 2, `A_timeout_is_reported_and_a_cancel_is_not`.
5. **A camelCase PRD response:** it binds into the review step (R8). Test: Task 2,
   `A_camel_case_prd_response_binds`.
