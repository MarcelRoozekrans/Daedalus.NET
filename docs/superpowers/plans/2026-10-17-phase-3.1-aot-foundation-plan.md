# Phase 3.1 AOT Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Native publishing works and is ratcheted in CI, the sandbox host ships native through Thalos 0.18.0, the
JIT baseline is recorded, and the ZeroAlloc.ORM gap audit is ready as a handover.

**Architecture:**
- **Counting:** one shell tool counts each target's distinct trim and AOT warnings. CI compares the counts with
  `eng/aot/baseline.json` and fails on any difference that the baseline does not record.
- **Sandbox host:** `Thalos.NET.Sandbox.Host` becomes AOT-clean in the Thalos repo: generated request delegates and
  reflection-free tool registration. It ships as 0.18.0. Daedalus then publishes `Daedalus.Sandbox` native inside the
  unchanged SDK runtime image.
- **Measurement and audit** are their own tasks, run against the phase's base commit `8173fd55`.

**Tech Stack:** .NET 10 (SDK 10.0.402), NativeAOT with clang 19 and zlib, the `wasm-tools` workload, GitHub Actions,
Docker buildx, ASP.NET Core minimal APIs with the Request Delegate Generator, ModelContextProtocol.AspNetCore, and
Microsoft.Extensions.AI `AIFunction`.

**Spec:** `docs/superpowers/specs/2026-10-17-phase-3.1-aot-foundation-design.md`. The milestone design is
`docs/superpowers/specs/2026-10-17-milestone-3-design.md`.

## Global Constraints

- **No suppressions for trim or AOT warnings.** No `UnconditionalSuppressMessage`, and no `<NoWarn>` for IL2xxx or
  IL3xxx. A `[Requires*]` attribute moved to another member is not a fix.
- **Distinct warnings:** IL2xxx and IL3xxx, deduplicated by `code + file + line + member`, counted per target.
- **The ratchet** fails on any count above **or** below `eng/aot/baseline.json`.
- **Targets:** `src/Daedalus.Api`, `src/Daedalus.Cli`, `src/Daedalus.Migrations`, `src/Daedalus.Sandbox` and
  `src/Daedalus.Web`. All use `-r linux-x64`.
- **Publish command:**
  `dotnet publish <proj> -c Release -r linux-x64 -p:PublishAot=true -p:TreatWarningsAsErrors=false -p:WarningsAsErrors= -p:TrimmerSingleWarn=false`.
  For Web it is `-p:RunAOTCompilation=true -p:SuppressTrimAnalysisWarnings=false`, without `PublishAot`.
- **A publish that fails for any reason other than warnings fails the job.** It is never counted as 0.
- **SDK:** `global.json` pins `10.0.402` with `rollForward: latestFeature`.
- **The JIT baseline commit is `8173fd55`.** The measurement uses `--cpus 2` and the median of 10 cold starts. The API
  load is 200 authenticated `GET /api/projects` at concurrency 10.
- **Secrets:** read the Keycloak `dev` password and client secret from `keycloak-realm.json` at run time, and never
  print them.
- **Thalos:** all packages move to 0.18.0 together. Thalos is released with release-please, `bump-minor-pre-major`.
- **ORM audit:** no ZeroAlloc.ORM issues are filed (owner).
- **Daedalus conventions** follow CLAUDE.md:
  - commit body lines ≤ 100 characters, no nested parentheses, the trailer
    `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, no session URLs;
  - every new assertion carries a `Red:` line, applied once and seen failing;
  - integration tests run with `DOTNET_USE_POLLING_FILE_WATCHER=1`.

## Review Focus

1. **A target whose publish fails outright** (a restore, link or missing-pack error) must fail the job, not count 0.
   Pinned in Task 1.
2. **A warning repeated at one location** across ILC passes counts once, and two warnings at different lines count
   twice. Pinned in Task 1.
3. **The native sandbox host spawning `dotnet`, `git` and `roslyn-codelens-mcp`** inside the SDK container still finds
   the SDK. Pinned in Task 5.
4. **A run whose host fails to start natively** must surface as the existing "sandbox did not become ready" failure,
   not hang. Pinned in Task 5.
5. **Measuring the "before" on `8173fd55` and not on this branch.** The commit SHA and the image digests are recorded.
   Pinned in Task 2.

### Task 1: AOT warning counter, baseline and CI ratchet

**Files:**
- Create: `global.json`, `eng/aot/count-warnings.sh`, `eng/aot/baseline.json`,
  `eng/aot/tests/sample-ilc.log`, `eng/aot/tests/test-count-warnings.sh`.
- Modify: `.github/workflows/ci.yml`. Add an `aot-analysis` job with `needs: version`, plus a step that runs the
  counter's self-test.

**Interfaces:**
- Produces: `eng/aot/count-warnings.sh [--target <Name>|--all] [--check] [--write]`.
  - It prints `<Target> <count>` lines, then the top five root-cause assemblies per target.
  - `--check` exits 1 when any count differs from the baseline, naming the target, its baseline and its actual count.
  - `--write` rewrites the baseline.
  - It exits 2 on a publish failure, naming the target.
- Produces: `eng/aot/baseline.json`, for example `{ "Api": 16725, "Cli": …, "Migrations": …, "Sandbox": 8, "Web": 41 }`.
  The numbers come from the first real run, not from this example.

- [ ] **Step 1: Write the counter's self-test** in `eng/aot/tests/test-count-warnings.sh`. It runs the parser on
  `sample-ilc.log`, a hand-written log with 3 distinct warnings, 1 duplicate and 1 non-IL warning, and asserts a count
  of 3. It also asserts that a log ending in a link error makes the counter exit 2.
  - Red: count every line → 4.
  - Red: treat an error as a pass → exit 0.
- [ ] **Step 2: Run it and see it fail** (the counter doesn't exist yet).
- [ ] **Step 3: Implement `count-warnings.sh`.**
  - It runs the Global Constraints publish command per target.
  - It extracts `warning IL[23][0-9]{3}` lines, normalises them to `code|file|line|member`, and deduplicates with
    `sort -u`.
  - It exits 2 when the publish exit code is non-zero for a reason other than warnings, or when an `error` line is
    present.
  - It is POSIX bash with `jq` for the JSON.
- [ ] **Step 4: Add `global.json`,** then run the counter twice for all targets on this branch. The two counts must
  match exactly; if they don't, fix the normalisation until they do. Write the baseline with `--write`.
- [ ] **Step 5: Add the CI job.**
  - Job `aot-analysis`: `ubuntu-latest`, matrix `target: [Api, Cli, Migrations, Sandbox, Web]`.
  - Steps: apt-install `clang` and `zlib1g-dev`; set up .NET from `global.json`; for Web,
    `dotnet workload install wasm-tools`; then `eng/aot/count-warnings.sh --target ${{ matrix.target }} --check`.
  - Also run the counter self-test in `build-and-test`.
- [ ] **Step 6: Prove the ratchet red both ways** on a throwaway commit pushed to this branch:
  - raise the Sandbox baseline by 1 and see the job fail;
  - lower it by 1 and see it fail;
  - revert, and record both run URLs in the ledger.
- [ ] **Step 7:** Run `dotnet format --verify-no-changes` (unaffected) and the self-test, then commit:
  `ci: ratchet each target's trim and AOT warnings against a baseline`.

### Task 2: JIT baseline harness and measurement

**Files:**
- Create: `eng/measure/measure-api.sh`, `eng/measure/measure-cli.sh`, `eng/measure/measure-sandbox.sh`,
  `eng/measure/load-projects.sh`, `eng/measure/README.md`, `docs/plans/2026-10-17-phase-3.1-aot-baseline.md`.

**Interfaces:**
- Produces: each `measure-*.sh <image-or-binary> [--runs N]` prints one JSON line:
  `{target, commit, digest, cpus, runs, startup_ms_median, startup_ms_p90, rss_idle_mb, rss_peak_mb, image_mb, app_mb}`.
  Fields that don't apply are `null`.
- 3.6 reuses these scripts unchanged for the "after" numbers.

- [ ] **Step 1: Write the scripts.**
  - **API:**
    - `docker compose -f docker-compose.full.yml up -d postgres keycloak migrations`, then wait for health;
    - `docker run --cpus 2` the image, and poll `/health` every 50 ms to the first 200;
    - read `VmRSS` after 60 s idle;
    - run `load-projects.sh`: 200 GET at concurrency 10 with a password-grant token for `dev`, using secrets read
      from `keycloak-realm.json` into variables and never echoed;
    - then read `VmHWM`;
    - get the image size from `docker image inspect`;
    - repeat for N cold starts, removing the container between runs.
  - **CLI:** run the published binary or the `dotnet` DLL against the same Postgres, and time to its ready prompt,
    the first stdout line; read RSS after 10 s.
  - **Sandbox:** `docker run --cpus 2` with a test token (32+ chars) and the `THALOS_SANDBOX_*` variables from
    `SandboxSettings`; time to the first 200 on `/control/ready` with the bearer token; get the image size, and the
    `/app` size via `du`.
- [ ] **Step 2: Check the scripts** with `bash -n` and `shellcheck`, if available. Do a dry run with `--runs 1` on the
  current branch's images to prove the scripts work. These numbers are not the baseline.
- [ ] **Step 3: The baseline run is the controller's live step.**
  - In a scratch worktree at `8173fd55`, build the API image (`src/Daedalus.Api/Dockerfile`), the sandbox image and a
    JIT CLI publish.
  - Run each script with `--runs 10`, then a second time to measure variance.
  - Write `docs/plans/2026-10-17-phase-3.1-aot-baseline.md`: commit, digests, VM, CPU count, both runs and the
    variance.
- [ ] **Step 4: Commit.**
  `chore(measure): add the start-up, memory and size harness and record the JIT baseline`.
