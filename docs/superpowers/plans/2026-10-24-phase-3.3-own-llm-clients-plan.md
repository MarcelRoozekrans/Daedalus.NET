# Phase 3.3 Own Anthropic and Ollama Clients Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Anthropic SDK and OllamaSharp leave every Thalos and Daedalus dependency graph, replaced by our own
AOT-clean `ZeroAlloc.Rest.Anthropic` and `ZeroAlloc.Rest.Ollama`, with behaviour unchanged on JIT and the native CLI
reaching "Application started".

**Architecture:**
- **ZeroAlloc.Resilience 3.4.0** learns to retry an `IAsyncEnumerable<T>` method until its first item (Part A).
- **ZeroAlloc.Rest 3.4.0** learns server-sent events (`IAsyncEnumerable<T>` over `text/event-stream`) and ships two
  new packages from the same repo: `ZeroAlloc.Rest.Anthropic` (messages create and stream) and
  `ZeroAlloc.Rest.Ollama` (`/api/embed`) (Parts B to D).
- **Thalos 0.20.0** replaces the SDK with its own M.E.AI `IChatClient` adapter over `ZeroAlloc.Rest.Anthropic`,
  rewrites the prompt-cache translator onto our request types, and adds `Thalos.NET.Ollama` (Part E).
- **Daedalus** takes Thalos 0.20.0, moves `AgentFactory` to `Daedalus.Agents` onto `IChatClientProvider`, registers
  embeddings through `UseOllamaEmbeddings`, and runs Ollama as a plain container with a pull step (Part F). Then the
  native smoke run, the upstream issue, the live run and the close-out (Parts G and H).

**Tech Stack:** .NET 10 (SDK 10.0.402), Roslyn incremental generators, System.Text.Json source generation with
polymorphism, Microsoft.Extensions.AI 10.11.0, ZeroAlloc.Rest / Resilience / Results, Aspire 13.4.6, NativeAOT (CI
only), release-please.

**Spec:** `docs/superpowers/specs/2026-10-24-phase-3.3-own-llm-clients-design.md`, including its owner decisions of
2026-10-24 and its "My call" items, which this plan treats as decided.

## Review Focus

1. **A long non-streaming turn.** A tool-heavy turn with `max_tokens` 8192 can take minutes; the SDK's default
   timeout was ten minutes, `HttpClient`'s is 100 seconds. Expected: the default stays ten minutes. Pinned in Task 7
   (`The_default_timeout_is_ten_minutes`) and Task 13 (`A_provider_without_a_timeout_uses_ten_minutes`).
2. **A stream that ends without `message_stop`.** The connection drops after a few text deltas. Expected: the caller
   gets an `AnthropicApiException` of type `stream_incomplete`, never a short answer that looks complete. Pinned in
   Task 7 and Task 12.
3. **Tool input split across `input_json_delta` events,** including an empty `partial_json` and a tool with no input.
   Expected: `FunctionCallContent.Arguments` equals the parsed object, `{}` gives an empty dictionary. Pinned in
   Task 12.
4. **Byte-at-a-time reads.** A network read boundary inside a UTF-8 sequence, inside a line, or between `\r` and `\n`.
   Expected: the same events as one big read. Pinned in Task 3.
5. **The key never leaks.** An auth failure, a retry exhaustion or a logged error. Expected: no exception message,
   `ToString()` or fixture holds the key or an `x-api-key`/`authorization` value. Pinned in Task 7 and Task 8.

## Calls this plan makes

The spec leaves these to the builder. Each is cheap to reverse before its task runs.

- **SSE shape (ZeroAlloc.Rest).** A method returning `IAsyncEnumerable<T>` must carry `[EventStream]`. Shape one:
  `IAsyncEnumerable<ServerSentEvent<T>>`, each event's `data:` deserialized as `T`, with the event name and id on the
  struct. Shape two: `IAsyncEnumerable<TBase>` with one `[EventType("name", typeof(TDerived))]` per event; unknown
  names are skipped. `[EventStream(ErrorType = typeof(E))]` routes a non-2xx through the `[ErrorMapper]` for `E`.
- **The pre-stream error path** throws `HttpErrorException` (or `HttpErrorException<E>` with an `ErrorType`), both
  deriving from `HttpRequestException` with `StatusCode` set. That is the "existing error path" for a method with no
  `Result` to return.
- **Resilience on a stream:** `[Retry]` with `RetryOnException` and `DelayHint(Exception)` is supported. `[Timeout]`,
  `[CircuitBreaker]`, `[RateLimit]`, a fallback and `PerAttemptTimeoutMs` are refused on such a method with ZR0014
  (Error) when set on the method, and not applied with ZR0015 (Warning) when inherited from the interface.
  `RetryWhen` keeps ZR0010.
- **Anthropic defaults** match the SDK's: base `https://api.anthropic.com/`, `anthropic-version: 2023-06-01`, timeout
  ten minutes, two retries (three attempts), backoff 500 ms with jitter, delays capped at 60 s. Task 7 confirms the
  SDK's own defaults from its 13.1.0 `ClientOptions` source before pinning them.
- **Retries:** status 429, 529 and every 5xx; `retry-after` in seconds is the delay hint. Transport failures are not
  retried; the spec does not list them.
- **Markers in Thalos:** the translator stays a `DelegatingChatClient` and marks content and tools with an
  additional property whose value is an internal `CacheBreakpoint` type, which only the adapter reads. No caller can
  construct one, so caller-set markers cannot exist and the cap counts only the translator's own.
- **`UseOllamaEmbeddings` is an `IServiceCollection` extension that registers and returns the generator,** because
  `AddDaedalusAgents` hands the same instance to AI.Sentinel at registration time
  (`DaedalusAgentsServiceCollectionExtensions.cs:495`), where DI cannot resolve it.
- **AppHost:** the Api receives `ConnectionStrings__ollama` as `Endpoint=<url>`, the shape the toolkit's server
  resource gave; one parser in Daedalus reads it.
