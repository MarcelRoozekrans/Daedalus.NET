# Phase 3.5 EF Core to ZeroAlloc.ORM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Daedalus' data layer runs on ZeroAlloc.ORM with LINQ through `ZeroAlloc.ORM.Linq`, over the existing schema
and data; EF Core leaves every dependency graph, #290 is fixed, and the native CLI reaches "Application started".

**Architecture:** First the packages, a shared data source and a capability spike; then a baseline migration that
adopts EF's database, and every fixture on real migrations. Then one store per task, EF still serving the stores not
yet moved: each task adds `Rehydrate` factories for its aggregates, maps and SQL in Infrastructure, ports the store
and deletes the EF mapping it no longer needs. Migration 2 follows the five #290 aggregates. The outbox pipeline and
its transaction partners move last, on the `ZeroAlloc.Outbox.Orm` release the handover asks for; then EF is deleted.

**Tech Stack:** .NET 10, ZeroAlloc.ORM 2.13.0 with `ZeroAlloc.ORM.Linq` 2.13.0 and its generator, Npgsql 10.0.3,
AdoNet.Async adapters, `ZeroAlloc.Outbox.Orm` (the release that closes gap 4.5), xUnit, FluentAssertions,
Testcontainers Postgres, Respawn.

**Spec:** `docs/superpowers/specs/2026-11-05-phase-3.5-zeroalloc-orm-design.md` (owner decisions 1 to 6). The
file-level record is the gap audit `docs/plans/2026-10-17-zeroalloc-orm-gap-audit.md`, sections 2, 3.4 and 5; its
line numbers predate phases 3.2 to 3.4, so read the current files. The outbox wait is
`docs/plans/2026-11-05-zeroalloc-outbox-orm-handover.md`. The ORM.Linq reference is the package's
`docs/cookbook/linq.md`, which maps most Daedalus sites by name ("Replacing EF Core's `Include`", "Replacing EF
Core's writes and locks").

**Owner answers at `list-phase-assumptions`, 2026-11-05:** AgentSession and RepositoryConfiguration have only
independent saves, so their `RowVersion` is dropped, not guarded; a lost race on Project and CodeAnalysisRequest
returns an explicit "modified by another operation. Please retry."; ScheduleReconciler keeps EF's `xmin` guard; the
builder's calls R2 to R5 stand; execution is subagent-driven.

## Global Constraints

- **Schema and data kept.** No table or column changes except migration 2's drop of the six dead `bytea`
  `RowVersion` columns. `__EFMigrationsHistory` stays, never written again.
- **Parity bar:** integration assertions do not change. Fixtures may. Every changed or retired test is a ruling.
- **No dual-ORM end state on `main`.** Both ORMs live together only on `phase/3.5-zeroalloc-orm`.
- **Domain references no ORM package** and gains no `[StoreAsString]`, `[Json]` or map attribute.
- **No inert guard:** a port keeps EF's `xmin` guard where it exists and adds one per owner decision 5; it never
  ports the `bytea` token as if it worked.
- **A transactional outbox write keeps its atomicity:** the row change and the enqueue commit or roll back together.
- **LINQ first:** `[LinqQuery]`/`[LinqCommand]` wherever the cookbook says it translates. A raw `[Query]`/`[Command]`
  only for inserts, upserts, correlated subqueries and the other items in the cookbook's "Not supported yet", each
  named in a ruling; a real translation gap gets an ORM issue filed as well.
- **No stopgaps from the audit:** no `::jsonb` casts, no `xmin::text::bigint`, no joined-string array parameters.
  ORM 2.13.0 binds arrays, jsonb and `xid`.
- **No suppressions or workarounds as fixes:** no `#pragma warning disable IL*`, no `<NoWarn>` for IL2xxx/IL3xxx or
  ZAO diagnostics, no `UnconditionalSuppressMessage`.
- **No local Native AOT publish on the agents VM.** The native CLI is checked through the `native-publish` workflow
  on a labelled PR. `eng/aot/baseline.json` is set by hand to the count CI's `aot-analysis` reports on a head that
  sat still, since every push cancels the running CI.
- **Central package management:** versions only in `Directory.Packages.props`, with a history comment in the file's
  format.
- **Commits:** conventional, release-please parseable; body and footer lines at most 100 characters; no nested
  parentheses; no `Co-Authored-By` trailer, no Claude signature, no session URL. `dotnet format` before committing;
  `dotnet format <csproj> --verify-no-changes --no-restore --include <files>` catches the import order CI checks.
- **Branch:** `phase/3.5-zeroalloc-orm`, pushed after every task with
  `git push origin phase/3.5-zeroalloc-orm:phase/3.5-zeroalloc-orm`. Never work on `main`. Release-please stays on
  hold.
- **`dotnet build` and `dotnet test` one at a time,** with `DOTNET_USE_POLLING_FILE_WATCHER=1`.
- **Save classification** (owner decision 5) is fixed per site in each store task, from a read of every EF write
  site on 2026-11-05; a task that finds a site the plan does not classify stops and asks.
- **Rulings:** every call the spec does not make goes into `docs/plans/2026-11-05-phase-3.5-rulings.md` as `R<n>`,
  with what it costs if wrong. Review minors are fixed in the task's loop, not deferred.

## Review Focus

1. **A row `Create` would now reject** (a task id longer than today's limit, an empty title from before a rule
   existed) must still load: `Rehydrate` never validates. Pinned per store task by a round-trip test that stores
   such a row with raw SQL and loads it.
2. **Two writers on one aggregate:** the second guarded save gets today's conflict result, and a benign concurrent
   write (a turn's counter increment while the session's state changes) does not fail the other's independent
   save. Pinned per guarded site by a lost-race test and in Task 9 by the benign case.
3. **A deleted row under a guarded save** answers not-found where the caller distinguishes it (AgentSession), and
   today's result elsewhere. Pinned in Tasks 9 and 12 to 15.
4. **An existing database with pending and leased channel outbox rows** at the switch: both are delivered once, and
   the workflow engine's `outboxmessages` is untouched. Pinned in Task 18.
5. **A database whose EF head is not `20261014090300_AddNodeSelectionUniqueIndex`** (older, or an empty history
   table) is refused before anything runs, and the Migrations host exits 1 with the reason. Pinned in Task 2.

### Store port recipe (Tasks 4 to 16 and 19 to 21)

Each store task follows these steps; its own section lists what is particular to it, including the classification
of every save site. Append each classification to the rulings as it lands.

1. **Read** the store, its callers' result handling, its tests, its EF configurations and the entity types.
2. **Domain:** add `Rehydrate` to each entity the task owns; remove its EF-only private constructor and the
   `S1144`/`CA1819` suppressions that existed for EF. Value objects are rebuilt through their existing `Create` in the
   row record; enums stored as strings are parsed there. In `Daedalus.Tests.Unit.Domain`, one test per factory that
   `Rehydrate` keeps every value given, including one `Create` rejects.
3. **Tests first,** in `Daedalus.Tests.Integration`, against the migrated schema:
   - `<Store>RoundTripTests.Stored_<aggregate>_loads_back_whole`: store through the port, load, compare every
     property and child (`BeEquivalentTo` on the domain object); and one row written by raw SQL with a value `Create`
     rejects, which loads (Review Focus 1).
   - For each guarded save site, `<Method>_loses_the_race_with_<Result>`: load twice, save the first, save the second,
     assert today's conflict result and that the first save's values stand.
   - The existing tests stay as they are; a fixture change is a ruling.
4. **Run them** and see the new ones fail for the right reason (the port does not exist yet).
5. **Write the maps and the SQL class** per the shared definitions. Inserts are `[Command]` with every column listed;
   `text[]` columns bind as `string[]`; jsonb columns are declared `Json = true` in the map, and inserts mark the
   parameter `[Json]`; `Task.RowVersion` maps to `xmin`. Child collections follow the rule the task states.
6. **Port the store** to `DaedalusDb` and the SQL class. Keep public signatures and results. Map
   `ZeroAllocOrmConcurrencyException` to today's result. A `catch (DbUpdateException)` becomes
   `catch (DbException)`, and a SqlState test on `DbUpdateException.InnerException` becomes one on
   `PostgresException` with the same `SqlState` and `ConstraintName`, in the store and in every caller that tests it.
   An independent save writes only the columns its domain method changes, never the whole row.
7. **Delete the EF mapping** the store no longer needs: the entity's configuration, its `DbSet`, and its row in
   `ApplicationDbContext.Configurations`, unless a store not yet ported still reads the table, which the task names;
   then the last task that ports a reader deletes it. For a #290 entity whose mapping must stay, its configuration
   `Ignore`s `RowVersion`. `ApplicationDbContextModelTests` follows.
8. **Run:** `dotnet build -c Release` (0 warnings), then `Daedalus.Tests.Unit.Domain`, `Daedalus.Tests.Unit`,
   `Daedalus.Tests.Unit.Infrastructure` and `Daedalus.Tests.Integration`, one at a time. All pass.
9. **Commit** `refactor(data): port <Store> to ZeroAlloc.ORM` (or `fix(data):` where the task fixes #290), push,
   and after CI settles set `eng/aot/baseline.json` to the reported counts in a follow-up commit if they moved.
