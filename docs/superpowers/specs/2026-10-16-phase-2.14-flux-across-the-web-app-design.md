# Phase 2.14 Design: Flux across the Web app

**Date:** 2026-10-16
**Phase:** 2.14
**Surface:** Refactor
**Stage:** phase (one phase, implementation-ready)

The owner skipped the design questions and approved this proposal: move the remaining pages onto ZeroAlloc.Flux
following the Tasks and Runs pattern from 2.12, with no new features and no visual change, and let the 2.13 browser
tests prove that nothing changed. Every decision below that is not in that proposal is marked **(my call)**. On
2026-10-16 the owner confirmed the two calls that change what gets built: #372 is in scope, and Home updates live.

## Goal

Every page in the Web app keeps its state in a ZeroAlloc.Flux feature: state, actions, reducers, and effects that
call the API. No page keeps its own load, error and data fields, and no page calls `HttpClient` directly. This holds
for all the pages 2.13 kept.

## Why

- 2.12 made ZeroAlloc.Flux the state layer for the whole app, but moved only Tasks and Runs (2.12 spec, decision D2).
- The other pages each keep their own data, loading and error fields, and their own copy of the session-expiry and
  error rules. 2.13 had to add `SessionExpiry.IsSigningIn` checks to every one of them separately.
- Two pages call `HttpClient` directly, `RepositoryConfiguration` and `PrdGenerator`, so their requests skip the typed
  clients' error handling. 2.13 had to fix refused writes there by hand.
- State that lives in a page cannot be unit-tested without a component renderer, which the repository does not have.
  A reducer or an effect can be tested.

## Goals

1. **One state approach.** Each page reads a Flux feature and dispatches actions. Loading, error and data live in the
   feature's state, and requests live in effects.
2. **Typed clients only.** Effects call `ApiClient`, `AgentApiClient` or `IProjectApiClient`. No component injects
   `HttpClient`.
3. **No visible change.** Same pages, same copy, same layout and same behaviour at every width. The existing browser
   suite, 185 tests, stays green without editing what it asserts. Tests may only change selectors and wiring.
4. **Unit-tested state.** Every new reducer and effect has unit tests, in the style of `TasksEffectsTests` and
   `RunsReducersTests`, with a `Red:` line per assertion.

## Non-goals

- New features, new copy, or layout changes.
- The open accessibility issues (#371, #374, #375), the Updated question (#373) and the run-list query (#367).
- The API surface. No endpoint changes, unless a typed client needs a method that `HttpClient` callers used and that
  no client offers yet. That addition goes on the client, not the endpoint.

## Anti-goals

- Moving fields into a feature without moving the logic. A page that still decides when to load, retry or clear has
  only been relabelled.
- A `TasksState`-style feature that grows extra flags to work around page lifetimes. 2.13 needed `ProjectsRequested`
  for that. Where pages share data, the feature owns it once and states the lifetime rule.
- Losing a behaviour 2.13 fixed. These are pinned by tests and must stay:
  - per-card errors on Home;
  - session-expiry skips;
  - refusal messages on Git Repositories;
  - the Home role gate.

## The pages and their features (my call)

| Page | Feature | Notes |
|---|---|---|
| Home (`NeedsMePanel`, `NeedsMeCard`) | `HomeState` | Four cards, each with its own rows, error, `More` flag and retry. The role gate moves into the effect: no reads without `RunAccess.CanView`. New task keeps opening the shared create dialog |
| Projects, `ProjectCreateDialog`, `ProjectEditDialog` | `ProjectsState` | The project list. It also replaces `TasksState.Projects`, so one projects feature serves the Tasks page, the task dialogs and Home's New task. This removes `ProjectsRequested` |
| Schedules | `SchedulesState` | The schedules list, the expanded row and its runs |
| Costs | `CostsState` | The summary, the sources and the period filter |
| Agent, `/brainstorm/{id}` | `AgentState`, `BrainstormState` | Sessions list, the open conversation, and the streaming reply. The SSE stream is an effect that dispatches one action per chunk |
| Git Repositories | `RepositoriesState` | Through a typed repositories client in place of `HttpClient`. The 403 says "admin only"; any other failure shows an alert with Retry |
| PRD Generator, `ProjectSelectionStep` | `PrdState` | The wizard step, the generated PRD, and converting it to tasks, through the typed client |

## Shared rules (my call)

- **Session expiry** is checked once, in the effects:
  - an effect whose request failed because the session is being renewed (`SessionExpiry.IsSigningIn`) dispatches
    nothing;
  - no page renders an error for it.

  This replaces the per-page checks 2.13 added.
- **Notifications.** Success and failure toasts stay in components, through `FailureNotices`. An effect reports an
  outcome as state, for example `LastSaved` or `LastRefusal`, and the page shows the toast. Effects stay free of UI
  services and can be unit-tested.
- **Lifetimes.** A feature is cleared when its page is left, as `RunsClosed` and `TasksClosed` do, unless another page
  reads it. For a shared feature, `ProjectsState`, the lifetime rule is written on the feature.
- **The hub.** Only runs and tasks follow `/hubs/workflow-runs` today. Home's Awaiting, Running and Failed cards
  re-fetch on `RunChanged` in the same way. This is the one behaviour change: Home now updates live instead of on
  reload. **(Owner-confirmed 2026-10-16.)**

## Also in scope (owner-confirmed 2026-10-16)

**#372, the Web project's 15 copies of Application DTOs.** Every page this phase moves binds those DTOs, so the
features bind the Application types directly and the copies are deleted. Doing it as a separate refactor later would
touch the same files twice.

## Files and modules touched

- `src/Daedalus.Web/State/<Feature>/` gets a new folder per feature listed above.
- `src/Daedalus.Web/Pages/*.razor` and `Components/*` for the pages listed.
- `src/Daedalus.Web/Services/`:
  - a typed repositories client, plus PRD methods on an existing client;
  - the Web DTO copies are deleted (#372);
  - the effects are registered in `Program.cs`.
- `src/Daedalus.Web/State/Tasks/`: the projects move out to `ProjectsState`.
- `tests/Daedalus.Tests.Unit/Web/`: reducer and effect tests per feature.
- `tests/Daedalus.Tests.Playwright.Browser/`: selector or wiring changes only.
- `README.md`, `docs/development-guide.md` (the Flux pattern for every page) and `docs/design/MASTER.md`, only if a
  convention is written there.

## Tests

- **Unit:** each feature's reducers cover every action, and each effect covers success, failure and session renewal,
  with stale results ignored after close. Every assertion carries a `Red:` line.
- **Browser:** the existing suite, 185 tests, unchanged in what it asserts. A browser test is added only where the
  phase adds behaviour: Home updating live on `RunChanged`.
- **Architecture:** `CleanArchitectureTests` still passes. With #372, a test asserts that `Daedalus.Web` declares no
  type whose name matches an Application DTO.
- **Regression:** a sweep with `regression-test` at three widths, compared with the 2.13 report. The expected result
  is no visual difference.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The Agent SSE stream in an effect drops or reorders chunks | A broken chat | One action per chunk, a reducer test over a recorded stream, and the existing Agent browser tests |
| Sharing `ProjectsState` across Tasks, the dialogs and Home brings back the lifetime race `ProjectsRequested` fixed | Lost projects after navigation | Write the lifetime rule on the feature, and add a browser test that navigates Home, then Tasks, then Home |
| Deleting the DTO copies (#372) changes JSON binding where a copy differed on purpose | A field silently null | Before deleting each copy, diff it against its Application type. Keep a deliberate difference as a view model that wraps the Application type |
| A behaviour 2.13 fixed regresses during the move | A known bug returns | The browser suite pins every one of them; a task is done only when it is green |
