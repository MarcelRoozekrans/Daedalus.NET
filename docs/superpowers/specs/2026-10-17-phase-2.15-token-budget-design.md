# Phase 2.15 Design: Size and document the token budget

**Date:** 2026-10-17
**Phase:** 2.15
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)

The owner skipped the design questions on 2026-10-17 and asked for a spec drafted from recon. Every decision below
that the owner has not made is marked **(my call)**. The phase closes the milestone 2 audit's one remaining gap,
"Spend is visible and bounded" (`docs/superpowers/reviews/2026-10-17-milestone-2-audit.md`), and closes #280.

## Goal

A manufacture run completes on the shipped configuration, and each agent turn in it is stopped by a token ceiling
that was set from measured turns and is written down where an operator will find it.

## Why

The milestone 2 definition of done asks that the token budget "either caps spend during a turn or is documented as
the post-turn check it is, sized from measurements rather than picked". Recon shows the problem is sharper than the
audit said: **the shipped ceiling stops most real manufacture turns, and every live proof ran with it raised by
hand.**

## What recon found (2026-10-17)

### The cap works, inside the turn, and counts every token

Thalos 0.11.0 (phase 2.5, Thalos#173) added `TurnBudgetChatClient`, and 0.17.0 is unchanged:

- **When it checks:** before every model round trip, including each tool-loop step. It stops the turn with
  `SubagentBudgetExceeded` once the running total reaches the ceiling. A round trip already started is never
  cancelled, so a turn can end above the ceiling by its last call.
- **What it counts:** input plus output. Input as the Anthropic SDK reports it includes cache reads and cache
  writes, so a cache read counts at full weight, though it is billed at a tenth.
- **Where it sits:** directly over the provider's client, below every decorator.
- **Where the ceiling comes from:** Daedalus' `BudgetedSubagentRunner` stamps `DetachedRuns:MaxTotalTokens`
  (150,000) and `DetachedRuns:DeadlineSeconds` (300) onto every workflow turn, whatever the node.

So the "post-turn check" wording in the criterion and in #280 is out of date. Thalos' own README still says "the
token budget is evaluated only after the turn returns", which is wrong.

### The shipped ceiling cannot run a manufacture

Every live manufacture proof raised three settings by hand, uncommitted, and reverted them afterwards:
- `DetachedRuns:MaxTotalTokens` to 1,000,000;
- `DeadlineSeconds` to 900;
- the dispatch `LeaseDuration` to 30 minutes.

The 2.8, 2.9, 2.11 and 2.12 rulings record this, and the 2.10 rulings name it "temporary run limits". The 2.10 run
`f2d30ac9`, started before the override, failed at implement with "Stopped before model round trip 6: 155138 tokens
used of a budget of 150000".

### The measurements

There are 75 manufacture turns from 11 runs, in the phase 2.10 live-test database, the Aspire volume
`daedalus.apphost-72c89faa1d-postgres-data`, 2026-10-14 to 2026-10-15, all on `daedalus-sandbox` and under the
1,000,000 override. Each workflow turn, including each review lens pass, is its own agent session owned by
`workflow:manufacture:<run>`. So `AgentSessions.TotalInputTokens + TotalOutputTokens` is one turn's total, in the
unit the cap counts:

| Agent | Turns | p50 | p90 | Max | Turns over 150,000 | Duration p50, p90, max |
|---|---|---|---|---|---|---|
| implementer | 19 | 262,219 | 435,682 | 501,172 | most | 31 s, 57 s, 71 s |
| reviewer, covering lens passes and retrospect | 56 | 197,159 | 270,197 | 392,852 | most | 36 s, 116 s, 150 s |

Across both agents, 53 of the 75 turns used more than 150,000 tokens. The p50 of each agent is above it.

Durations are `LastActivityAt − CreatedAt`. No turn came near the shipped 300-second deadline. The 20-minute default
lease covers that deadline plus a ten-minute readiness wait, so **the deadline and lease overrides were caution, not
need. Only the token ceiling is wrong.**

On `implement`, cache reads average 89% of input. Without them the largest implement turn is 47,592 tokens. A
`review` node's `node-usage` record sums its lens passes, so size from the session table, not from node usage.

## Goals

1. **The shipped configuration runs a manufacture.** No live test needs a hand-raised limit again.
2. **Each role's ceiling is set from measurements.** The implementer and the reviewer get separate ceilings, set by a
   stated rule from the measured turns. The query, the sample and the rule are written next to the setting, so the
   next person can redo the sizing when the process or the models change.
3. **A turn the budget stops still counts toward costs.** Today a failed node records no usage, so the spend the
   budget exists to bound vanishes from `/costs` exactly when the budget fires. **(my call)**
4. **It is documented where an operator looks:**
   - the README configuration section;
   - the development guide;
   - the `appsettings.json` comment;
   - the Thalos README's wrong sentence, as an upstream fix.

## Non-goals

- **Changing what the cap counts.** Weighting cache reads at their billed tenth would bound cost more faithfully, but
  it is a Thalos change to shared semantics. The cap's job here is to stop a runaway turn, and counting every token
  does that predictably. The owner confirmed this on 2026-10-17.
- **A per-run or per-day cost cap in currency.** It is a different control, with its own design questions, such as
  what happens to a run stopped at its review gate. If wanted, it is a new issue. **(my call)**
- **Per-role deadlines.** The measurements put every turn at half the shipped deadline or less, so one deadline
  stays, documented with the numbers. **(my call)**
- **Chat and scheduled turns.** They have no cap today (`TurnScope`) and are outside a manufacture run. The scout
  keeps `DetachedRuns:MaxTotalTokens`, which was sized for it.
- **Making turns smaller.** One way out #280 mentions is trimming tool schemas. That is an optimisation, not
  this phase.

## Anti-goals

- **A ceiling moved until today's runs pass.** Every ceiling comes with its inputs and the rule applied to them.
- **A cap that silently does nothing.** A test must go red if the role ceiling stops reaching the turn, as a wrong
  decorator order or a dropped stamp would.
- **Hand-raised limits as the normal way to run.** After this phase, a live test that needs an override is a finding
  to record, not a step in the procedure.

## Approach

### 1. Per-role ceilings in Daedalus

- `BudgetedSubagentRunner` picks the turn's ceiling from a new `Thalos:Workflow:TurnBudgets` section, keyed by agent
  name, with `implementer`, `reviewer` and a required `Default`.
- **Keyed by agent name. (my call)** The runner receives the resolved `AgentId`, which maps to a catalog agent and
  its name, and the measurements are per agent. The reviewer serves both review lenses and retrospect.
- **With the squad off,** every node runs as "Daedalus Architect", which is unlisted and gets `Default`. `Default` is
  therefore at least the larger of the role ceilings. **(my call)**
- **Deadline:** every role keeps `DetachedRuns:DeadlineSeconds`.
- **Unchanged:** a request that already carries a budget keeps it, as today. `DetachedRuns:MaxTotalTokens` stays the
  scout's.
- **Start validation:** start refuses a missing `Default` or a non-positive value, as the other options do.

### 2. Sizing

Apply one rule to each agent's measured turns: **ceiling = the larger of 1.5 × the measured maximum and 2 × p90,
rounded up to the next 25,000. (my call)** The rule leaves room for a heavier task than the sample, without being so
loose that a runaway turn spends a run's worth before it stops.

On the current 75 turns:

| Agent | 1.5 × max | 2 × p90 | Ceiling |
|---|---|---|---|
| implementer | 751,758 | 871,364 | **875,000** |
| reviewer | 589,278 | 540,394 | **600,000** |
| `Default` | — | — | **875,000** |

These are close to the 1,000,000 the live tests used by hand. The plan recomputes them from the final sample before
committing to the numbers.

**Superseded 2026-10-17 by the measured sample.** The extra live runs of section 3 were taken, on
`MarcelRoozekrans/Daedalus.NET` at branch `phase/2.15-token-budget`, and the sandbox sample's maxima were far below
what a real repository costs. The same rule over all 88 completed turns, the 75 above plus 6 implementer and 7
reviewer turns from Daedalus.NET:

| Agent | Measured maximum | 1.5 × max | 2 × p90 | Ceiling |
|---|---|---|---|---|
| implementer | 1,918,692 | 2,878,038 | lower | **2,900,000** |
| reviewer | 1,917,540 | 2,876,310 | lower | **2,900,000** |
| `Default` | — | — | — | **2,900,000** |

The four turns that a ceiling stopped, at 875,000 and at a temporary 2,000,000, were all in runs whose sandbox build
was broken, and give only lower bounds, so they are not in the maxima. The original table above is left as written.

### 3. More measurements before the numbers are fixed

Eleven runs on one small sandbox repository is a thin sample. Five more live runs against a larger repository would
be added before sizing, with the turns stopped at the review gate so nothing is published. Approved by the owner on 2026-10-17.

### 4. A stopped turn's spend in `/costs`

**The rule:** every turn that ran is counted exactly once, including a stopped turn and, in a review node that
failed, the lens passes that completed before it.

Today, in Daedalus:
- `NodeUsageRecorder.Forget` drops a failed review node's held passes;
- `ReviewLensRunner` returns on a failed pass without handing on the earlier passes' usage.

Today, in Thalos:
- `RunTurnAsync` keeps only a failed turn's error;
- `IWorkflowStore.FailAsync` stores no usage.

**The preferred route is Daedalus-only. (my call)**
- Thalos publishes `TurnFailedNotification` with the turn's usage and session. The session's owner,
  `workflow:manufacture:<run>`, names the run.
- Daedalus records that usage as a node-usage record for the failed node.
- Daedalus keeps a failed review node's completed passes instead of forgetting them.

If the notification lacks what is needed, such as the node, or reliable delivery before the run is marked failed,
the fallback is an additive Thalos change: a new optional member, no changed signature, released as 0.18.0. The
plan's first task establishes which route works.

### 5. Documentation and close-out

- **README:** in the configuration section, the per-role ceilings, what they count (every token, cache reads at full
  weight) and what happens when a turn reaches one.
- **Development guide:** a "Token budget" section with the sizing query, the rule and how to redo it.
- **`appsettings.json`:** the comment that replaces the "NOT SIZED" paragraph. It explains the deadline numbers as
  well.
- **Thalos:** an issue for its README's wrong sentence, or a one-line PR. **(my call)**
- **Close-out:** close #280. Correct the milestone 2 audit's description of the cap as a post-turn check, with a
  dated note, not a rewrite. Re-run `audit-milestone`.

## Tests

- **Unit, `BudgetedSubagentRunner`:**
  - stamps each agent's ceiling;
  - gives an unlisted agent `Default`;
  - keeps a budget the request already carries.
- **Unit, options:** start refuses a missing `Default` or a non-positive ceiling.
- **Unit, costs:** a stopped turn's usage, and the completed passes of a failed review, are each recorded once, never
  twice.
- **Integration:**
  - the composed API host stamps the implementer's ceiling on an implement turn. It must go red if the decorator
    leaves the chain;
  - a budget-stopped node's spend appears in `/api/cost-analytics/summary`.
- **Drift guard:** a test reads the shipped `appsettings.json` and fails if an agent the shipped squad uses has no
  ceiling, or if a ceiling sits below the measured maximum recorded beside it.
- **Live, recorded in the rulings:**
  - one manufacture run completes on the shipped configuration, with no hand-raised limit;
  - one turn under a deliberately tiny ceiling is stopped, and its spend shows on `/costs`.

## Decided by the owner, 2026-10-17

1. **Keep counting every token, with cache reads at full weight.** No Thalos change to the counting. The ceilings
   are sized in that unit.
2. **Five extra live measurement runs, before the numbers are fixed,** stopped at the review gate so nothing is
   published. **Repository: Daedalus.NET itself (my call)**, added as a second workflow repository for the
   measurement only. It is the largest codebase at hand and a real one, and stopping at the gate means no pull
   request is opened against it. The owner can name another in the plan review.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Ceilings sized on a small sandbox stop real work on a larger repository | Runs fail at implement | The extra runs; the headroom rule; a stopped turn's spend now shows on `/costs`, and its error names the ceiling |
| `TurnFailedNotification` does not carry enough to attribute the spend | Goal 3 needs a Thalos change | Fallback: an additive Thalos member, released as 0.18.0 |
| A model change makes turns larger | Ceilings stop runs again | The documented query and rule make resizing a routine task; the drift guard reads the recorded maximum |
| The cap counts cache reads at full weight | A well-cached run uses its ceiling faster than its cost suggests | Stated in the docs; the owner chose this counting on 2026-10-17 |
