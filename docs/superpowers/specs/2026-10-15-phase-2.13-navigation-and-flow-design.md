# Phase 2.13 Design — Navigation and flow review

**Date:** 2026-10-15
**Phase:** 2.13
**Surface:** UI
**Stage:** phase (one phase, implementation-ready)

The owner skipped the brainstorm questions and asked for a start from the 2.12 regression report
(`docs/regression-report-2026-10-13-1033.md`) and issues #348 to #351. Every decision below that is not in those
inputs is marked **(my call)** so it can be checked and corrected.

## Goal

A person goes from an idea to a merged pull request in the Web app without dead ends: sign in, create a task that
works first time, manufacture it, follow the run, approve it at the gate and reach the pull request. The app keeps only
pages that serve that path or a clear operator need, and it works on a phone.

## Why

Phase 2.12 made runs visible and decidable in the browser, but the path around it still trips people up.
- Create Task fails silently with its own defaults and asks for a raw project GUID (#348).
- A signed-out or expired visitor sees errors and empty pages instead of a sign-in (#350).
- On a phone, the opened menu squeezes the page to about 100px (#349).
- Pages from the retired task loop still sit in the menu (#351).
- A failed run gives no reason (#347).
- A rejected review's findings are invisible on the run page (#354).

Phase 2.14 moves the remaining pages onto Flux; this phase decides which pages there are to move.

## Goals

1. **The path, end to end.** Every step from sign-in to pull request is one obvious action. Nothing on the way fails
   silently or needs knowledge of the database.
2. **A page set with a purpose.** Each page in the menu serves the manufacture path or a named operator need. Retired
   pages leave the menu.
3. **Signed-out and expired sessions lead to sign-in**, never to page errors or empty data.
4. **Phone widths work as one column.**
5. **A run explains itself:** why it failed, what review rejected and how implement answered.

## Non-goals

- Moving pages onto ZeroAlloc.Flux. That is phase 2.14. Pages touched here keep their current state approach, unless a
  page is already on Flux (Tasks, Runs).
- New product features beyond the path: no new analytics, no new admin screens.
- The rate limiter's proxy trust (#345), which waits on a deployment decision.
- Showing node selections in the console. That is part of #354's area but is not needed for the path. **(my call)**

## Anti-goals

- Hiding a failure to make the path look smooth. A refused create, a failed run or an expired session must say so
  plainly.
- Removing an operator capability without a replacement. Executions' frozen history stays readable through the API and
  Costs.

## Approach

**1. Sign-in (#350).**
- Every page that needs data carries `[Authorize]`, so `AuthorizeRouteView` redirects a signed-out visitor to
  Keycloak.
- `/` shows a signed-out landing page: what Daedalus is and a Sign in button. The menu is hidden while signed out.
- A failed token refresh, meaning `AccessTokenNotAvailableException` or a 400 from the token endpoint, is treated as
  signed out. It sends the user to sign in instead of showing "Please log in to access this data".
- The stored OIDC user is cleared when that happens, so the header never claims a dead session.

**2. Home for a signed-in user (#351, my call).** Home leads with what needs a decision:
- runs awaiting approval, linking to their gate;
- runs in progress;
- runs that failed in the last week, with their reason (from #347);
- recently opened pull requests.

It has one primary action, **New task**. The four coloured quick-action buttons and the icon beside a heading go, as
MASTER.md asks.

**3. Creating a task (#348).**
- The dialog asks for:
  - **Project**, a required picker showing name and repository;
  - **Title** and **Description**, both required;
  - **Priority** and **Complexity**, optional with defaults.
- **Prompt** becomes optional. When it is empty, the API uses the description. The DTO and the validator change
  together, and so does the `IValidationAdapter` registration, per CLAUDE.md's Validation rule.
- The Ralph-era fields leave both dialogs: Phase, Parallel Group, Dependencies and Files to Modify. The API keeps
  accepting them with defaults it accepts, so the CLI and scripts are unaffected. **(my call)**
- The Tasks grid drops the Prompt and Iterations columns, gives the title the width, and adds a pull request link
  column.
- A refused create or edit shows the API's ProblemDetails reason in the dialog.
- **Create and manufacture**: a second button in the dialog starts the run straight away and opens `/runs/{id}`. This
  is the one shortening of the path. **(my call)**

**4. The run page (#347, #354, minors).**
- **A failed run carries its reason.** The Daedalus host derives it on read from the run's steps: "review rejected N
  times (cap); last rejecting lens: X", or "implement reported blocked", or the host error. It is shown as the run's
  `failureReason` in the view and in the Failed alert. This needs no engine change. **(my call:** derived on read rather
  than recorded by Thalos at the terminal node.**)**
- **Each review visit is shown:** its verdict, its rejecting lens and that lens's findings, next to implement's
  `review_response` for the visit that answered it. The API exposes these from the `review-evidence` records and the
  run's variables. `review_response` stays withheld from the reviewer's own dispatch, as today.
- **Minor fixes:**
  - "Started by" shows the person's name (`startedByName` is already in the view).
  - A step whose outcome is `none` shows no badge.
  - The pull request link is a styled link button.
  - The Manufacture button gets a text label and the accessible name "Manufacture".
  - Status badges use one shade across Tasks and Runs.

**5. Phone layout (#349).**
- Below 768px the sidebar overlays the content and closes on navigation.
- The header is compact: the user's name and Log out move into an icon menu.
- PRD Generator's content is constrained to its column.
- The loading screen follows MASTER.md instead of the full-viewport gradient (#351).

- **Unit:** the failure-reason derivation, one case per path; the Prompt fallback.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Removing `/executions` hides something an operator still uses | Lost access to history | The API and Costs keep it; the PR names the removal; restoring a page is cheap |
| Treating every refresh failure as signed out loses unsaved form input | Annoyance | Only on a genuine refresh failure; the redirect returns to the same page |
| The failure reason derived on read misreads a new terminal path | A wrong or empty reason | One unit case per path; unknown paths show the host error or "ended at adjudicate" |
| Optional Prompt changes an API contract | Old clients | Sending a Prompt still works; only an empty one changes |
| The Tasks page already on Flux conflicts with 2.14's migration | Rework | 2.13 changes Tasks inside its Flux state; 2.14 moves only the other pages |
