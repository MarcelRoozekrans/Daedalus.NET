# Phase 3.4 Design — Controllers to minimal APIs

**Date:** 2026-10-31
**Phase:** 3.4
**Surface:** Refactor
**Stage:** phase (one phase, implementation-ready)

> Brainstormed with the owner on 2026-10-31. Milestone design: `docs/superpowers/specs/2026-10-17-milestone-3-design.md`,
> phase 3.4. AOT evidence: `docs/plans/2026-10-17-native-aot-survey.md`, row 3 (MVC, 143 warnings) and the 3.2
> native run, where the API stopped at A2, MVC loading its application parts.

## Goal

`Daedalus.Api` serves its whole HTTP contract from minimal API endpoints instead of MVC controllers, byte-for-byte the
same on the wire, with source-generated JSON, so MVC and its reflection leave the API and 3.6 can publish it native.

## Why

ASP.NET Core MVC is not supported under Native AOT in .NET 10; minimal APIs are, through the request delegate
generator. The milestone's rule for every phase is **no contract change**: the Web app and any other caller must not
notice. Known contract bugs keep their own issues and are deliberately preserved here: #366 (problem bodies served as
`application/json`) and #326 (error bodies echo exception text).

## Scope

**In:**
- The 13 controllers in `src/Daedalus.Api/Controllers/` (3,007 lines with five helper files):
  `AgentMemories`, `AgentSessions`, `Agents`, `Brainstorm`, `CodeAnalysis`, `CostAnalytics`, `Prd`, `Projects`,
  `Repositories`, `Schedules`, `TaskExecutions`, `Tasks`, `WorkflowRuns`. The milestone docs say 18; the true count
  is 13, and MILESTONE.md and ROADMAP.md are corrected in this phase.
- The MVC filters: `ZeroAllocValidationFilter` (action filter) and `WorkflowEngineEnabledAttribute` (resource filter).
- API versioning: `Asp.Versioning.Mvc` 8.1.0 out, `Asp.Versioning.Http` (10.x) in. Renovate PR #402 (Mvc to v10)
  becomes moot and is closed when MVC goes.
- The endpoints' JSON: a source-generated context wired into the minimal-API `JsonOptions`, matching today's bytes.
- The unit tests that construct controllers, about 15 files under `tests/Daedalus.Tests.Unit/Controllers/` and
  `Workflow/`, moved to the new handler classes.

**Out:**
- Any contract change, including fixes to #366 and #326, and the `catch (Exception)` blocks (below).
- The SignalR hub (`WorkflowRunsHub`) and health checks: already non-MVC.
- Native publish of the API and native test runs: 3.6.
- Making `aot-analysis` a required check.

## Owner decisions, 2026-10-31

1. **Approach A: incremental, with a route-table snapshot.** Snapshot the MVC endpoint table first, then port one
   controller per task with MVC and minimal APIs live side by side, and remove MVC last. Chosen over a big-bang port
   (a contract break found late with no locality) and incremental without a snapshot (Playwright.Api's 115 tests do
   not cover every policy and rate-limit pairing).
2. **Handler classes, unit-tested directly.** Each controller becomes a static endpoint class: one `Map…Endpoints`
   extension that builds the route group, plus one `static` handler method per endpoint returning typed
   `Results<…>`. The controller unit tests are rewritten to call the handlers and assert on the typed results, keeping
   their cases one for one. Chosen over moving them to HTTP integration tests (slower, larger rewrite) and over
   splitting logic into services (more restructuring than a port needs).
3. **The 14 `catch (Exception)` blocks stay, byte-identical.** They return `500 { "error": "Internal server error" }`
   and bypass `GlobalExceptionHandler`. Removing them is a contract change, so it gets its own issue, #426: drop the
   catches and let the global handler answer with ProblemDetails.
4. **JSON is source-generated in this phase, matching today's bytes.** No reflection fallback in the endpoints'
   resolver chain. The anonymous `new { error = … }` bodies become a named record with one `error` property.

## Approach

**Step 1, the contract snapshot, before any controller moves.** A test in `Daedalus.Tests.Integration` boots the API
through the existing `WebApplicationFactory` fixture, reads every `RouteEndpoint` from `EndpointDataSource`, and
renders one line per endpoint: verb, route pattern normalised to lower case with `[controller]` expanded, authorization
policies and `[Authorize]`/`[AllowAnonymous]`, rate-limiting policy, API version, and the response metadata (status
codes, response type names and content types, as OpenAPI would see them). The rendering is sorted and compared with a
checked-in snapshot file. The snapshot is generated from the MVC build and committed in this step; every later task
must leave it unchanged, except for differences the rulings record by name (for example, a metadata type name that
changes from `IActionResult`-inferred to typed-result-inferred while the OpenAPI document stays equivalent). The
snapshot test must be shown red: delete a policy from one endpoint and watch it fail.

**Step 1b, body-shape tests where Playwright.Api is thin.** Where a behaviour below is implicit in MVC and not asserted
by an existing test, add an integration test against the MVC build first, so it is green before the port and must
stay green after. At minimum: a `null` property is written as `null`; an empty-body `Unauthorized()`/`NotFound()`
answers with MVC's client-error ProblemDetails (`type`, `title`, `status`, `traceId`); malformed JSON in a body answers
400 with `ValidationProblemDetails`; a body missing a non-nullable property answers MVC's implicit-required 400; the 500 catch body; the problem `Content-Type` per #366; `Location` on each 201;
`api-supported-versions` on responses; an unsupported `api-version` answers as today.

**Steps 2 to 14, one controller per task.** The endpoint class takes the controller's routes, verbs, policies, rate
limits, version set and metadata; `MapControllers` keeps serving the controllers not yet ported. The controller is
deleted in the same task, so no route is ever registered twice. Smallest first, to settle the pattern: `Agents`,
`Schedules`, `TaskExecutions`, then the rest, with `WorkflowRuns` (630 lines, the resource filter, cursor paging,
resume and retry) and `CodeAnalysis` (436 lines, `ModelState`) last. Each task ports the controller's unit tests to the
handler, and ends with the snapshot, the body-shape tests, unit, integration and Playwright.Api green.

**The final step removes MVC.** `AddControllers`, `MapControllers`, `Asp.Versioning.Mvc`, `Microsoft.AspNetCore.Mvc`
usings, `ProblemDetailsFactory` uses and the empty `Controllers/` folder go. The filters are already endpoint filters
by then. CI's `aot-analysis` job confirms the MVC warning family (143 in the survey) is gone from the API; the ratchet
baseline moves down to the measured count. No local Native AOT publish (CLAUDE.md).

### MVC behaviours the port must reproduce

MVC with `[ApiController]` does several things implicitly that minimal APIs do not. Each is a contract item:

| MVC behaviour today | Minimal API equivalent to build |
|---|---|
| `[ApiController]` client-error mapping: `NotFound()`, `Unauthorized()`, `Conflict()` with no body answer with a ProblemDetails body (`type` from the client-error map, `title`, `status`, `traceId`) | A shared helper or endpoint filter that writes the same body; the test of step 1b pins it |
| Automatic 400 for body binding failures, as `ValidationProblemDetails` | Same shape from the binding-failure path: minimal APIs answer a bare 400 by default |
| `Problem(...)` through `ProblemDetailsFactory`, with `traceId` and the status's `type` | The same fields; check `TypedResults.Problem` plus `IProblemDetailsService` produces them, or build the body explicitly |
| `[Produces("application/json")]` on 12 controllers, which serves problem bodies as `application/json` (#366) | Keep `application/json` for those bodies, as today; #366 decides the fix |
| `CreatedAtAction(nameof(Get), new { id }, body)` | `TypedResults.CreatedAtRoute` with named routes, or `Created` with the same URL; the `Location` header must match byte for byte |
| `ZeroAllocValidationFilter` over `ActionArguments`, keyed by `IValidationAdapter.TargetType` | An endpoint filter over `EndpointFilterInvocationContext.Arguments`, same adapters, same `ValidationProblemDetails`. The two-place registration rule in CLAUDE.md and `CleanArchitectureTests` stays true |
| `WorkflowEngineEnabled` resource filter: after authorization, before the controller's dependencies resolve, answers 503 problem details | An endpoint filter on the `workflow-runs` group, which runs after authorization; handler parameters resolve per request, so `WorkflowRunGateway` must not be resolved before the filter has passed: inject it lazily or from `HttpContext.RequestServices` in the handler, not as a handler parameter |
| Implicit `[Required]` on non-nullable reference properties of a body DTO (`SuppressImplicitRequiredAttributeForNonNullableReferenceTypes` is not set): a missing one answers 400 `ValidationProblemDetails` with "The X field is required." | The same 400 for the same DTOs; step 1b first lists, per body DTO, which properties MVC treats as required, and pins one per DTO |
| `ModelState.IsValid` / `BadRequest(ModelState)` in `CodeAnalysis`, lines 67 and 177 | Dead code today: `[ApiController]`'s invalid-model filter answers before the action runs, and `ZeroAllocValidationFilter` never writes `ModelState`. Dropped in the port, not reproduced; the binding and implicit-required rows above cover what reaches a client |
| `[controller]` route token, `[FromQuery]` defaults, `[FromBody]` inference | Explicit route patterns, the same parameter names and defaults |
| `text/event-stream` turn stream in `AgentSessions`, written to `Response` with buffering disabled | A handler that writes the same headers and events; compression must still be bypassed |

### Versioning

`Asp.Versioning.Http` 10.x replaces `Asp.Versioning.Mvc`. One `ApiVersionSet` with version 1.0, applied to every
group, keeps today's readers (query `api-version`, header `x-api-version`, URL segment), the default-version
assumption and `ReportApiVersions`. Whether the package is AOT-clean is read from CI's `aot-analysis`; if it is not,
the milestone policy applies: an upstream issue, and the phase records it. Versioning is not dropped: that would
change the `api-supported-versions` header and the answer to an unsupported version.

### JSON

`ApiJsonSerializerContext` is reworked, not plugged in as is: today it sets `WhenWritingNull`, which would drop nulls
that MVC writes. The endpoints' context uses MVC's web defaults: camelCase properties, case-insensitive reading,
nulls written, numbers as today, enums as today (MVC has no string-enum converter configured, so per-type
`[JsonConverter]` attributes alone decide). Every request and response type of every endpoint is registered,
`ProblemDetails`, `ValidationProblemDetails` and the named error record included. It goes first in
`ConfigureHttpJsonOptions`' `TypeInfoResolverChain` with no reflection resolver after it, so a missing type fails a
test instead of silently falling back. The SSE writer keeps its explicit `JsonTypeInfo`. The SignalR hub's context is
unchanged.

## Tests

- **Contract snapshot** (new, step 1): the endpoint table, unchanged from MVC to the end of the phase.
- **Body-shape tests** (new, step 1b): the implicit MVC behaviours in the table above, green on MVC first.
- **Unit:** the controller tests, ported case for case to handlers. A ported test's assertions must be falsifiable on
  the handler, per CLAUDE.md: for each assertion, name the handler change that turns it red.
- **Integration:** every existing controller and authorization test passes unchanged in what it asserts;
  `ValidationContractTests` included.
- **Regression:** Playwright.Api, 115 tests, and Playwright.Browser pass unchanged.
- **AOT:** CI's `aot-analysis` on the API shows no MVC warnings; ratchet baseline lowered to the measured count.

## Calls made in the design, not by the owner

Each is recorded as a ruling in `docs/plans/2026-10-31-phase-3.4-rulings.md`, which the plan creates and every task
appends to, the same as 3.2 and 3.3.

- **OpenAPI is held to equivalence, not bytes.** Nothing consumes the document; it is served only in Development for
  Scalar. "Identical OpenAPI" means the same operations with the same status codes and response types, and the
  snapshot's response-metadata column is that check. No snapshot of the document itself.
- **Response metadata matches MVC's declared set.** Each endpoint declares, with `.Produces*`/`ProducesProblem`, the
  same status codes and types its `[ProducesResponseType]` attributes declared, so the snapshot line is unchanged. A
  type name may differ only where MVC declared none (an untyped 404, for instance) and typed `Results<…>` infers one;
  each such difference is a named ruling. No other snapshot difference is allowed.
- **`Asp.Versioning.Http` 10.2.1,** which ships `net10.0`. All three readers stay, `UrlSegmentApiVersionReader`
  included, though no route has a `{version}` segment: removing it is a behaviour change outside this phase's remit.
- **Filter order needs no new work.** Authentication, rate limiting and authorization are middleware in `Program.cs`
  and run before any endpoint in both stacks, so a 401, 403 or 429 precedes any 400 before and after. Body binding
  runs before the validation filter in both, too. The step 1b tests include one 401-before-400 and one
  429-before-400 case to pin it.

## Open Questions

None blocking. Left to the builder: the endpoint class naming, the order of the middle controllers, and how the
shared client-error ProblemDetails helper is shaped, as long as the contract tests pin the bytes.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| An implicit MVC behaviour is missed, such as client-error bodies, binding-failure 400s or `traceId` | Silent contract change the Web app may not show | Step 1b tests on MVC first; the table above is the checklist |
| `WorkflowRunGateway` resolved before the 503 filter runs on a disabled host | Bare 500 instead of 503 | Resolve lazily; `WorkflowDisabledHostTests` covers it |
| `Asp.Versioning.Http` is not AOT-clean | Native API blocked in 3.6 | Read `aot-analysis`; upstream issue per milestone policy |
| A response type missing from the JSON context | Runtime failure with no reflection fallback | No fallback in the chain, so tests fail loudly; every endpoint is hit by integration or Playwright tests |
| The `Location` header differs between `CreatedAtAction` and the minimal equivalent, in case or path | Clients following `Location` break | Step 1b asserts `Location` per 201 endpoint |
| Ported unit tests pass for the wrong reason | Coverage lost silently | Red/green per assertion, the recurring defect named in CLAUDE.md |
| MVC and minimal APIs both registering a route mid-phase | Ambiguous-match 500s | The controller is deleted in the same task its endpoints are mapped |
