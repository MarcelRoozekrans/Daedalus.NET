## The things worth remembering

**1. The first live run failed because a skill made the model infer a fact the host knew.** B7's
process told `implement` to work out whether it was sandboxed or local by looking at its tool list.
The tool list was 74 entries long, and the model got it wrong. See "The live proof, as run".

**2. Integration only ever migrates fresh databases.** B1's bump of `ZeroAlloc.Outbox.Orm` from 4.0.1

table, and the migrations failed on boot with a `ZeroAllocOrmMigrationConflictException`. The
integration suite was green at B9 and none of it could have seen it. It was found at B10's first boot,
before any credits were spent.

**3. Every Red had to fail on its own assertion.** B8 caught one of its own tests passing for the wrong
reason, a seed `.sln` with no projects that let `dotnet test` exit 0. The final review then found a
real seam, `AGENT.md/x`, that no per-task review saw. See "Red-verification notes".

## Defects the live proof found before any credits were spent

**The migration-history upgrade.** The first AppHost boot exited 1 against the real database:
`ZeroAllocOrmMigrationConflictException`. In ZeroAlloc.ORM 2.2.0, migration history is scoped by source
with primary key `(source, version)`. The Outbox.Orm and Workflow.Orm sources had shared one pre-scoping
table, and 9 of its 11 rows were workflow rows. The library's in-place upgrade assigns every row to the
source it is running and then refuses if any row is not that source's, so no run order could pass. The
cause was B1's bump of `ZeroAlloc.Outbox.Orm` 4.0.1 to 4.2.0. The history table was unchanged by the
failed boot, and the AppHost was stopped.

- **Fix `fb46111`.** Migrations attribute the shared table's rows per source before either runner runs.
  It was verified on a `pg_dump` copy of the real database. The review judged it safe on the real
  database: attribution exact, equivalent to the library's upgrade, atomic under the runner lock,
  idempotent, fails closed.
- **Tests `816524c`.** Pins the upgrade to the library's layout, its attribution and its lock. 35
  Migrations tests and the Unit suite were green.
- **Result.** Boot 2 migrated the real database cleanly, exit 0. The API was healthy in about 60 s.
- **The Thalos counterpart is #266.** `Workflow.Orm`'s schema initializer fails at startup on any
  database migrated before 0.13.0. It is not reachable in Daedalus, since `EnsureSchemaOnStartup` is
  false.

## Red-verification notes

CLAUDE.md names tests that pass for the wrong reason as this codebase's recurring defect, and asks for
falsifiability per assertion, not per test. Every task report in this phase carries a table of Reds,
each applied, run and restored, and every review checked it. Notable cases:

- **The seed `.sln` with no projects (B8).** The first seed solution had no configuration sections.
  Roslyn loaded it, but `dotnet test` said "Unable to find a project to restore!" and exited 0 with no
  test summary. Test 1 still passed, because the PR body contained `Passed!` from the scripted review
  evidence's own wording. The seed now has proper configurations, the evidence text no longer says
  `Passed!`, and the assertions require a record summary and a `## Tests` line that start with `Passed!`.
- **The Reds that failed an earlier step (B8 review, I3).** Three Reds failed an earlier assertion
  rather than the one they named. For example, dropping `runScoped` from the generated
  `sandbox.mcp.json` made the host refuse to boot, so the test failed at host start and never reached
  its S3 assertion. Fix round 1 re-aimed each at its own assertion: the `thalos.run_id` claim, the
  patch-removed retry, and a same-container Red built with the Docker API because the runtime always
  creates a fresh `/work`.
- **The I1 `AGENT.md/` seam (final whole-branch review).** The two-commit publish split protects
  `AGENT.md` as a file, so `AGENT.md/x` was writable and publishable, in both modes. No task review saw
  it, because each task checked its own seam. The fix protects `<path>/` as well, and the root fix is
  Thalos #265. B8's scripted test uses a seed with no `AGENT.md`, since with one present the I1 Red
  could not go red.
- **Unreachable and non-falsifiable guards that were dropped or replaced.** A6's reverse-DNS test
  cannot go red on Docker Desktop, so it was kept with the pinned `squid.conf` test as the Red that fires
  here (R25). A8's R8a could not go red because the worktree equals the index after `git add -A`.
- **Wrong-reason Reds in Part A.** A6's implementer redid five wrong-reason Reds. A7 had three unrun Reds
  and one cap Red that did not go red. A12's S3 Red, run with an in-process runtime, left check 1 passing and failed check 2 with
  `marker.txt` found on the host, which is what proves check 2 is real.
- **A regression found only by a full run.** B4's fix round 2 made a disabled-engine host answer 503.
  Two `ResumeAuthorizationBoundaryTests` still expected the old 500 and failed at B5. R56 records the
  process lesson: any round that changes host wiring runs the full Integration suite.

## Lessons

- **Integration only ever migrates fresh databases.** A test that creates the schema from nothing cannot
  catch an upgrade. A dependency bump that changes persisted layout needs a test that starts from the
  previous layout. `816524c` is that test for this one.
- **A skill must not make the model infer facts the host knows.** Run mode is decided by configuration.
  Asking a model to deduce it from a 74-entry tool list produced a confident wrong answer that cost a
  process version and a live run. If the host knows it, the host states it.
- **Load-sensitive Windows CI flakes, and the root causes behind them.** The series on Thalos, each
  root-caused and fixed in the code or test that held the wrong assumption, not retried:
  - `RunScopedMcpToolSourceTests` reload test: a wall-clock overlap assumption. Fixed with a
    `--reload-when` gate and a `FakeTimeProvider` (`e28ac59`, `4f98fb5`). Pre-existing on main.
  - Windows load flakes in `SandboxProcessRunner` and `RemoteRunToolSource`: grandchild spawn through
    cmdlets, cleanup that did not stop the tree first, and a cut-off wait past `ConnectTimeout`
    (`802d7ff`, `5a4bc49`).
  - `RunMcpServerRegistryTests` removal test (16.8 s against an 8 s bound): a test defect. Blocking
    stdio pipe reads in MCP SDK 2.2.0 starve the thread pool under CPU load, and cancellation itself was
    prompt. Fixed on PR #258. The upstream part is Thalos #257.
  - `GitCliRunWorkspaceGitTests.Push_argv...` on ubuntu: hypothesis ETXTBSY from `WriteSpyGit`
    exec-after-write, also fixed on PR #258.
  - `RemoteRunToolSourceTests` cut-off test, "no connection could be made": **a product defect**, not a
    flake. The SDK's 5 s discover-probe fell back to initialize, and an SDK 2.2.0 bug sent a mismatched
    protocol header, so the sandbox answered 400. Fixed in 0.14.2 with Thalos #259 and #260 filed.
  - One failure dropped as not worth a fix (R41): `RunMcpServerRegistryTests` failed once under a
    synthetic 40-burner load and never on CI.
  - Unrelated Git tests failed once each under full-solution load (LibGit2Sharp `CreateBranch`,
    `GitMirrorStoreTests.Prepare_clones_once`). They passed alone and their errors were not captured, so
    they are watched, not filed.
  - **Process lesson:** `publish-nuget` builds only the tagged commit. A fix merged after the tag cannot
    unblock that tag, which is why 0.14.1 stayed a tag and 0.14.2 was needed.

### Part A, Thalos 0.14.0

- **R8.** `ProtectedPathSet.Normalize` canonicalises: empty and `.` segments dropped, any `..` segment is
  protected, fail closed. The plan's version was a bypass. Cost if wrong: a path with `..` is refused as
  protected.
- **R9.** The Action-only overload becomes `UseRunWorkspaceToolsAllowingAnyExtension`, which sets
  `AllowAnyWriteExtension` itself. Carry to A8: `*` maps to it. Cost if wrong: a rename.
- **R10.** The network spike finding is a binding amendment to A6, A8, B2 and A12 (squid, nginx and
  Dockerfile specifics, stateless MCP per route). Cost if wrong: none, it was measured.
- **R11.** Sandboxes reaching each other is already answered by the per-sandbox bearer token; A8's review
  must confirm every route is token-guarded. Cost if wrong: a cross-run call needs a leaked token.
- **R12.** Git's case-sensitive tree is the source of truth for base-file reads; document it, do not
  reject case mismatches. Cost if wrong: a wrongly-cased config path pins empty standing instructions.
- **R13.** Bundles carry a temporary `refs/heads/thalos-bundle/<guid>` branch, not a `refs/thalos` ref,
  because `git clone` of a bundle fetches only branch refs. Cost if wrong: none.
- **R14.** The mirror's in-process gate is static, keyed by full lock-file path; a commit missing from
  the mirror is a failure in `ReadFileAsync`, not absent. Cost if wrong: a static table of semaphores,
  bounded by repositories.
- **R15.** Short-name-shaped segments such as `foo~1` are refused on every OS. Cost if wrong: a repo with
  a legitimate `name~N` path cannot publish such a change.
- **R16.** An empty patch applies as a no-op success, so publish's DiffStat check reports "nothing to
  publish". Cost if wrong: none.
- **R17.** A patch creating or changing a symlink (mode 120000) or gitlink (160000) is refused at
  publish. Cost if wrong: a run cannot publish a symlink or submodule bump.
- **R18.** GitCli's CR-to-LF normalisation is a pre-existing defect outside A4; the applier refuses such
  names, and a Thalos issue is filed (#245). Cost if wrong: a CR-containing filename cannot be published.
- **R19.** `GitPatchApplier` refuses `.gitattributes` and `.gitmodules` at any depth. Cost if wrong: a
  run cannot edit a nested `.gitattributes`.
- **R20.** The applier refuses every patch on non-Linux Unix until a tested lstat check exists; issue
  #246. Cost if wrong: sandbox publish is unusable on a macOS host.
- **R21.** `SandboxSpec.Validate()` returns a result (no throw), refusing `;`, empty and `*` extensions
  and `;` in protected paths; `Environment()` emits extensions distinct and ordinally ordered; A10 calls
  it before create. Cost if wrong: one more call site.
- **R22.** A6's `GetAsync` and `ListAsync` log engine failures and return null or empty, which is
  fail-safe: reconcile deletes nothing. Cost if wrong: an engine outage is reported as "no sandbox".
- **R23.** The runtime pulls the gateway and egress images when missing but never the run image; a
  labelled leftover `-work` volume is recreated, an unlabelled one fails create; infra is re-ensured when
  create fails because it is gone. Cost if wrong: a slower first create.
- **R24.** A6's "sandboxes can reach each other" is settled by R11, not an owner decision. Cost if wrong:
  not stated.
- **R25.** The reverse-DNS runtime test is kept though it cannot go red on Docker Desktop; the pinned
  `squid.conf` test is the Red that fires. Three inspects per cached-infra call are accepted. Cost if
  wrong: a slower Get or List.
