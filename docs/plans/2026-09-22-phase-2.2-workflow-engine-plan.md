# Phase 2.2 Implementation Plan — durable workflow engine

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A durable, resumable process engine with branching, loops and human approval gates, whose process shape is a git-authored file rather than code.

**Architecture:** A run is a database row advanced one node at a time. Each node completion commits the event log append, the edge evaluation, the run update and the next outbox enqueue in **one transaction**, so a crash never re-pays for a completed agent turn. The graph lives in `Thalos.NET.Workflow`; persistence and dispatch live in `Thalos.NET.Workflow.Orm`; Daedalus supplies process files, agents, skills and hosting.

**Tech Stack:** .NET 10, `ZeroAlloc.ORM` 1.6.6, `ZeroAlloc.Outbox` 2.6.0 + `ZeroAlloc.Outbox.Orm` 2.6.0, `AdoNet.Async.Adapters` 1.4.0, Npgsql, YamlDotNet, xUnit, Testcontainers.PostgreSql. **No EF Core in either new package.**

**Spec:** `docs/plans/2026-09-22-phase-2.2-workflow-engine-design.md`

**This plan spans TWO repositories.** Tasks 1–8 are in `C:\Projects\Prive\Thalos.NET`; tasks 9–11 are in `C:\Projects\Prive\daedalus`. Each repo gets its own branch and its own PR. Every task states its repo — check before committing, because the default assumption will be wrong half the time.

## Explicitly out of scope for this phase

The spec's `models:`, `lenses:` and `quorum:` fields are **parsed and validated by Task 1 but not executed**. `Thalos.NET.Anthropic` is the only chat provider that ships, so a panel has nothing to fan out to; the spec records this as carried-forward and the definition of done does not include it. Task 1 keeps the fields so a process file written today stays valid when a second provider lands — **do not implement the panel, and do not quietly drop the fields.**

## Global Constraints

- **Never commit to `main`** in either repository. Run `git rev-parse --abbrev-ref HEAD` before every commit.
- **Thalos.NET must never reference Daedalus.** Not a package reference, not a project reference, not a type. `tests/Thalos.NET.Tests.Architecture/DaedalusIndependenceTests.cs` enforces this and must stay green.
- **No EF Core in `Thalos.NET.Workflow` or `Thalos.NET.Workflow.Orm`.** EF Core is Milestone 3's AOT blocker and the reason this phase uses `ZeroAlloc.ORM`. A `Microsoft.EntityFrameworkCore.*` reference anywhere in either package's tree is a task failure.
- **Central package management in both repos:** `PackageReference` carries **no `Version` attribute**. Add versions only in `Directory.Packages.props`. `NU1109` is an error and cannot be suppressed.
- **Commit message bodies must contain no nested parentheses** — release-please silently drops the entire commit from the changelog while the workflow still reports success. Write `typeof IFoo`, not the nested-paren form.
- **No `claude.ai/code/session_*` URLs** in commits or PR bodies.
- **Run tests in the FOREGROUND with an explicit timeout. Never background a test run** — five or more agents were lost to that in earlier phases. Long runs stay with the controller.
- **Capture the test baseline before changing anything**, per repo, and leave it unchanged except for tests you add.
- **No test may be one that cannot fail.** For every assertion, name the code change that turns it red, and for the security- and durability-relevant ones, actually make that change and observe RED before restoring. Phase 1.7 found eight tests passing for the wrong reason, two of them inside guards written to catch exactly that.
- **`dotnet` is a Windows process:** give it Windows-style paths, never git-bash POSIX paths.
