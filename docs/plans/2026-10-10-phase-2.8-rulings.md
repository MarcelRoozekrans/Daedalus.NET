## What this phase produced

The Ralph loop is gone. A person now starts work from the board, and each run is a manufacture run.

- **Bridge (Tasks 1, 2, 7 to 10).**
  - `POST /api/tasks/{id}/manufacture` starts a manufacture run for a board task. It is guarded by the
    `WorkflowResume` policy.
  - The repository is matched against `Thalos:Workflow:Repositories` (P2). The task's title and
    description become the work intent.
  - A run that started but could not be attached is cancelled, with a reason that names the failure.
  - `Task.WorkflowRunId` links the task to its latest run. The Tasks page has a Manufacture button,
    shows the run's derived status and links to its pull request.
- **Derived status (Tasks 2, 7, 8; D4, A2, A7).**
  - A task's status is computed when it is read: Running gives 1, Awaiting gives 5 (Awaiting
    Approval), Succeeded gives 2, Failed gives 3, Cancelled gives 6.
  - Values 5 and 6 are never stored. The check constraint `CK_Tasks_Status_Stored` enforces that.
  - On a host with the engine off, the run status is Unknown and the stored status shows.
  - While a run is live, update and delete answer 409. Deleting a project does too, if any of its
    tasks has a live run.
  - `Task.RowVersion` is now Postgres `xmin`, so optimistic concurrency is real.
- **Costs (Tasks 3 to 5; D3, A3, A4, A9).**
  - Every completed agent node writes a `node-usage` record.
  - A startup backfill fills in records for older runs. A partial unique index on (run, seq) makes
    both paths idempotent.
  - Cost analytics has four sources: `history` (TaskExecutions), `manufacture`, `chat` and
    `scheduled`. Sessions owned by `workflow:*` are excluded from `chat`.
  - `by-session` is deleted. `estimate` is kept.
- **Frozen knowledge (Task 6, A5).** `search_failure_patterns` and `search_learnings` say their data
  predates the retirement. The learnings write path is deleted (Task 13).
- **Deletions (Tasks 11 to 15).**
  - The loop's settings are removed from task create and edit.
  - The `Daedalus.Console` host, the `daedalus-console` image and the root `Dockerfile` are deleted.
  - The pipeline is deleted: its 8 middlewares, the orchestrators, prompt builders, the loopback
    evaluator, the workspace context and the learnings service.
  - The Ralph-only API and UI are deleted: Ralph config, execution sessions, and the execute, abandon,
    resume and regenerate-plan commands.
  - The loop's repository and domain members are deleted.
  - The `ExecutionSessions` table and the old task columns stay as history (D5).
- **Names (Tasks 16, 17; D6, A8).**
  - `IRalphAgentFactory` is renamed to `IAgentFactory`.
  - `Thalos:Memory:RalphRecall` is renamed to `LearningsRecall`. A configuration that still sets the
    old key fails at boot.
  - No live code says Ralph, except the CodeAnalysis `RalphLoopOrchestrator` (#279, P10).
- **Docs (Task 18).**
  - The README has a "Manufacturing a task" section, and `CLAUDE.md`, the development guide and the
    architecture diagrams are rewritten.
  - The revoked context7 key is removed from `.mcp.json`, and `ralph_wiggum.html` is deleted.

Suites at the end of the branch: Unit 1045 (plus 7 parity rows), Unit.Application 260,
Unit.Domain 346, Unit.Infrastructure 91, Integration 676, Playwright.Api 113, Playwright.Browser 82.

## Incidents

- **The Task 8 Console boot failure.** Registering the run-status reader only on engine hosts broke DI
  for the Console. It was fixed at the source: a `TryAdd` Disabled fallback beside the handlers that
  use it (`5071850`).
- **A `byte[]` RowVersion that never enforced anything.** Npgsql treats `byte[] RowVersion` as an
  ordinary column, so the Task 8 lost-update guard could not fail. `Task` moved to `xmin` (`5071850`).
  The six other entities are on #290.
- **Exception text in API errors.** Task 9's review found repository failures echoing `ex.Message`.
  It was fixed for `TaskRepository` and `ProjectRepository`, and for `DeleteProjectCommandHandler` in
  the final round. The other sites are on #326.
- **An S3267 fix that changed what a benchmark measured.** The Task 11 implementer satisfied the
  analyzer by turning the manual-iteration benchmark into LINQ. The controller restored a manual
  indexed loop (`5eb70e6`).
- **The safety check and helper scripts.** Running a shell helper script inside a monitor loop was
  blocked, as in 2.7. Inline Python pollers worked.
- **Commit-type hygiene.** Two `fix:` commits that changed no behaviour were reworded to `docs:` and
  `test(tasks):` on the unpushed branch with `git filter-branch`. A backup ref was kept, and the tree
  was identical afterwards.
