# Phase 1.8 Implementation Plan — docs and architecture diagrams

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the documentation describe the system that exists, and release Thalos.NET 0.6.0.

**Architecture:** Restructure `docs/architecture-diagrams.md` around the current architecture rather than appending to it, then document Thalos.NET's 11 packages, then release.

**Spec:** `docs/plans/2026-09-21-phase-1.8-docs-and-diagrams-design.md`

## Global Constraints

- **Every type, file, interface and method named in any document must be verified to exist.** Use `grep`, not memory. The phase 1.7 audit found guidance naming `RalphLoopService.cs` and `ClaimNextTaskAsync`, neither of which exists — the real names are `RalphLoopWorker.cs` and `ClaimNextAsync`.
- **Every package claim must be checked against `Directory.Packages.props`.** The same audit found ~80 lines documenting Polly, which is not a dependency, and a Specification pattern that is not present.
- **Every mermaid block must render.** A diagram that fails to parse is worse than no diagram.
- **State what is NOT present.** Absence cannot be discovered by reading code, so it must be written down.
- Commit message bodies must contain **no nested parentheses** — release-please silently drops the entire commit from the changelog while the workflow still reports success.
- No `claude.ai/code/session_*` URLs in commits.
- **Never commit to `main`.** Check `git rev-parse --abbrev-ref HEAD` before committing.
- Documentation-only changes must not alter `src/`. If a document cannot be written truthfully without a code change, that is a finding to report, not a change to make.

### Task 3: Dispatch and agent runtime

**Files:**
- Modify: `docs/architecture-diagrams.md`

- [ ] **Step 1: Replace the CQRS section with mediator dispatch**

The old section describes the hand-rolled `ICommandHandlerFactory` layer deleted in phase 1.7.

**This section carries the most weight in the document.** It must show the boundary: `IMediator` and `AddMediator()` are generated `internal` to `Daedalus.Application`, so they cannot appear in a public signature or be called from `Program.cs`; the two controllers that dispatch commands depend on the public `IApplicationCommands` facade covering 8 commands. That is the most surprising thing about the current design and the thing a newcomer will get wrong.

Also record that requests are `readonly record struct`, because the generator rejects reference-type records.

- [ ] **Step 2: Agent runtime section**

`IAgentRuntime`, sessions, memory over pgvector, skills, and subagents via `ISubagentRunner`.

- [ ] **Step 3: Verify every interface named exists, confirm mermaid renders, commit**
