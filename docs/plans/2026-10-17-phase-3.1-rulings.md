## Rulings

1. Task 2's measurement run, Step 3, is done by the controller, not the implementer — it needs Docker, the realm
   secrets and a scratch worktree at `8173fd55`, and a fresh subagent should not handle secrets.
   *Cost if wrong:* the controller's context grows.

2. Task 1 Step 6's red-proof commits are pushed to this phase's own branch and reverted there — the ratchet can only
   be proven red in real CI. Superseded by ruling 6.
   *Cost if wrong:* two extra CI runs in the branch history.

3. Task 3, the audit, runs while Task 4 waits for the owner's Thalos merges, if the ordering allows — the audit is
   independent of the Thalos work.
   *Cost if wrong:* none.

4. The correction of the spec and plan for the owner's ORM decision waits until Task 1's implementer has committed,
   because both work in the same worktree.
   *Cost if wrong:* none, since Task 1 does not touch those files.

5. The Web publish adds `-p:PublishTrimmed=true` to the constraint command — WebAssembly AOT refuses to run
   untrimmed, and `Daedalus.Web.csproj` sets it false for the normal publish. The override is on the command line
   only.
   *Cost if wrong:* none.

6. Task 1's red proof in real CI comes from the phase PR, not a branch push — `ci.yml` triggers only on PRs and on
   pushes to `main`. The local red proof stands until then, and the PR's runs add the URLs below.
   *Cost if wrong:* the gate is proven in CI later than planned.

7. The Api leg of the AOT job keeps its 90-minute timeout on `ubuntu-latest` — the Api publish took 21 min 23 s in
   Task 1, by its log timestamps, with ILC near 12 GB resident, and 22 min 3 s in the smoke run, on the 12-core agent
   VM, against the hosted runner's 16 GB. If it runs out of memory on the PR, that is fixed then, with
   a larger runner and not by skipping Api.
   *Cost if wrong:* one red PR run.

8. The load script alternates the `dev` and `admin` tokens — the API's global rate limit is 100 requests a minute per
   subject, so 200 requests as `dev` alone return 100 replies of 429.
   *Cost if wrong:* none; the load is the same 200 requests at concurrency 10.

9. The harness starts its own Postgres and Keycloak, and runs the migrations with `dotnet run`, instead of using
   `docker-compose.full.yml` — that file is broken: its `migrations` service builds a Dockerfile that does not
   exist, and its connection-string keys are ones no host reads. It is a different area, so it is filed as an issue
   (see Findings).
   *Cost if wrong:* none.

10. The handover's errors that the audit found are corrected in the handover in Task 6, which now points at audit
    section 6 — the handover goes to another agent, and a wrong requirement there costs more than here.
    *Cost if wrong:* none.

11. The six ZeroAlloc.ORM gaps the audit found, the three hard gaps and the three further ones, the migration-skip
    defect among them, stay in the audit for the owner's ZeroAlloc session, not filed, per the owner's no-issues
    decision.
    *Cost if wrong:* they depend on the owner handing the audit over.

12. The milestone design's 3.5 mention of `ZeroAlloc.Specification` is replaced by ZeroAlloc.Linq in Task 6 —
    CLAUDE.md rules Specification out, and the owner's decision supersedes it.
    *Cost if wrong:* none.

13. Task 4's implementer commits only; the controller reviews, then pushes and opens the Thalos PR — a PR is
    outward-facing, so it is reviewed first.
    *Cost if wrong:* one extra hand-off.

14. After the Thalos bump, Task 5 recounts every target and sets exact baselines, in the commit that changes each
    count — the ratchet is two-way, so a stale baseline fails CI either way.
    *Cost if wrong:* CI red on the PR.

15. The `publish-release` cache scope change is accepted — the brief's "unchanged" meant its push behaviour, and
    without the scope it would read a cache that nothing writes any more.
    *Cost if wrong:* a one-line revert.

## Thalos PR and release

- **MarcelRoozekrans/Thalos.NET#365,** `feat(sandbox)!: make the sandbox host AOT-clean`, merged on 2026-10-18 as
  `8a6cf03`. The sandbox host went from 10 distinct warnings to 0 in Thalos' own native smoke host, with no
  suppression: `IsAotCompatible`, the Request Delegate Generator, the slim builder, and a reflection-free
  `AddLocalTools<TTools>` overload with source-generated JSON contexts. Thalos' suite: 2366 passed.
  The native smoke host served `/control/ready`, imported the bundle, ran `tools/list` and returned `read_file`'s exact
  content, per Thalos.NET#365. The spec decided that a native run, not a warning count, is the proof.
- **Release v0.18.0,** published on 2026-10-18 from release PR #367. All 18 Thalos packages moved to 0.18.0 together,
  and Daedalus consumes them from Task 5.
- **Known cosmetic defect.** The release notes' BREAKING CHANGES entry ends with a stray
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. The commit's `BREAKING CHANGE:` footer ran straight into
  the trailer with no blank line between them, so the conventional-commit parser read the trailer as part of the
  footer's text. The release was cut before a `BEGIN_COMMIT_OVERRIDE` in the PR body could fix it, and a published
  release's notes are not regenerated. The packages are unaffected.
  - **Lesson:** a `BREAKING CHANGE:` footer is followed by a blank line before any trailer; and when the merged
    commit is already wrong, the override goes into the PR body before release-please runs, not after.
