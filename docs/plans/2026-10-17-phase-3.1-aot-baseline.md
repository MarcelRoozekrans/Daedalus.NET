# Phase 3.1: the JIT baseline

The start-up, memory and size numbers of the JIT build that milestone 3 starts from. Phase 3.6 runs the same harness,
`eng/measure/`, against the Native AOT build and compares with these. The harness README defines every field.

## What was measured

- **Commit:** `8173fd55`, main at the start of milestone 3, in a detached scratch worktree holding the harness of this
  branch.
- **Images and binary:**

  | Target | Built with | Digest |
  | --- | --- | --- |
  | API | `docker build -f src/Daedalus.Api/Dockerfile` | `sha256:d9deb05e41a50dd60820d5d6969177b4a6b13808ac27fcb74b6a669272016184` |
  | Sandbox | `docker build -f src/Daedalus.Sandbox/Dockerfile` | `sha256:547d8a6536e100704802ff58aaa25c3c01e4489104f6085a2d2c6257f7ee18d3` |
  | CLI | `dotnet publish src/Daedalus.Cli -c Release`, run as `Daedalus.Cli.dll` | `sha256:18f0fe2396727a9e61c8101cafd3bdcbd721f79a6c3cdb12a7d0699d327fe9a8` |

- **VM:** Debian 13, kernel 6.12.111, Intel Core Ultra 7 255H with 12 logical CPUs, 23 GiB RAM, Docker 29.9.0,
  .NET SDK 10.0.402.
- **CPUs:** 2. Containers ran with `--cpus 2`, and the CLI under `taskset` on two cores.
- **Runs:** 10 cold starts per target per pass, two passes back to back, with no build running on the VM. Four
  unrelated long-running containers stayed up throughout. The API and CLI shared one Postgres and Keycloak stack,
  holding the migrated schema and no rows.

| CLI | 1 | 1114.0 | 1217 | 146.0 | 146.0 | n/a | 76.4 |

The API's peak is `VmHWM` after 200 `GET /api/projects` at concurrency 10. For the CLI and the sandbox, the peak is
read at the same moment as the idle value.

## Variance between the passes

| Target | Start-up median | Start-up p90 | RSS idle | RSS peak |
| --- | ---: | ---: | ---: | ---: |
| API | -4.6 % | -9.5 % | +0.2 % | -0.8 % |
| CLI | +2.1 % | +7.9 % | -0.1 % | -0.1 % |
| Sandbox | -4.5 % | -7.2 % | 0 % | 0 % |

- **Start-up varies by about 5 % at the median and up to 10 % at p90** between passes on the same VM. So a
  difference smaller than that, in phase 3.6, is noise. Native AOT is expected to cut start-up by far more than that.
- **Memory is stable to within 1 %.**
- **Sizes are identical,** because the images and the binary did not change.

## Reading the numbers

- **The sandbox image is 1375 MiB, of which the app is 6.6 MiB.** The rest is the .NET SDK, which each run needs to
  build and test the code it works on. Native AOT shrinks the host, not the SDK, so the image will stay large. The
  numbers to watch for the sandbox are start-up and RSS.
- **The API's app is 104.5 MiB of a 463.7 MiB image.** The rest is the `aspnet:10.0-alpine` base image, which a native
  build replaces with `runtime-deps`.
- **The CLI runs through `dotnet`,** so its start-up includes the host's resolution of the shared framework.
