# Phase 3.4 Rulings: controllers to minimal APIs

**Spec:** `docs/superpowers/specs/2026-10-31-phase-3.4-minimal-apis-design.md`
**Impact analysis:** `docs/superpowers/specs/2026-10-31-phase-3.4-minimal-apis-impact-analysis.md`
**Plan:** `docs/superpowers/plans/2026-10-31-phase-3.4-minimal-apis-plan.md`
**Contract snapshot:** `tests/Daedalus.Tests.Integration/Api/endpoint-contract.snapshot.txt`, pinned by
`EndpointContractSnapshotTests`

The phase runs subagent-driven on `phase/3.4-minimal-apis`. The impact analysis was written after the design and
corrects it on six points; the plan follows the analysis where the two differ, and those six corrections are R1 to R6.
R7 to R10 are calls the design or the plan makes that the owner did not, and R11 and R12 are Task 1's own. Every
later task appends from R13. Every decision taken on the owner's behalf is listed with what it costs if it is wrong,
so it can be checked and reversed. The snapshot file changes only through a ruling here.

## Owner decisions

Owner decisions are the owner's to weigh, so they carry no cost line.

2026-10-31, at the brainstorm, in the design's "Owner decisions":

- **Approach A: incremental, with a route-table snapshot.** Snapshot the MVC endpoint table first, port one controller
  per task with both stacks live, remove MVC last.
- **Handler classes, unit-tested directly.** One static endpoint class per controller, one `Map…Endpoints` extension
  and one static handler per endpoint returning typed `Results<…>`; the controller unit tests call the handlers, case
  for case.
- **The 14 `catch (Exception)` blocks stay, byte-identical,** `500 { "error": "Internal server error" }`. Removing them
  is #426.
- **JSON is source-generated in this phase, matching today's bytes,** with no reflection fallback. The anonymous
  `new { error = … }` bodies become a named record.

2026-10-31, during the impact analysis, in its "Owner decisions taken during the analysis":

- **The target list is confirmed,** `AgentErrorResults`, `StartWorkflowRunRequest` and the Browser fixture included.
  The Browser host switches to the same public `Map…Endpoints` extension `Program.cs` uses.
- **Integration tests that construct controllers are retargeted at the handlers,** case for case, red/green per
  assertion.
- **`ApiAuthorizationTests` becomes an `EndpointDataSource` check:** every `RouteEndpoint` carries an authorization
  policy or is on an explicit anonymous list.
- **`EnableRequestDelegateGenerator=true`** in the API project.

Later, 2026-10-31:

- **Release-please stays on hold** for the phase.
- **Keep today's unversioned wire and drop the dead versioning code** (Task 1 found it inert, R11). Endpoint groups
  get no version set and `Asp.Versioning.Http` is not added. Task 20 removes, together with MVC, the inert
  `AddApiVersioning` call in `Program.cs`, the 13 `[ApiVersion]` attributes, `Asp.Versioning.Mvc` from
  `Directory.Packages.props` and the API's csproj, the `Asp.Versioning` global using, and the Browser fixture's copy of
  `AddApiVersioning`. Task 20 also drops the snapshot's `versions` column, which pins `-` on every line and whose
  `ApiVersionMetadata` type leaves with the package, and the `HasApiVersion` case of
  `Render_reads_a_minimal_api_endpoint_from_its_metadata`; both stay until then. If real versioning is wanted later,
  it gets its own issue. This withdraws R8.

## Rulings

The impact analysis' corrections to the design, Task 1:

1. **R1:** `tests/Daedalus.Tests.Integration/Controllers/*` do not test over HTTP, so they cannot "pass unchanged".
   Seven of them, `AgentMemories`, `AgentSessions`, `CodeAnalysis`, `Projects`, `Repositories`, `TaskExecutions` and
   `Tasks`, construct the controller and assert on `OkObjectResult` and friends, as do five cases in
   `Workflow/ResumeBoundaryTests.cs`. They are retargeted at the handlers, per the owner's decision; only
   `SchedulesControllerTests` is not one of them.
   *Cost if wrong:* a retargeted test asserts on a typed result where an HTTP test would have caught a wire
   difference; the snapshot and the body-shape tests are the wire check, so the cost is a gap only where neither
   reaches.
2. **R2:** three targets the design missed are in scope: `Agents/AgentErrorResults.cs`, MVC-bound and used 21 times;
   `StartWorkflowRunRequest`, declared in `WorkflowRunsController.cs` and used by 16 test files; and
   `Playwright.Browser/Fixtures/E2EServerFixture.cs`, a second composition root that maps controllers itself.
   *Cost if wrong:* none in the direction of doing more; leaving any of the three out breaks the build or, for the
   Browser fixture, fails at runtime with 404s once MVC goes.
3. **R3:** `ApiAuthorizationTests` reflects over eight controller types and holds an assertion that cannot fail,
   `true.Should().BeTrue()`. It is rewritten over `EndpointDataSource` on the booted host (Task 9), per the owner's
   decision.
   *Cost if wrong:* one test rewritten that could have been patched; the rewrite is what makes it hold on both stacks.
4. **R4:** "`Microsoft.AspNetCore.Mvc` usings go" is too strict. `ProblemDetails`, `ValidationProblemDetails` and the
   `[FromQuery]`, `[FromBody]`, `[FromRoute]`, `[FromServices]` attributes live in that namespace but in the shared
   framework's `Http.Abstractions` and `Mvc.Core` assemblies, and minimal APIs use them. What goes is MVC's services and
   types: `ControllerBase`, `IActionResult`, `ObjectResult`, `ProblemDetailsFactory`, filters, `AddControllers`,
   `MapControllers`, `Asp.Versioning.Mvc`. The end-of-phase check greps for those, not for the namespace.
   *Cost if wrong:* an MVC type that sits under a name the grep does not list survives; CI's `aot-analysis` count is
   the backstop.
5. **R5:** the request delegate generator is switched on, `EnableRequestDelegateGenerator=true` in
   `Daedalus.Api.csproj`, from the first ported controller, per the owner's decision. It is on by default only under
   `PublishAot=true`, so without it every test would run the reflection `RequestDelegateFactory` while the native
   publish ran generated delegates.
   *Cost if wrong:* a generator diagnostic to fix in each port task, which is work the native publish needs anyway.
6. **R6:** the problem `Content-Type` is recorded per endpoint, not per stack. Twelve controllers carry
   `[Produces("application/json")]` and serve problem bodies as `application/json` (#366); `TasksController` does not
   and serves `application/problem+json`. The snapshot's `content` column and the body-shape tests pin both.
   *Cost if wrong:* none to the contract; a uniform choice would have been a contract change on one side or the other.

Calls in the design and the plan, Task 1:

7. **R7,** superseded in part by R16: binding failures keep MVC's 400. A malformed query value answers `ValidationProblemDetails` with "The value
   '{raw}' is not valid for {name}.", and an empty or `null` POST body answers "A non-empty request body is required."
   with the parameter's implicit-required error (Review Focus 1 and 2). Minimal APIs answer a bare 400 for both, so
   the endpoints bind through `ApiBody<T>` and `ApiQuery<T>`, which never fail binding and carry the problem MVC would
   have written.
   *Cost if wrong:* two shared binding types to maintain; dropping them later is a contract change, a bare 400 where a
   client reads errors today.
8. **R8, withdrawn** by the owner's versioning decision of 2026-10-31 above; kept for the record. `Asp.Versioning.Mvc`
   goes from 8.1.0 to 10.2.1 beside `Asp.Versioning.Http` 10.2.1 while both stacks live,
   so one versioning family is loaded, and leaves with MVC.
   *Cost if wrong:* a versioning behaviour change between 8.1 and 10.2 lands on the controllers before they are ported;
   the snapshot and Task 3's version tests are the check. On today's host the controllers are not versioned at all
   (R11), so the bump would have bought nothing.
9. **R9:** OpenAPI is held to equivalence, not bytes, and response metadata matches MVC's declared set. Nothing
   consumes the document; it is served only in Development for Scalar. Equivalence means the same operations with the
   same status codes and response types, which is the snapshot's `responses` column; there is no snapshot of the
   document itself. Each endpoint declares, with `.Produces*` and `.ProducesProblem`, the same statuses, types and media
   types as its `[ProducesResponseType]` attributes, so its line does not change. A type name may differ only where MVC
   declared none and a typed `Results<…>` infers one, and each such difference is a named ruling here.
   *Cost if wrong:* a difference in the document outside what the snapshot renders, such as a parameter's schema or a
   summary, goes unnoticed; nothing reads it.
10. **R10:** `CodeAnalysis`' `ModelState.IsValid` and `BadRequest(ModelState)` checks, lines 67 and 177, are dropped,
    not reproduced. They are dead today: `[ApiController]`'s invalid-model filter answers before the action runs, and
    `ZeroAllocValidationFilter` never writes `ModelState`.
    *Cost if wrong:* if either check could fire, a 400 it wrote is lost; R7's binding problems and the validation
    filter answer the same cases first.

Task 1, the snapshot:

11. **R11:** the snapshot renderer is stack-neutral. `EndpointContractSnapshotTests.Render` reads each
    `ApiDescription`'s own fields and its `ActionDescriptor.EndpointMetadata`, never a controller type's attributes:
    `IAuthorizeData`, `IAllowAnonymous`, `EnableRateLimitingAttribute` (which `RequireRateLimiting` adds too),
    Asp.Versioning's `ApiVersionMetadata`, `ProducesAttribute`, and a `ProblemContentType` record matched by type name
    and read through its `ContentType` property, the hook for the metadata a port task adds. Route constraints are
    rebuilt from each parameter's `RouteInfo`, because MVC's `RelativePath` drops them and the minimal-API explorer
    keeps them. A second test, `Render_reads_a_minimal_api_endpoint_from_its_metadata`, maps one versioned,
    authorized, rate-limited minimal-API endpoint and checks every column fills from it. The host is
    `ScratchWorkflowHost`, `ApiWebApplicationFactory` with `workflowEnabled: true` over a fully migrated scratch
    database on the `PostgresFixture` server, because the factory forbids the engine over the shared fixture database.
    The snapshot has 61 lines, one per action.
    *Cost if wrong:* a column that renders blank on one stack makes every later check on it vacuous; the minimal-API
    test is the guard, and a field the renderer does not read at all is not pinned. Binding sources and request body
    types are left out on purpose: R7's `ApiBody<T>` and `ApiQuery<T>` change the parameter descriptions by
    construction, so pinning them would change the snapshot on every port; Tasks 2 and 3's body-shape tests own
    binding.

    **Found while generating it, for the controller:** the `versions` column reads `-` on every line. `Program.cs`
    calls `AddApiVersioning` without `.AddMvc()`, so the controllers' `[ApiVersion("1.0")]` is never read: no
    `api-supported-versions` header is sent and `?api-version=2.0` answers 200. The global constraints and Review
    Focus 3 assume versioning is live on MVC. A port that maps its group with `.HasApiVersion(1.0)` changes the
    snapshot line and the wire. Resolved by the owner's versioning decision of 2026-10-31, above.

Task 1, review fix round 1:

12. **R12:** the `content` column takes the last content-type-bearing item in endpoint metadata, a
    `ProducesAttribute` or the `ProblemContentType` record, whichever comes last. MVC lists a controller's attributes
    before its action's and minimal APIs a group's metadata before its endpoint's, so an endpoint-level value
    overrides the group's, as an action's `[Produces]` overrides its controller's on the wire. Ported groups carry
    `ProblemContentType.Json` only where the controller had `[Produces("application/json")]`; the Tasks group carries
    no record, so its lines stay `content -`; the stream endpoint keeps `text/event-stream` through its own
    endpoint-level metadata. The first renderer let the record win over any `[Produces]`, which would have rendered
    the stream endpoint as `application/json` after its port.
    *Cost if wrong:* a port that sets the content type at the wrong level renders the right line while serving the
    wrong header; the body-shape tests' `Content-Type` assertions are the wire check.

Task 2, MVC's implicit answers, pinned in `MvcBehaviourContractTests`:

13. **R13:** the bodiless 404 is pinned on `GET /api/workflow-runs/{unknown}`, not on `GET /api/projects/{unknown}` as
    the brief had it. `ProjectsController` answers `NotFound(new { error = "Project with ID {id} not found" })`, a
    plain `{ "error" }` body as `application/json`, which `Problem_content_type_is_per_controller` pins as it is. The
    only bare `NotFound()` calls are in `WorkflowRunsController`, so that case boots `ScratchWorkflowHost` (R11). MVC
    answers members `type`, `title`, `status`, `traceId`, no `detail`; type
    `https://tools.ietf.org/html/rfc9110#section-15.5.5`, title `Not Found`, `application/json; charset=utf-8`.
    *Cost if wrong:* none; both answers are pinned, each on the endpoint that serves it.
14. **R14:** no bodiless 409 is pinned, because no action returns one. Every 409 in the controllers carries a body:
    `Problem(detail: ...)`, `Conflict(new { error })` or `Conflict(new ProblemDetails { ... })`. Task 5's `ApiProblem`
    needs no bodiless-409 mapping to keep the contract.
    *Cost if wrong:* a port that adds a bare 409 gets no wire check; MVC would have written its client-error problem
    for it, and nothing here says what that looks like.
15. **R15:** the bodiless 401 is pinned over HTTP, so Task 5 needs no unit-test fallback for it.
    `HeaderTestAuthHandler` always sets `sub`, so no principal without a subject reaches the branch. A subject equal to
    `AnonymousSecurityContext.AnonymousId`, `anonymous`, takes the same branch: `HttpSecurityContextFactory.TryCreate`
    refuses it the way it refuses a missing one. Pinned on `GET /api/agent-memories`, `application/json`, and on
    `POST /api/tasks/{id}/manufacture`, `application/problem+json`: members `type`, `title`, `status`, `traceId`; type
    `https://tools.ietf.org/html/rfc9110#section-15.5.2`, title `Unauthorized`.
    *Cost if wrong:* the missing-subject path itself, a claim set with no `sub`, no `NameIdentifier` and no name, is not
    exercised over HTTP; it reaches the same `return Unauthorized()`, so only `TryCreate`'s own unit tests cover it.
16. **R16:** a malformed query value answers "The value 'abc' is not valid.", with no "for take". R7 and Review Focus 1
    quote "The value '{raw}' is not valid for {name}.", which is MVC's message for a property of a bound complex type.
    A top-level action parameter gets the non-property message. Pinned for `take`, an `int`, on
    `GET /api/schedules/{id}/runs`, and for `projectId`, a `Guid`, on `GET /api/brainstorm/sessions`; the key is the
    parameter name as declared. `ApiQuery<T>` writes the non-property text; R7's quoted wording is superseded.
    *Cost if wrong:* none to the contract; the pinned text is what MVC sends today.
17. **R17:** the malformed-JSON error key is the JSON path where `System.Text.Json` stopped, `$` only when it stops at
    the root. `{"name":` gives key `$.name` with the reader's message verbatim, line and byte position included;
    `[1]` gives key `$` with "The JSON value could not be converted to Daedalus.Application.DTOs.CreateProjectDto.
    Path: $ | LineNumber: 0 | BytePositionInLine: 1.". Either way MVC adds the parameter's key, `request`, with "The
    request field is required.". An empty body and the literal `null` both answer key `""`, the empty string, with "A
    non-empty request body is required." beside the same `request` entry. A nullable body parameter,
    `CancelWorkflowRunRequest?`, accepts an empty body and binds null.
    *Cost if wrong:* `ApiBody<T>` must carry the reader's path and message and the parameter name through; a fixed `$`
    key fails the `{"name":` case.
18. **R18:** what is pinned and what is not. Pinned: the exact member set; `type`, `title`, `status` and `detail` as
    raw JSON; every `errors` key with its messages in order; `traceId` as a non-empty string; the whole `Content-Type`,
    charset included, `application/json; charset=utf-8` or `application/problem+json; charset=utf-8`. Not pinned: the
    order of members and of `errors` keys, which follows MVC's model-state dictionary. The implicit `[Required]` on a
    non-nullable reference property fires only when the bound value is null: an initializer or a parameterless
    constructor that supplies a value keeps an omitted member from being refused, and an empty string passes binding
    and meets `ZeroAllocValidationFilter`, whose problem is rfc7231-typed, has a `detail` and no `traceId`. Nested
    keys carry the collection path, `PrdItems[0].Title`. The stream action's binding problem is
    `application/problem+json`, not `application/json`: its own `[Produces("text/event-stream")]` replaces
    `AgentSessionsController`'s, so Task 16's port keeps that.
    *Cost if wrong:* a client that reads members or error keys in order would break unnoticed; none is known.
19. **R19:** text escaping is pinned. MVC's `JsonOptions` escape relaxed, so an apostrophe goes out as `'`, not
    `\u0027`. The tests compare raw JSON against values serialized with `JavaScriptEncoder.UnsafeRelaxedJsonEscaping`,
    so a port whose serializer escapes by default fails "The value 'abc' is not valid.".
    *Cost if wrong:* if the owner holds escaping to be outside the contract, Task 5 still has to match it or relax
    these assertions through a ruling; the JSON means the same either way.

Task 3, headers, nulls and pipeline order, pinned in `MvcBehaviourContractTests`:

20. **R20:** MVC writes null members. `GET /api/projects/{id}` for a fresh project answers `"modifiedAt":null`; MVC's
    `JsonOptions` keep `DefaultIgnoreCondition` at `Never`. `ApiJsonSerializerContext` declares `WhenWritingNull`, so
    the endpoints' JSON options must not take that from the context: Task 5 sets the options so a null member is
    still written, and `Null_properties_are_written` fails a port that drops it.
    *Cost if wrong:* a client that tells "absent" from "null" sees members vanish; the Blazor client deserializes
    both the same, so the visible damage would be in third-party clients only.
21. **R21:** `Location` is absolute wherever MVC builds it, and relative in the one place a controller wrote it by
    hand. `CreatedAtAction` writes scheme and host from the request, `http://localhost` under TestServer, and the
    route's own case, so `api/[controller]` gives the class name: `http://localhost/api/Projects/{id}`,
    `http://localhost/api/Tasks/{id}`, `http://localhost/api/Repositories/{id}`,
    `http://localhost/api/CodeAnalysis/{requestId}`, `http://localhost/api/agents/sessions/{sessionId}` and
    `http://localhost/api/workflow-runs/{id}`. `POST /api/tasks/{id}/manufacture` uses `Created` with a relative URI
    and answers `/api/workflow-runs/{id}`. Task 5's `ApiLocation.For` builds the absolute form from the request's
    scheme, host and path base, with the path in the casing above, and the manufacture endpoint keeps its relative
    string. The brief listed five 201s; the two workflow ones, `POST /api/workflow-runs` and manufacture, are pinned
    too, on `ScratchWorkflowHost` (R11), since no other test pins their `Location`.
    *Cost if wrong:* a lower-cased or relative `Location` passes every status check and breaks only a client that
    follows the header; the path base is not exercised, TestServer has none.
22. **R22:** versioning is pinned inert, as the owner ruled on 2026-10-31. A 200 carries no `api-supported-versions`;
    `?api-version=2.0` and `x-api-version: 2.0` get the same status, `Content-Type` and body as the request without
    them. The Red change is `.AddMvc()` on `AddApiVersioning`, which turns both tests red: the header appears, and 2.0
    is refused with a 400.
    *Cost if wrong:* none to the contract today; if versioning is later turned on, both tests change with it by a
    ruling.
23. **R23:** the order tests use MVC's real limits and no host setting, because `Program.cs` reads none for
    `write-operations`. That limiter is one fixed window of 30 permits a minute for the whole host, not partitioned
    per user, so the test spends 30 permits with `POST /api/projects` and `{}`, each answered with the binding 400,
    and the 31st same request answers 429. Each test boots its own host, so no other test shares the window, and the
    window opens with the first request. The 429 is pinned whole: `Content-Type` `application/problem+json` with no
    charset, and the exact `OnRejected` body. `Unauthenticated_comes_before_validation` pins the 401 status only: its
    body comes from the test scheme's challenge, not JwtBearer's, so it says nothing about production.
    *Cost if wrong:* a 31-request run that straddles a minute would see the window reset and fail; the requests take
    well under a second, so this is not expected. A port that moved the limit or forgot `RequireRateLimiting` fails
    the test either way.
24. **R24:** the `Accept: application/xml` case's `Content-Type` assertion is falsified with
    `[Produces("text/json")]` on `ProjectsController`, not with an XML formatter. `AddXmlSerializerFormatters()` with
    the controller's `[Produces]` removed was tried and stayed green: MVC still answered the page as JSON. The
    status assertion is falsified with `ReturnHttpNotAcceptable = true`, which answers 406.
    *Cost if wrong:* none; the test pins what MVC serves, and the minimal endpoints have no XML formatter at all.

Task 4, endpoint composition beside MVC:

25. **R25:** SSE events keep their own source-generated context. `AgentEventDto` has eight optional members that the
    stream omits when null; the reworked `ApiJsonSerializerContext` is `DefaultIgnoreCondition.Never`, which would write
    them as `null` in every event, since the stream names `Default` and so gets the context's own options. `AgentEventStreamJsonContext` keeps `WhenWritingNull` and the old options, the
    controller's `WriteEventAsync` serializes through it, and `Stream_events_omit_unset_members` pins
    `{"kind":"done"}`. `AgentEventDto` is no longer in `ApiJsonSerializerContext`.
    *Cost if wrong:* this is the spec's no-contract-change rule over the plan's single-context wording; if the owner
    wants one context, every stream event gains eight null members and clients written against the stream see them.
26. **R26:** the context lists every request and response type of the 13 controllers' actions now, not as each port
    arrives. The endpoints' chain is the context alone, and `Microsoft.AspNetCore.OpenApi` reads the same Http
    `JsonOptions` to build schemas for the MVC actions, so with a short list Development `GET /openapi/v1.json`
    answered 500 "JsonTypeInfo metadata ... was not provided" (baseline 200). The collection types are listed as the
    actions declare them, `IReadOnlyList<T>` and `IEnumerable<T>`. `OpenApiDocumentTests` boots the API in Development
    and pins 200 with paths; each later port's new type must be in the context or it fails. A reflection fallback was
    refused as the forbidden alternative.
    *Cost if wrong:* the context grows by the MVC actions' types a few tasks early; the port tasks would have had to
    add them anyway.
