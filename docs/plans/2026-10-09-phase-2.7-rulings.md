## What this phase produced

Issues are now a first-class output. Agents can read GitHub issues, developers can file them through chat, and a
manufacture run files the review findings it deliberately did not fix, so they are tracked and not lost in the event
log.

- **Issue reads and writes (tasks 1 and 2).** `GitHubApi` gained `GetIssueAsync`, `SearchIssuesAsync`,
  `ListIssuesUpdatedSinceAsync`, `ListIssueCommentsSinceAsync`, `GetPullRequestHeadShaAsync` and `CreateIssueAsync`,
  all `Result<T>`, plus `RepoRef.FromGitHubUrl`. `repoaction__create_issue` joined `DaedalusRepoActionTools`, bound to
  the existing developer policy, so no workflow run can call it.
- **The `issues__*` tool source (task 3).** `issues__get` and `issues__search` are ungated reads in their own source,
  named only by the reviewer and the chat Architect. Search refuses its own `repo:`, `org:`, `user:` and `owner:`
  qualifiers and drops hits from other repositories (A5). Issue text is framed as third-party content.
- **Deferred findings in the review evidence (tasks 4 and 5).** `report_review_outcome` takes an optional `deferred`
  array, accepted only with an approval. Each entry is `file`, `line`, `title`, `scenario`, `reason` and an optional
  `existingIssue`. `ApprovingReview.Read` is the one place that reads the approving visit and gives each finding a
  stable id `<lens>-<n>`.
- **The gate (task 6).** The run view shows the deferred findings. The resume request may name findings to drop; an
  unknown id is a 422; the drop is recorded with the resumer, as a `findings-dropped` record that a
  `findings-drop-voided` record cancels when the resume then fails (A1).
- **The `file-review-findings` host action and process v9 (tasks 7 and 8).** After publish, a `file-findings` node
  files each remaining finding as an issue, or comments on the issue the reviewer named, idempotently through markers
  and a `since` scan (A2). It declares only the outcomes `filed` and `none`; every failure is a failed result that
  phase 2.5's admin retry can re-run (A3). The repository and PR number come from `pr_url` and the allow-list is
  re-checked (A4). The review skill gained "Out of scope: defer, do not drop".
- **Verification, docs and the live proof (task 9).** Docs in `docs/development-guide.md` and
  `docs/architecture-diagrams.md`; about 45 analyzer warnings on branch lines cleared; the live proof below.
- **A fix the live proof forced.** `62ed406`: a review node's reported variables are dropped before the bag cap.

Final suites: Unit 939, Unit.Application 439, Unit.Domain 383, Unit.Infrastructure 153, Integration 712 of 712.

## Defects the live proof found

**The review node overflowed the variable bag.** Run 2's `review` node reported six new variables: `lens`, `note`,
`verdict`, `tests_run`, `deferred_count` and `files_reviewed`. `run_mode` already existed. That took the bag to 15, and
to 17 with the host's keys, past the cap of 16. Phase 2.6's passing run had minted four (`lens`, `verdict`,
`diagnostics`, `sandbox_test`) and reached 13, so the margin was three and 2.7 spent it.

- **Root cause.** The review node's free-form reported variables land in the shared bag though nothing reads them.
  Evidence lives in records, `retrospect` reads learnings and pins, and `publish` reads `implement`'s summary. The
  phase's own skill text had nudged one extra key, `deferred_count`.
- **Fix `62ed406`.** `ReviewHandoffWorkflowStore` drops the reported variables of a node that declares lenses before
  merging, so absence matches the projection's design. `retrospect` and `implement` keep theirs. The cap is not
  raised, since raising it only moves the cliff. One sentence in `skills/manufacture-review/SKILL.md` tells the model
  to report only the outcome. This is ruling R25.
- **Tests `03c68a2`.** The review caught that the real-bag cap count had lost its falsifying test. It was restored on
  `retrospect`, with host keys forged on a review node shown to be dropped. Three former review-node cap tests moved
  to `implement`, since a review node can no longer overflow.

**The Anthropic key.** Run 1 failed on a 401 before any work. This is environmental, not a code defect, but it cost one
attempt and shows that 2.6's advice to rotate was followed.

## Red-verification notes

Every task report carries a table of Reds, each applied, run and restored, and every review checked it. Notable cases:

- **A test that could not fail (task 1 pre-flight).** The plan's pagination test routed on the fragment `page=1`,
  which also matches `per_page=100&page=2`, so page 2 got page 1's body and the scan never ended. Routed on `&page=1`
  and `&page=2` instead (R1). Likewise the truncation test counted `x` over output whose framing sentence contains `x`;
  it now counts `Z` (R2).
- **The assertion that asserts nothing (task 7).** The plan mandated a `NotContainAny` host-path assertion. No code
  change could turn it red, because the action handles no host path. It was dropped (R13).
- **A Red that was not falsifiable with `Uri` (task 7).** `new Uri` escapes spaces, so the path-escape Red could not go
  red. The test finding became `src/Sub Dir/C#/A.cs`, expecting `C%23`.
- **A test that asserted inside the callback it was testing (final fix wave, L3).** The first draft of
  `The_void_is_bounded_by_its_own_timeout` asserted inside the append callback, and the gateway swallows whatever that
  throws, so it could not fail. Its own Red run caught it; the token state is now captured and asserted afterwards,
  with a `FakeTimeProvider` and no sleep.
- **A comment describing an old failure.** The cancelled-request test's comment described the pre-fix failure mode. It
  was rewritten and the void assertion confirmed red with the request token.
- **Review-evidence strictness (`a9dbb65`).** The three failing `SquadHandoffEndToEndTests` were fixed by adding the
  `deferred` member to the pin, not by loosening it. Red verified.
- **Task 6 and task 7 Reds that proved a race and a forgery.** Tasks 6 and 7 each added tests for scenarios the plan
  left unpinned: the concurrent resumes that leave the loser's drop list latest, and the comment scan, summary scan,
  scan window and summary ordering behind the marker defence.
- **Task 7's tests were written with the implementation in one pass,** not build-error-first. The implementer said so,
  and falsifiability was then proven per assertion by mutations.
- **Part of the Integration evidence is late.** The `OpenPullRequestActionTests`, `ProcessDefinitionSyncEndToEndTests`
  and the Postgres drop test were written, compiled and unrun until Docker returned; they ran green in the final
  712.

## Lessons

- **A shared bag is a budget, and every new reporter spends it.** 2.6 left three keys of margin. A node whose output
  nothing reads should not write to shared state at all. When a skill asks the model for an extra key, that is a
  change to the budget and needs the same review as a code change.
- **Do not claim a security closure the code cannot back.** Task 7's marker ruling claimed to close the forgery paths.
  The final review showed that any caller with the same login could still plant a valid marker through
  `repoaction__comment_on_issue` or `repoaction__create_issue`. Closing it needed `<!--` neutralized in those tools too
  (R15).
- **Decide the cheap outcome first.** A host action that checks its preconditions before it knows it has any work
  fails runs that had nothing to do. C1 was exactly that; the `none` decision now precedes every GitHub check (R14).
- **Two live runs may not exercise the feature you built.** The reviewer judged the gap sound or already acknowledged
  by the intent. A live proof that depends on a model choosing to defer cannot be forced by an intent alone. Either
  script a deferring reviewer, as 2.6 did for its negative check, or accept that the path is proven by tests only.
- **A bare `dotnet format` rewrites about 120 unrelated files.** Later dispatches ran `dotnet format whitespace` and
  `style` with `--include` on their own paths (R5). Drift is tracked by #295 and #312.
- **An analyzer error is a fix, not a suppression.** The owner's rule held in task 1: `Uri HtmlUrl` replaced the
  `CA1056` suppression (R6). The one suppression that stayed is `CA1054` on `FromGitHubUrl(string?)`, which genuinely
  accepts SSH remotes that are not URIs.
