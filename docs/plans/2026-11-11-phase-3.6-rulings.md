# Phase 3.6 Rulings: native Api, Cli and Migrations

## Rulings

Calls the design leaves to the builder:

1. **R1, Task 1, the YAML reflection root.** No caller exists. `eng/aot/find-reflection-callers.sh` reads the
    metadata of every assembly in a non-AOT Api publish: TypeRefs, MemberRefs including generic TypeSpecs, and base
    types. Only `Thalos.NET.Workflow` 0.20.0 and `YamlDotNet` 18.1.0 mention YamlDotNet. Thalos uses the static
    path: `ProcessYamlContext : StaticContext` and `StaticDeserializerBuilder`. Nothing, in Thalos or in YamlDotNet
    itself, calls `Deserializer::.ctor()`, `Serializer::.ctor()`, `DeserializerBuilder::.ctor()` or
    `SerializerBuilder::.ctor()`. A call graph over YamlDotNet's IL from `StaticDeserializerBuilder` reaches 86
    methods, none of them in `ReflectionExtensions`, `TypeConverter` or the parameterless constructors. Yet the
    ILC log of `main` compiles those constructors and reports IL3050 on them. A constructor that nothing calls is
    compiled only when its whole assembly is a root.
    The cause is in this repo: `Directory.Build.props` sets `TrimMode` to `partial`. In partial mode the SDK gives
    every assembly without `IsTrimmable=True` the trim mode `copy`, and ILC's `Microsoft.NETCore.Native.targets`
    turns that into `--root:<assembly>` plus `--defaultrooting`. The metadata check shows YamlDotNet 18.1.0 has no
    `IsTrimmable` attribute, so ILC roots all of it and warns on its reflection paths. The same holds for
    `Daedalus.*`, `HealthChecks.NpgSql`, `Pgvector` and `Rag.NET`, which are also not marked. The Sandbox
    project already sets `TrimMode` to `full` for this reason (phase 3.1).
    The mechanism is inferred from the targets file, the call graph and the observed IL3050 on uncalled
    constructors; the Task 3 CI native run proves or refutes it.
    Decision: the fix is `TrimMode` `full` for the published native hosts, in their project files, not a change in
    Thalos, a ZeroAlloc package or YamlDotNet. No upstream issue: YamlDotNet is not marked trimmable and is not
    wrong to leave it so, and Thalos already uses the AOT-safe static builder. Task 3 sets the property and reads
    the `aot-analysis` log; if warnings remain they are reachable code, not rooted code.
    Existing values: `src/Daedalus.Cli/Daedalus.Cli.csproj` line 13 and
    `src/Daedalus.Migrations/Daedalus.Migrations.csproj` line 14 already set `TrimMode` to `none`, so Task 3
    overrides an existing value there. `src/Daedalus.Web/Daedalus.Web.csproj` line 9 notes that ILLink accepts
    only `full` or `partial`, so `none` is not an option for any host that runs ILLink.
    Caution for Task 3: with `full`, warnings from assemblies that are not trimmable can collapse into one
    per-assembly summary warning, IL3053 for ILC or IL2104 for ILLink, instead of individual IL3050 lines.
    Compare the per-assembly detail and the keys file, not only the baseline number, so that a drop in the
    count is not hidden warnings.
    *Cost if wrong:* the CI log still shows YamlDotNet warnings after `full`, and Task 3 then traces the rest from
    the log instead of the call graph.
