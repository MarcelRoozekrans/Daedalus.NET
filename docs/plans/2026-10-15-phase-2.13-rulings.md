# Phase 2.13 Rulings: Navigation and flow

**Spec:** `docs/superpowers/specs/2026-10-15-phase-2.13-navigation-and-flow-design.md`
**Plan:** `docs/superpowers/plans/2026-10-15-phase-2.13-navigation-and-flow-plan.md`
**UI contract:** `docs/plans/2026-10-15-phase-2.13-navigation-and-flow-ui-contract.md`, amended where a ruling below says so
**UI review:** `docs/plans/2026-10-15-ui-review-phase-2.13.md`
**Sweep:** `docs/regression-report-2026-10-15-2026.md`

The phase ran subagent-driven: each task had a fresh implementer and a fresh reviewer, and a whole-branch review ran at
the end. The owner chose that method, approved the plan, and was away for the second half. Every decision taken on the
owner's behalf is listed below with what it costs if it is wrong, so it can be checked and reversed.

## Rulings

### API (Tasks 1 to 3)

1. **The `[Produces]` fix was taken to its root in `TasksController`.** A class-level `[Produces("application/json")]`
   overrode the ProblemDetails content type. It was removed there, so every task refusal and validation 400 is
   `application/problem+json` with a `detail`. The 12 other controllers with the same attribute are filed as #366.
   *Cost if wrong:* a follow-up PR.
2. **The review-limit reason keys on a `CapExceeded` step into `adjudicate`.** The plan said "a `CapExceeded` step from
   `review`". The engine records the cap on the edge back into review, from `implement` to `adjudicate`. An integration
   test drives a real capped run to prove it.
   *Cost if wrong:* a wrong reason if another node ever gains a cap that leads to `adjudicate`.
3. **A failed run with no steps reads "The run ended before any step."** The plan had no copy for it, and the spec
   says a reason is never empty.
   *Cost if wrong:* one copy edit.
4. **A review visit with any unreadable record reads "Unreadable".** It shows a Warning badge, is still listed, and is
   still paired with implement's answer. The contract was amended.
   *Cost if wrong:* a label change.
5. **`LensCheckedView` gained `Findings`.** The brief had nowhere to put per-lens findings, and the contract needs them.
6. **`review-response` is recorded only while the completion is acceptable:** `seq == CurrentSeq` and the run is
   Running. The lens runner's same-shaped evidence path, and the remaining race between two deliveries at the same seq,
   are filed as #368.

### Web (Tasks 4 to 8)

7. **Expired sessions are handled in one outermost HTTP handler, `SessionExpiryHandler`, rather than in `ApiClient`.**
   It covers every client and every component that calls `HttpClient`, including `AgentApiClient`.
   *Cost if wrong:* a handler to move.
8. **Browser tests cannot reach Keycloak.** They use a test-mode switch and assert the app's own sign-in redirect. The
   real Keycloak round trip was checked in the Task 10 sweep, and it passed.
9. **The landing sentence is the README's second sentence:** "A person plans work on a task board …". The first is
   about how Daedalus is built, not what it does.
   *Cost if wrong:* a copy edit.
10. **While the sign-in state is unknown, the header shows the logo only, and the body shows a Loading indicator.**
    Content appears once the state is known.
    *Cost if wrong:* a blank header for a few milliseconds.
11. **An expired session shows one Info notification, "Your session has ended. Signing in again.", for about 1.5
    seconds before the redirect.** Pages skip their own error rendering for it.
    *Cost if wrong:* a different notification style.
12. **The tablet sidebar starts collapsed, as the approved contract says.** The contract was not changed to match the
    old behaviour.
    *Cost if wrong:* one media query.
13. **A task with a run shows its run's badge through `RunStatusLabels`, exactly as Runs does.** A task with no run,
    which is frozen history from the retired loop, shows its own status text in a muted badge.
    *Cost if wrong:* a muted Failed badge on legacy tasks.
14. **The Tasks grid shows Created, not Updated.** Nothing stores a "last updated" time. #373 asks the owner what
    "updated" should mean. The contract was amended.
    *Cost if wrong:* renaming the column back once #373 lands.
15. **Pre-existing range bugs in the task DTOs were fixed.**
    - Priority is 0 to 3, Low to Critical; it said "0 (Critical) to 4 (Low)" and accepted 4.
    - Complexity is 0 to 2.
16. **Home's Recent pull requests card has no count.** It is a fixed list of five.
17. **A refused manufacture started from Home shows its reason on Home, with an Open Tasks link.**
18. **The time a gate has waited counts from the run's `UpdatedAt`.**
19. **`GET /api/workflow-runs` gained server-side `signal` and `updatedSince` filters,** with `updatedSince` in ISO 8601
    only.
    - Thalos 0.17.0 cannot filter on either, so the controller scans up to 500 summaries and returns `Next` only when
      more matches may remain.
    - **This is a workaround,** tracked on #367 with a store-side query as the real fix.
    *Cost if wrong:* past 500 failed runs, a card can show "n+" even when it is complete.
20. **The PR card queries `process=manufacture`.** When its page is incomplete it says "No pull requests in the latest
    20 runs."; the real filter waits on #367.
21. **`WorkflowRunView.Checked` was removed rather than filed.** No reader was left outside tests, and the review
    visits replace it.
    *Cost if wrong:* an external client that reads `checked`; none is known.
22. **Commit trailers name the model that wrote each commit.**
    *Cost if wrong:* a trailer edit.

### UI review fixes (Task 10)

23. **The UI review's ten findings were fixed in this phase, not deferred.** Primary and success token contrast,
    3.66:1 for white on `--rz-primary`, is a palette decision that MASTER.md reserves for its own change. It is filed
    as #374.
24. **On a phone, the Tasks grid is one stacked column** rather than only hiding Project. At 375px, Status and
    Manufacture cannot fit beside the title any other way. The contract was amended.
