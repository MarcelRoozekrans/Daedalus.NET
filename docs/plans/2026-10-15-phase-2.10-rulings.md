# Phase 2.10: execution rulings

Per-node model and tool selection with Minos.NET, from 2026-10-13 to 2026-10-15. Spec
`docs/superpowers/specs/2026-10-13-phase-2.10-minos-decisions-design.md`, plan
`docs/superpowers/plans/2026-10-13-phase-2.10-minos-decisions-plan.md`. The first session was killed mid-B3 and a second
session resumed from the SDD ledger; nothing was lost, the only uncommitted file matched its pre-mutation copy.

## What this phase produced

- **Thalos.NET 0.17.0** (Thalos#325, release #326): `AllowedModels` on the agent definition and envelope, a per-request
  `Model` and `ToolFilter` on `SubagentRunRequest`, checked in the engine by `IAgentFactory.ValidateOverridesAsync`, so a
  turn can only narrow. Thalos#330 added the missing default-envelope test.
- **Decisions** (`src/Daedalus.Agents/Decisions/`): the `NodeQuestions` set, `NodeSelectionMapper`, and
  `NodeSelectionDecider`, which asks Minos over OpenRouter within `Thalos:Decisions:Timeout` and never fails a node. Every
  problem becomes the defaults with a reason: `off`, `timeout`, `error:{kind}`, `error:Client`, `error:Validate`,
  `low-confidence`, `tools-unresolved`, `no-allowed-models`.
- **`NodeSelectionRunner`**: one decision per implement or review visit, recorded as a `node-selection` run record under
  the filtered unique index `UX_WorkflowRunRecords_NodeSelection_RunId_Seq`, reused on redelivery, validated with Thalos
  before it is recorded, never narrowing after a rejected review. Lens model pins apply only while decisions are on.
- **Wiring**: the AppHost secret `openrouter-key` as `OPENROUTER_API_KEY`; decisions only with a key and
  `Thalos:Decisions:ZeroDataRetentionAccount: true`; a start-up line saying why they are off; `daedalus.decisions` and
  `Minos` telemetry; `nodeSelections` and `nodeSelectionsError` on the run view; review usage priced per model.
- **`review-replay`** (`processes/review-replay.yaml`): one review of an existing `manufacture/<run-id>` branch, seeded with
  the original run's `files_touched`.
- **B11, found by B9**: every node now gets the full task. See Incidents.

shrink. Total B9 spend: 21 runs, $25.09, about EUR 23.

## Incidents

- **The task was cut at 512 characters for every node.** `work_intent` reaches agents as a Thalos workflow variable,
  and `WorkflowVariableBlock.MaxValueLength` is 512; the pinned manifest document never reached a turn. H1 lost 18
  characters, H2 184. The first H2 runs took four review rounds because Opus 5.5 would not approve requirements it could
  not see. Fixed in B11 (`WorkIntentRunner`, `ddb1e75`..`42f5354`): implement and review get the full intent as a framed
  block, and the host's framing tags are neutralised in variables for agent turns only. The rerun approved H2 on the
  first round. It predates phase 2.10; this phase did not cause it.
- **R1's first decided run failed** with `SubagentBudgetExceeded`, 155138 of 150000 tokens; void, rerun under the
  temporary limits.
- **The API refused to start** once a Telegram bot token was set without `PrincipalId` and `AllowedUserIds`, by design;
  the owner configured both.
- **The Anthropic credit ran out** mid-replay; two replays failed on it and were rerun after the top-up.
- **Integration tests on the agent host** failed in bulk while the Aspire stack ran: the inotify instance limit of 128.
  `DOTNET_USE_POLLING_FILE_WATCHER=1` for the test process avoids it.
- **ASP.NET Core 10.0.12 advisories** broke restore on `main` mid-phase; fixed in #358 and merged into the branch.
