> **Purpose:** This contract defines the visual and interaction specification for phase 2.12's manufacturing
> console. It is produced by `ui-phase` before implementation and used by `ui-review` to audit the result.
> Sections approved with the owner on 2026-10-12.

## Design System

Design system sourced from `docs/design/MASTER.md`; the CSS it documents,
`src/Daedalus.Web/wwwroot/css/daedalus-theme.css`, wins on any disagreement. This phase adds **no** token, font,
spacing scale or gradient.

### Colors

| Token | Value | Usage in this phase |
|---|---|---|
| `--rz-primary` | `#667eea` | Approve, links, the active tab |
| `--rz-secondary` | `#764ba2` | not used by this phase |
| `--rz-base-background-color` | `#ffffff` | cards: grid card, gate panel, tabs |
| `--rz-body-background-color` | `#f8f9fc` | page background |
| `--rz-text-color` | `#334155` | body text |
| `--rz-text-title-color` | `#1e293b` | page and card titles |
| `--rz-danger` | `#ef4444` | Failed, rejected and cap-exceeded badges, error alerts, the Cancel button |
| `--rz-success` | `#10b981` | Succeeded, approved and published badges, success notifications |
| `--rz-warning` | `#f59e0b` | Awaiting badges, Reconnecting, an unreadable PR link |
| `--rz-info` | `#3b82f6` | Running, Resumed, Retried, the empty-list alert |

No hex literal in any component; reference tokens or Radzen severity enums only.

### Typography

Radzen's default stack, no webfont. Copy is `RadzenText` with `TextStyle`: page titles `H4`, card titles `H6`,
body `Body1`/`Body2`, metadata and the live indicator `Caption`. Ids, file paths and the standing-instructions
diff use `font-family: monospace`, as `Executions.razor` does for ids.

### Spacing

No token scale. `RadzenStack` with explicit `Gap` in rem (`0.25rem`, `0.5rem`, `1rem`); card spacing with
Radzen's `rz-mb-4` utility, as the existing pages do. Radius is the theme's `--rz-border-radius` (8px).

### Component Library

- [x] Other: **Radzen.Blazor** only. No second library.

## Status mapping

Status is badge text plus severity, never colour alone.

### Run status — `RunStatusBadge`

| Status | Badge text | `BadgeStyle` |
|---|---|---|
| `Running` | Running | Info |
| `Awaiting`, signal `human_approval` | Awaiting approval | Warning |
| `Awaiting`, any other signal | Waiting: `<signal>` | Warning |
| `Succeeded` | Succeeded | Success |
| `Failed` | Failed | Danger |
| `Cancelled` | Cancelled | Light |

### Timeline outcome — inside `RunTimeline`

| Event kind or outcome | Badge text | `BadgeStyle` |
|---|---|---|
| outcome `approved`, `published` (except the five kinds below) | the outcome | Success |
| outcome `rejected`; kind `Failed`, `CapExceeded` | the outcome; for the two kinds, always the kind | Danger |
| kind `Resumed`, `Retried` | the kind, whatever the outcome, plus "by `<actor>`" as caption text | Info |
| anything else (`Entered`, `Completed` with another outcome, `Branched`, `Awaiting`) | the outcome, else the kind | Light |
| a run cancelled (kind Cancelled), whatever the outcome | Cancelled | Light |

Failed, CapExceeded, Cancelled, Resumed and Retried always show their kind; other kinds are unchanged.

## Components

### Component: `RunStatusBadge`

**Purpose:** The one rendering of a run's status, shared by `/runs`, `/runs/{id}` and `/tasks`.

**Props API:**

| Prop | Type | Required | Default | Description |
|---|---|---|---|---|
| `Status` | `string` | Yes | — | Thalos `WorkflowStatus` name |
| `AwaitingSignal` | `string?` | No | `null` | The signal a parked run waits on |

**Variants:** `default` only.

**States:** stateless; an unknown status renders its raw text with `Light`.

**Visual notes:** `RadzenBadge` with `Shade.Lighter` where the existing pages use it; text is never omitted.

### Component: `RunsGrid`

**Purpose:** The `/runs` list, in the `Executions.razor` pattern.

**Props API:**

| Prop | Type | Required | Default | Description |
|---|---|---|---|---|
| `State` | `RunsState` | Yes | — | List page, filters, loading and error |

Columns: status (`RunStatusBadge`, links to the run), process and version (`manufacture v9`), current node,
task (title, links to `/tasks`; "—" when none), started by, started, updated.

**Variants:** desktop keeps all columns; tablet hides started by and updated; mobile keeps status, current node and
task. When the content area is narrower than the shown columns (desktop with the sidebar open below about 1484px, and
phones), the grid scrolls inside its card, never the page.

**States:**

- `loading` — the grid's `IsLoading`
- `empty` — Info `RadzenAlert`: "No runs yet. Start one with Manufacture on a board task."
- `error` — Danger `RadzenAlert` with the server's reason and a **Retry** button
- `success` — rows; a `RunChanged` for a listed run updates its row in place

**Visual notes:** inside a `RadzenCard`; `AllowSorting`, keyset paging through the list endpoint (Next/Previous),
`PageSize` 15. Filters (status, process) are `RadzenDropDown`s in `RadzenFormField`s in a filter card above.

### Component: `RunHeader`

**Purpose:** Who, what and where a run is, and its admin retry.

**Props API:**

| Prop | Type | Required | Default | Description |
|---|---|---|---|---|
| `Run` | `WorkflowRunViewDto` | Yes | — | The run view |
| `CanRetry` | `bool` | Yes | — | The user holds `admin` |

Content: `H4` "Run `<first 8 of id>`" + `RunStatusBadge` + `LiveIndicator` on the right; a `Caption` line with
process and version, current node, started by and the PR link ("Pull request #N", new tab, `rel="noopener"`);
`LastError` below as a Danger alert. An `UnreadablePullRequestLink` renders as Warning text instead of the link.
**Retry** (outlined, `refresh` icon with text) only when `CanRetry` and the status is `Failed`, behind a confirm
dialog.

**States:** `error` — `LastError` alert; `success` — the retry posts, then waits for `RunChanged`.

### Component: `GatePanel`

**Purpose:** The page's primary action: decide the gate.

**Props API:**

| Prop | Type | Required | Default | Description |
|---|---|---|---|---|
| `Run` | `WorkflowRunViewDto` | Yes | — | Deferred findings, standing-instructions diff |
| `Draft` | `GateDraft` | Yes | — | Dropped finding ids, apply flag, submitting |

Content: a `RadzenCard` titled "Approval gate". Each deferred finding is a row: drop checkbox, lens, `file:line`
(monospace), title, scenario, reason, and the existing issue link when present. The standing-instructions diff is
a monospace block, with an "Apply standing instructions" checkbox, **off by default**; both are absent when the
run has no diff. **Approve** (`ButtonStyle.Primary`) sends
`resume { Signal: "human_approval", DropFindings, ApplyStandingInstructions }`; **Cancel**
(`ButtonStyle.Danger`, `Variant.Outlined`) opens `CancelRunDialog`.

**Variants:** desktop (buttons right-aligned under the content), mobile (stacked, full-width buttons).

**States:**

- rendered **only** while `Status` is `Awaiting` and `AwaitingSignal` is `human_approval`
- `empty` — "No deferred findings." in place of the list
- `submitting` — both buttons `IsBusy` and disabled
- `error` — a 409 or 422 shows the server's ProblemDetails reason in a Danger alert inside the panel; a 409
  because the run moved on also re-fetches the run
- `success` — a Success notification "Run approved" (4 s); the panel closes when `RunChanged` arrives, not
  optimistically

### Component: `CancelRunDialog`

**Purpose:** Confirm an irreversible cancel.

**Props API:**

| Prop | Type | Required | Default | Description |
|---|---|---|---|---|
| `RunId` | `Guid` | Yes | — | The run to cancel |

Content: a `RadzenTextArea` "Reason (optional)", **Cancel run** (Danger) and **Keep run** (Light). Escape keeps
the run.

**States:** `submitting` — Cancel run `IsBusy`; `error` — the server's reason inline; `success` — closes, a
Success notification "Run cancelled" (4 s).

### Component: `RunTimeline`

**Purpose:** What happened, step by step, from `Steps[]`.

**Props API:**

| Prop | Type | Required | Default | Description |
|---|---|---|---|---|
| `Steps` | `IReadOnlyList<WorkflowRunStepDto>` | Yes | — | Ascending by seq |
| `Run` | `WorkflowRunViewDto` | Yes | — | For the running row |

Each row: seq, node (or `from → to` for a branch), the outcome badge, error text (Danger alert style, inline),
time and duration since the previous event, actor, tokens (input/output/cache read) when the event carries usage.

**States:** `empty` — "No steps recorded yet."; while `Running`, a final Info row "Running: `<current node>`".

**Visual notes:** a vertical list in a `RadzenCard`, not a grid; one row per event, no icons per row.

### Component: `ReviewEvidence`

**Purpose:** What the review lenses checked and what they deferred.

**Props API:**

| Prop | Type | Required | Default | Description |
|---|---|---|---|---|
| `Run` | `WorkflowRunViewDto` | Yes | — | `Checked[]`, deferred and filed findings |

Sections: **Checked** per lens (a lens name, then its items); **Deferred** (as in the gate panel, read-only; a
dropped finding is struck through with the text "dropped"); **Filed** (finding id, mode, issue link).

**States:** each section shows "None" when empty.

### Component: `NodeUsageTable`

**Purpose:** Token usage per node.

**Props API:**

| Prop | Type | Required | Default | Description |
|---|---|---|---|---|
| `Usage` | `IReadOnlyList<NodeUsageDto>` | Yes | — | Per node execution |

Columns: seq, node, model, input, output, cache read, cache write; a totals row.

**States:** `empty` — "No agent turns yet."

### Component: `WriteAuditTable`

**Purpose:** Every workspace write the run made.

**Props API:**

| Prop | Type | Required | Default | Description |
|---|---|---|---|---|
| `Audit` | `IReadOnlyList<WriteAuditDto>` | Yes | — | The write audit |

Columns: seq, node, tool, path (monospace), started by.

**States:** `empty` — "No writes."

### Component: `LiveIndicator`

**Purpose:** Tell the operator whether what they see is live.

**Props API:**

| Prop | Type | Required | Default | Description |
|---|---|---|---|---|
| `Connection` | `HubConnectionStatus` | Yes | — | Connecting, Connected, Reconnecting, Disconnected |

**Variants:** "Connecting…" (Caption, muted, no Reload; the initial state, until the first start completes or
fails); "Live" (Caption, muted); "Reconnecting…" (Warning text); "Offline: showing last loaded" (Danger
text) plus a **Reload** button (`refresh` icon, `aria-label="Reload"`).

### Changes to existing components

- **`MainLayout.razor`:** a **Runs** `RadzenPanelMenuItem`, icon `precision_manufacturing`, under the existing
  Operations group, shown only to `developer` or `admin`, with a `RadzenBadge` (Warning) holding the count of
  runs awaiting approval, hidden at zero.
- **`Tasks.razor`:** the derived status badge becomes a link to `/runs/{RunId}` with the accessible name
  "Open run"; status updates in place on `RunChanged`; Manufacture navigates to the new run instead of a toast
  with its id. Everything else on the page is unchanged.

## Layout Specification

### Desktop (≥1280px)

`/runs/{id}`:

```text
┌ sidebar 260 ┬─────────────────────────────────────────────────────┐
│             │ Run 65270f1c   [Awaiting approval]      Live        │
│             │ manufacture v9 · at gate · started by … · PR #17    │
│             │ [LastError alert, when set]                         │
│             ├─────────────────────────────────────────────────────┤
│             │ GatePanel (RadzenCard, only when awaiting approval) │
│             │  findings [drop] … · diff [apply]  [Approve][Cancel]│
│             ├─────────────────────────────────────────────────────┤
│             │ [Timeline] [Review] [Usage] [Writes]  (RadzenTabs)  │
│             │  tab content                                        │
└─────────────┴─────────────────────────────────────────────────────┘
```

`/runs`: title "Runs" (`H4`) and a `Body2` caption line, the filter card, then `RunsGrid`, matching
`Executions.razor`.

### Tablet (768px–1279px)

- The sidebar collapses through the existing `RadzenSidebarToggle`.
- `/runs`: the grid hides started by and updated.
- `/runs/{id}`: the header metadata wraps; the gate panel buttons wrap below the findings.

### Mobile (<768px)

- Single column.
- `/runs`: status, current node and task; the status badge is the link to the run. The grid is wider than a phone's
  content area, so it scrolls inside its card, never the page.
- Gate panel stacked; Approve and Cancel full width, at least 44px tall.
- Tabs scroll horizontally; usage and audit tables scroll inside their card, never the page.

## Interaction States

### Page-level states

| State | Trigger | UI |
|---|---|---|
| Loading | First fetch | `/runs`: the grid's `IsLoading`; `/runs/{id}`: `RadzenProgressBarCircular` in the content area |
| Not found | 404 | Warning alert "Run not found" with a link back to Runs |
| Forbidden | 403, or a direct URL without the role | "You need the developer or admin role to view runs." The menu item is hidden for such users |
| Error | Any other API failure | Danger alert with the server's reason and **Retry** |
| Empty | No runs | Info alert, as in `RunsGrid` |
| Success | Approve, cancel, retry | Success notification, 4 s; data changes arrive through `RunChanged` |
| Live update | `RunChanged` | Re-render in place; no toast per step |
| Reconnecting | Hub connection lost | `LiveIndicator` "Reconnecting…"; on reconnect, everything on screen is re-fetched |
| Connecting | Page load, until the first start completes or fails | `LiveIndicator` "Connecting…", no Reload |
| Offline | First start failed, or reconnect gave up | `LiveIndicator` "Offline: showing last loaded" with **Reload** |

### Form behavior

- The gate's only inputs are checkboxes and the cancel reason; nothing validates client-side. The server's 409
  and 422 reasons are shown verbatim.
- Submit disables Approve and Cancel (`IsBusy`) until the run leaves the gate; a refused approval re-enables
  them with the server's reason.
- No optimistic UI: the page reflects a change only when the server reports it.

## Accessibility Requirements

- The gate panel is a `region` with `aria-label="Approval gate"`. Each drop checkbox's label carries the finding's
  id and title.
- Approve is the first focus target when the gate panel is present on navigation to the page; a gate panel that
  appears through a live update never moves focus.
- `CancelRunDialog` and the retry confirm: `role="dialog"`, focus trapped, Escape closes, focus returns to the
  button that opened it.
- One `aria-live="polite"` region per run page announces "Status: `<badge text>`" when the run's status changes;
  timeline steps are not announced.
- Badges always carry text. Icon-only buttons (Reload) carry an `aria-label`.
- The PR link reads "Pull request #N", opens in a new tab with `rel="noopener"`.
- All actions reachable by keyboard (Tab, Enter, Space, Escape); focus ring visible (Radzen default).
- Contrast: Radzen tokens on the existing surfaces only; Warning badges use Radzen's Warning style, not custom
  text on `--rz-warning`.
- Page titles: "Runs · Daedalus" and "Run `<short id>` · Daedalus".
