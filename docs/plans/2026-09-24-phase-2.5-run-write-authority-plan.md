# Phase 2.5 — Run Write Authority: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** A manufacture run goes from a written intent to a real pull request against an
allow-listed repository. `implement` edits an isolated per-run worktree under a grant tied to the
developer who started the run. The lenses record `checked[]`, retrospect proposes, a human approves
at the gate, and host code commits, pushes and opens the PR. The token budget stops a turn before
the next model call, and prompt caching cuts the cost of every agent loop.

**Architecture:** Two repositories. Thalos.NET 0.11.0 gains:

- a write-once `StartedBy` and a recorded `ResumedBy` on workflow runs;
- tool methods that bind the calling `ISecurityContext`;
- run workspaces: abstractions, path confinement, a git worktree provider and a sweeper;
- `workspace__*` file tools;
- run-scoped MCP servers with per-call routing;
- a dispatch gate;
- host action nodes;
- a per-round-trip token ceiling;
- cache counts in `TurnUsage` and per-node usage on the node event;
- a provider-neutral `PromptCachingChatClient`, stable-first prompt order, and an Anthropic
  translator.

Daedalus adopts it. It adds a `repository` to the start request, the `workspace-writer` grant, a
host-side run record for write audit and review evidence, `AGENT.md` inside the worktree, the
`open-pull-request` host action, and process v6. It ends with a live proof that opens a real PR on
`MarcelRoozekrans/daedalus-sandbox`.

**Tech Stack:** .NET 10 / C# 13, Thalos.NET 0.10.0 → 0.11.0, `ZeroAlloc.Results`, `ZeroAlloc.ORM`
raw-SQL migrations (Thalos), EF Core 10 + PostgreSQL (Daedalus), Microsoft.Extensions.AI 10.10,
Microsoft.Agents.AI 1.22, ModelContextProtocol 2.2.0, Anthropic SDK 12.50.0, LibGit2Sharp 0.32.0,
the `git` CLI, xUnit 2.9.3 + AwesomeAssertions 9.6.0 + NSubstitute, Testcontainers.PostgreSql.

**Spec:** `docs/plans/2026-09-24-phase-2.5-run-write-authority-design.md`. Where this plan departs
from it, the reason is recorded under **Pre-plan findings**. Those departures are corrections found

## Pre-plan findings

### Open question 2: run-scoped MCP servers need a new tool-source type

**Answer: no, the current configuration cannot express it. A new tool-source type is needed.**

- `McpServerDefinition` has no substitution. `AddMcpServersFromFile` says in its own remarks that
  `${VAR}` expansion "is *not* implemented in 0.1 — values are used verbatim"
  (`Thalos.NET/src/Thalos.NET.Mcp/McpThalosBuilderExtensions.cs:110-111`).
- `McpToolSource` is a host-lifetime singleton. It connects once and caches both its client and its
  tool list for its whole life (`McpToolSource.cs:128-136`, `:171-208`).
- Tools are resolved once per agent build and baked into the cached agent. `AgentFactory.BuildAsync`
  calls `_toolCatalog.ResolveAsync(definition)` and caches the result per `(AgentId, Revision)`
  (`Thalos.NET/src/Thalos.NET/Runtime/AgentFactory.cs:87`, `:202`, `:235`). So a tool instance
  cannot be swapped per run.
- The spec's "the `roslyn` entry becomes run-scoped" would also strip Roslyn from Daedalus Architect
  and the scout, which hold `roslyn__*` (`src/Daedalus.Api/appsettings.json:241`, `:249`).

**Design (tasks A9 and A10):**

- `.mcp.json` entries gain an optional `runScoped` block holding `args`, `env`, `cwd`, `readyTool`
  and `reload`. Its values may contain `${run.id}`, `${run.workspace.root}` and
  `${run.workspace.solution}`.
- A `RunMcpServerRegistry` starts one server per run when the run's workspace is ready, and disposes
  it with the workspace.
- A `RunScopedMcpToolSource` keeps the entry's source name (`roslyn`). It takes its tool schemas from
  the host-wide server, and routes each call by the caller's `thalos.run_id` claim:
  - A caller without the claim, such as a chat or scheduled turn, is served by the host server,
    exactly as today.
  - A caller with the claim is served only by that run's server, never by the host server. This is
    what makes `roslyn__apply_*` under the grant confined to the worktree. Without routing, a
    granted `implement` turn would apply code actions to the host's own `Daedalus.sln`.

### Open question 3: `sub` is the principal id, but it is not stable in the dev realm

**Answer: `sub`.**

- `ClaimsSecurityContext` already takes `Id` from `sub`, then `ClaimTypes.NameIdentifier`, then the
  identity name (`src/Daedalus.Agents/Security/ClaimsSecurityContext.cs:373-376`).
- Program.cs uses the JwtBearer defaults (`src/Daedalus.Api/Program.cs:199-207`), so inbound claim
  mapping is on. `sub` arrives as `ClaimTypes.NameIdentifier`, which `ClaimsSecurityContext`
  covers. `roles` maps to `ClaimTypes.Role`.
- Both clients include the `basic` client scope, which emits `sub` in Keycloak 25 and later
  (`keycloak-realm.json:26`, `:85`).
- `preferred_username` is a mutable display attribute, not an identity.

**The catch:**

- The realm's users carry no fixed `id` in `keycloak-realm.json`.
- The AppHost's Keycloak has no data volume (`src/Daedalus.AppHost/Program.cs`, the `AddKeycloak`
  chain has no `WithDataVolume`).
- So the realm is re-imported on every AppHost start, and `sub` changes each time.

**Fix, task B3:** give `dev` and `admin` fixed `id` values in `keycloak-realm.json`. `StartedBy`
also records `preferred_username` as a display name, for the PR body only; it never takes part in
authorization.

**Also: the realm defines no `developer` role.** Its realm roles are `project-manager`,
`task-manager`, `analyst` and `admin`. So only `admin` qualifies a `StartedBy` for the grant.

**Owner decision 2026-09-25:** task B3 adds a `developer` realm role and assigns it to user `dev`,
so `WorkspaceWritePolicy`'s "developer or admin" is real, and `admin` stays for administration.

### Open question 1: Roslyn staleness stays a spike

Task A1 settles it. A9 implements all three reload modes, and B9 picks the one A1's finding names:

| Mode | What happens |
|---|---|
| `none` | The server re-reads changed files itself. |
| `tool:<name>` | Before the next routed call after a write, the registry calls a reload tool such as `rebuild_solution`. |
| `restart` | Before the next routed call after a write, the registry disposes and restarts that run's server. |

### Spec items found wrong or unimplementable against the real code

1. **"The workspace is ready before the first node dispatches" cannot be done after the run row
   exists.**
   - `OrmWorkflowStore.StartAsync` generates the run id itself and enqueues the start node's
     dispatch in the same transaction (`src/Thalos.NET.Workflow.Orm/OrmWorkflowStore.cs:147-183`).
   - Fix, task A2: `WorkflowStartRequest.RunId` lets the host create the worktree first and then
     start the run under that id.
2. **The budget cannot be checked "in `RunModelLoopAsync`".**
   - That method makes one call to MAF's `agent.RunStreamingAsync`. The model round trips happen
     inside MAF's function-invocation loop (`ThalosAgentRuntime.cs:298-322`).
   - Fix, task A15: the check is a chat client that `AgentFactory` puts directly over the provider,
     so it sees every round trip. It reads the ceiling from `TurnScope`.
3. **Nothing records who approved at the gate.**
   - `IWorkflowStore.ResumeAsync(runId, signal, payload)` carries no principal
     (`src/Thalos.NET.Workflow/IWorkflowStore.cs:154`).
   - `WorkflowRunsController.Resume` never reads the caller
     (`src/Daedalus.Api/Controllers/WorkflowRunsController.cs:120-142`).
   - Fix, task A3: `WorkflowResumeRequest.ResumedBy`, recorded as `WorkflowRun.LastResume`.
4. **`checked[]` is never persisted.**
   - `ReviewLensRunner` reads each lens's evidence off the turn's tool calls and returns only the
     last pass's turn (`src/Daedalus.Agents/Workflow/ReviewLensRunner.cs`, `RunLensesAsync`). The
     evidence is not a run variable.
   - A run variable would be node-writable anyway, and phase 2.4's ruling C1 forbids letting one
     carry facts a later step trusts.
   - Fix, tasks B6 and B8: a host-written, append-only `WorkflowRunRecords` table.
5. **The separate `AGENT.md` commit is impossible through today's Thalos.Git.**
   - `LibGit2SharpGitWriteService.CommitCore` always runs `Commands.Stage(repo, "*")`
     (`src/Thalos.NET.Git.LibGit2Sharp/LibGit2SharpGitWriteService.cs:93`).
   - Fix, task A7: a path-scoped commit.
6. **The spec's PR-idempotency risk applies.** `IPullRequestPublisher` has no lookup
   (`src/Thalos.NET.Git/IPullRequestPublisher.cs:44`). Fix, tasks A7 and B12:
   `FindOpenPullRequestAsync`.
7. **"lastError names the path" cannot come from the `failed` branch.**
   - A branch to `terminal: failed` never sets `last_error`. Only `FailAsync` and `CancelAsync`
     write it (`OrmWorkflowStore.cs:402-470`).
   - Fix, task B13: a push or PR failure returns a failed `Result`, which the dispatcher records with
     `FailAsync`, naming the kept worktree path.
   - An empty diff is the `failed` outcome, as the spec says.
8. **The implementer could edit `AGENT.md` directly with `workspace__write_file`,** bypassing the
   gate and the separate commit.
   - Fix, tasks A8 and B9: `RunWorkspaceToolOptions.ProtectedPaths`. It refuses writes to the
     configured standing-instructions path; reads are still allowed.
9. **The PR body's work intent must not come from a variable.**
   - `work_intent` is a run variable, and any node can overwrite it through its outcome tool.
   - Fix, task B3: pin it as manifest document `work_intent`. B13 reads it from there.
   - The same C1 reasoning makes `summary` implement-authored only (task B14).
10. **Per-node usage for `review` would undercount.** `ReviewLensRunner` returns only the last lens
    pass's turn. Fix, task B15: sum the usage of all passes.
11. **Recalled memories sit inside the system prompt.**
    - `MemoryContextProvider` returns `new AIContext { Instructions = block }`
      (`src/Thalos.NET.Memory/MemoryContextProvider.cs:79`).
    - That puts per-turn content ahead of the stable prefix. Fix, task A21.
12. **At the shipped budget, `implement` cannot finish.**
    - `DetachedRuns:MaxTotalTokens` is 150,000 (`src/Daedalus.Api/appsettings.json:44`). The two
      measured implement turns used 358,703 and 737,634 input tokens.
    - The live proof raises the ceiling with a temporary AppHost line. See the graph walk in B17.

## Global Constraints

- **Thalos.NET must never reference Daedalus.** Generic mechanisms go in Thalos; content, hosting and
  policy stay in Daedalus. Direction recorded 2026-09-21.
- **Thalos checkout:** Part A's first step switches to `main`, fast-forwards it, and creates
  `feat/phase-2.5-run-workspaces` (task A1, step 1).
- **`ZeroAlloc.Results`:**
  - Qualify the generic type: `Result<T>.Success(v)`, `Result<T, AgentError>.Failure(e)`, never
    inferred.
  - Combinators need `using ZeroAlloc.Results.Extensions;`.
  - Workflow code uses `Result` or `Result<T>` with string errors; tools, git and agents use
    `Result<T, AgentError>` and `UnitResult<AgentError>`. Follow the file you are in.
- **Forbidden:**
  - `Task.Wait()`, `.Result` and `.GetAwaiter().GetResult()`.
  - `async void`.
  - Throwing for expected failures.
  - `Task.Run` to fake async. The existing `LibGit2SharpGitWriteService.RunAsync` wrapper stays as
    it is.
  - Existing `ArgumentException` guards stay.
- **Code conventions:**
  - Use `[LoggerMessage]` source-generated logging.
  - Use primary constructors for DI, never mixed with a second constructor.
  - One public type per file.
- **Central package management.** Versions live only in `Directory.Packages.props`. The Thalos
  family moves together (Daedalus `Directory.Packages.props:55-70`).
- **Per-assertion falsifiability.**
  - Every assertion below names its red-making change.
  - The implementer **makes that change, watches that exact assertion fail, reverts it**, and records
    the red in the task report.
  - Seed stores before filtering them; an empty store passes any filter.
  - Boundary tests build the host from the **shipped** `appsettings.json` and reach the caller
    through the **real** `resolveCaller`. They never use hand-built principals or hand-built
    definitions.
- **Run every suite that builds what you touched.** Phase 2.4 missed `Daedalus.Tests.Unit.Application`,
  and that suite hid two regressions.
  - **Thalos:** a task that touches `Thalos.NET.Abstractions`, `Thalos.NET`, `Thalos.NET.Memory`,

- **Test style:**
  - xUnit `[Fact]`, AwesomeAssertions `.Should()`, `CancellationToken.None`.
  - Method names are sentences with underscores.
  - Docker-backed Thalos tests use `[Collection(PostgresCollection.Name)] [Trait("Category",
    "Docker")]`.
- **Commits:**
  - Conventional Commits, with the header at most 100 characters (`.commitlintrc.yml`).
  - Use `!` plus a `BREAKING CHANGE:` footer for a breaking Thalos API or behaviour change.
  - **No nested parentheses in bodies.** Write `typeof IFoo`, not `(typeof(IFoo))`.
  - No `claude.ai/code/session_*` URLs.
  - Implementer commits end with `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`,
    following ruling A3 in the 2.4 rulings.
- **Formatting.** Run `dotnet format` on touched projects before committing. Do not reformat files
  you did not touch.

**`CreateAsync` sequence.** All git calls go through `GitCli.RunAsync(workingDirectory, args,
extraConfig, ct)`: a `Process` with `ArgumentList`, awaited with `WaitForExitAsync`, and killed on
timeout. It returns `(ExitCode, StdOut, StdErr)`.

1. Take a per-repository `SemaphoreSlim` from a `ConcurrentDictionary<string, SemaphoreSlim>`.
2. If `<DataRoot>/mirrors/<repo>` does not exist, run
   `git clone --bare <Remote> <mirror>`, then
   `git -C <mirror> config remote.origin.fetch +refs/heads/*:refs/remotes/origin/*`.
3. Run `git -C <mirror> fetch origin --prune`.
4. Run `git -C <mirror> worktree add -b <Branch> <DataRoot>/runs/<runId> origin/<DefaultBranch>`.
5. Write the sidecar JSON: the request, plus `Root` and `SolutionPath`. `SolutionPath` is
   `WorkspacePath.Resolve(root, Solution)` when `Solution` is set; if that fails, the create fails
   and the worktree is removed.
6. Call every observer's `OnReadyAsync`. An observer that throws is logged and does not fail the
   create.
7. Return the workspace.

```csharp
    public ValueTask OnRemovingAsync(RunWorkspace workspace, CancellationToken ct); // disposes that run's clients
    public void OnFilesChanged(Guid runId, IReadOnlyList<string> relativePaths);    // marks the run dirty
    public ValueTask<UnitResult<AgentError>> WaitAllReadyAsync(Guid runId, TimeSpan timeout, CancellationToken ct);
    /// The ready client for (server, run); applies a pending reload first. Fails, never falls back, when the run
    /// has no ready server — the caller must not reach the host server instead.
```

**Key logic:**
- Each `(server, runId)` gets an `Entry` holding a `Task<Result<McpClient, AgentError>> Starting`, a

- `OnReadyAsync` assigns `Starting = StartAsync(...)` and keeps the task. It is observed by
  `WaitAllReadyAsync`, so nothing is fire-and-forget.
- `StartAsync` builds a `StdioClientTransport` from the host definition, with `RunScoped` overriding
  `Args`, `Env` and `Cwd` after substitution. It then calls `McpClient.CreateAsync` and
  `ListToolsAsync`, and polls `ReadyTool` when one is set.
- Substituting `${run.workspace.solution}` when `SolutionPath` is null fails the start, with
  `"run workspace has no solution"`.
- A reload happens under the entry's semaphore:
  - `tool:<name>` calls that tool;
  - `restart` disposes the client and starts again;
  - after either one, `Dirty` is set to false.

```csharp
// TurnScope — internal state, set by Begin
internal static TurnScope Begin(SessionId sessionId, TurnId turnId, ISecurityContext caller, AgentId agentId = default, int? maxTotalTokens = null);
internal int? MaxTotalTokens { get; }
internal int NextRoundTrip() => Interlocked.Increment(ref _roundTrips);
internal long TokensSoFar => Interlocked.Read(ref _tokens);
internal void AddTokens(long n) => Interlocked.Add(ref _tokens, n);

// AgentError
public static AgentError SubagentBudgetExceeded(int maxTokens, int roundTrip, long tokensSoFar) =>
    new(AgentErrorCode.SubagentBudgetExceeded,
        $"Stopped before model round trip {roundTrip}: {tokensSoFar} tokens used of a budget of {maxTokens}.");

/// Directly over the provider's client, below every decorator, so MAF's function-invocation loop passes through it on
/// every round trip. Counts input plus output tokens per round trip into the ambient TurnScope; before each call,
/// throws AgentTurnException when the count is already at or above the ceiling. The runtime's MapException turns
/// that into the turn's error. A call already made is never cancelled.
internal sealed class TurnBudgetChatClient(IChatClient inner) : DelegatingChatClient(inner)
{
    public override async Task<ChatResponse> GetResponseAsync(IEnumerable<ChatMessage> messages, ChatOptions? options = null, CancellationToken ct = default)
    {
        var scope = Check();
        var response = await base.GetResponseAsync(messages, options, ct).ConfigureAwait(false);
        scope?.AddTokens((response.Usage?.InputTokenCount ?? 0) + (response.Usage?.OutputTokenCount ?? 0));
        return response;
    }

    public override async IAsyncEnumerable<ChatResponseUpdate> GetStreamingResponseAsync(IEnumerable<ChatMessage> messages, ChatOptions? options = null, [EnumeratorCancellation] CancellationToken ct = default)
    {
        var scope = Check();
        await foreach (var update in base.GetStreamingResponseAsync(messages, options, ct).ConfigureAwait(false))
        {
            foreach (var content in update.Contents)
                if (content is UsageContent uc) scope?.AddTokens((uc.Details.InputTokenCount ?? 0) + (uc.Details.OutputTokenCount ?? 0));
            yield return update;
        }
    }

    private static TurnScope? Check()
    {
        var scope = TurnScope.Current;
        if (scope?.MaxTotalTokens is not { } max) return scope;
        var trip = scope.NextRoundTrip();
        var used = scope.TokensSoFar;
        return used >= max ? throw new AgentTurnException(AgentError.SubagentBudgetExceeded(max, trip, used)) : scope;
    }
}
```

```csharp
internal sealed partial class OpenPullRequestAction(
    IRunWorkspaceProvider workspaces, IGitWriteService git, IServiceScopeFactory scopes, WorkflowConfig config,
    IGitCredentialSource credentials, ILogger<OpenPullRequestAction> logger) : IWorkflowHostAction
{
    public const string ActionName = "open-pull-request";
    public string Name => ActionName;

    public async ValueTask<Result<HostActionResult>> RunAsync(WorkflowRun run, ProcessNode node, CancellationToken ct)
    {
        if (await workspaces.FindAsync(run.Id, ct) is not { } ws)
            return Result<HostActionResult>.Failure($"run '{run.Id}' has no workspace to publish from.");
        var author = new GitAuthor(config.CommitAuthor.Name, config.CommitAuthor.Email);
        var agentMd = config.StandingInstructionsPath;

        // 1. Commit. Each call is a no-op when nothing is staged, so a redelivery commits nothing twice.
        var code = await git.CommitAsync(ws.Root, new GitCommitRequest { Message = CodeCommitMessage(run), Author = author, ExcludePaths = [agentMd] }, ct);
        if (code.IsFailure) return Failed($"commit failed: {code.Error.Message}", ws);
        var standing = await git.CommitAsync(ws.Root, new GitCommitRequest { Message = "docs: apply the approved standing instructions change", Author = author, Paths = [agentMd] }, ct);
        if (standing.IsFailure) return Failed($"AGENT.md commit failed: {standing.Error.Message}", ws);

        var stat = await git.DiffStatAsync(ws.Root, ws.BaseRef, ct);
        if (stat.IsFailure) return Failed($"diff failed: {stat.Error.Message}", ws);
        if (stat.Value.Count == 0)
            return Result<HostActionResult>.Success(new HostActionResult("failed", new Dictionary<string, object?> { ["publish_error"] = "nothing to publish" }));

        // 2. Push. Only this run's own branch, only to this run's own allow-listed remote.
        var push = await git.PushAsync(ws.Root, "origin", credentials.GetCredentials(ws.Remote), ct);
        if (push.IsFailure) return Failed($"push failed: {push.Error.Message}", ws);

        // 3. Open, or reuse, the pull request.
        await using var scope = scopes.CreateAsyncScope();
        var publisher = scope.ServiceProvider.GetRequiredService<IPullRequestPublisher>();
        var existing = await publisher.FindOpenPullRequestAsync(ws.Root, ws.Branch, ct);
        if (existing.IsFailure) return Failed($"pull request lookup failed: {existing.Error.Message}", ws);
        var pr = existing.Value;
        if (pr is null)
        {
            var body = PullRequestBody.Render(await FactsAsync(run, ws, stat.Value, scope, ct));
            var opened = await publisher.OpenPullRequestAsync(ws.Root, ws.Branch, ws.DefaultBranch, Title(run), body, ct);
            if (opened.IsFailure) return Failed($"opening the pull request failed: {opened.Error.Message}", ws);
            pr = opened.Value;
        }

        var removed = await workspaces.RemoveAsync(run.Id, ct);   // after a successful push and PR; a failure is only logged
        if (removed.IsFailure) LogRemoveFailed(logger, run.Id, removed.Error.Message);
        return Result<HostActionResult>.Success(new HostActionResult("published", new Dictionary<string, object?> { ["pr_url"] = pr.Url }));
    }

    private static Result<HostActionResult> Failed(string what, RunWorkspace ws) =>
        Result<HostActionResult>.Failure($"{what}; the worktree is kept at {ws.Root}");
}
```
