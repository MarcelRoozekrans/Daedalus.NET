# Phase 2.3 — The Manufacturing Squad: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Staff the manufacturing pipeline with an implementer and an independent reviewer whose
approvals carry evidence, and give each role memory that accumulates across runs without leaking
into the other.

**Architecture:** Two repositories. `Thalos.NET.Memory` gains the ability to separate a caller's
*memory owner* from its *authorization identity*, and a recall path that degrades instead of
returning silence. Daedalus consumes both, adds two agents, rewires the handoff contract so the
reviewer reads the artifact rather than the implementer's narrative, and runs review as three
sequential lenses that short-circuit on rejection.

**Tech Stack:** .NET 10 / C# 13, Thalos.NET 0.8.0, `ZeroAlloc.Results`, EF Core 10 + PostgreSQL,
Rag.NET memory index, xUnit + FluentAssertions.

**Spec:** `docs/plans/2026-09-23-phase-2.3-manufacturing-squad-design.md`

## Global Constraints

- **Thalos.NET must never reference Daedalus.** Generic agent capability lands in Thalos; Daedalus
  keeps its domain, hosting and orchestration. Direction recorded 2026-09-21.
- **`ZeroAlloc.Results`:** qualify generics — `Result<T>.Success(v)`, never inferred. Combinators
  are extension methods; `using ZeroAlloc.Results.Extensions;` is required. `Ensure` exists only on
  `Result<T,E>`.
- **No `Task.Wait()` / `.Result` / `.GetAwaiter().GetResult()`. No `async void`. No throwing for
  expected failures — use `Result<T>`. No `Task.Run` to fake async.**
- **`[LoggerMessage]` source-generated logging** in anything performance-sensitive.
- **Primary constructors for DI**; never mix with a second traditional constructor.
- **Central package management** — versions go in `Directory.Packages.props` only; `PackageReference`
  carries no `Version` attribute.
- **Per-assertion falsifiability.** For every assertion, name the code change that turns it red and
  **verify red by making that change**. Phase 1.7 found eight tests that passed for the wrong reason;
  2.2 Part B shipped four fixes with no guard at all.
- **Commit bodies: no nested parentheses**, no `claude.ai/code/session_*` URLs. release-please
  silently drops a commit with a nested paren and still reports success.
- **`dotnet format`** before committing. Note `main` is not format-clean — roughly 130 pre-existing
  files. Confirm your changes are clean; do not sweep unrelated files.
- **Never run the test suite in the background.** Foreground, and report real numbers.

### Task 1: Separate the memory owner from the authorization identity

**Files:**
- Create: `src/Thalos.NET.Memory/IMemoryOwner.cs`
- Modify: `src/Thalos.NET.Memory/MemoryTools.cs`
- Test: `tests/Thalos.NET.Memory.Tests/MemoryOwnerTests.cs`

**Interfaces:**
- Produces: `public interface IMemoryOwner { string MemoryOwnerId { get; } }` — consumed by Task 4.

**Why:** `MemoryRecord.OwnerId` is documented as "security-context id of the owner … never set from
tool parameters". A caller whose `ISecurityContext.Id` varies per run therefore writes into an owner
partition no later run can read. Daedalus's `WorkflowCaller.Id` is `workflow:{process}:{runId}`, so
per-role learning cannot accumulate. That id must stay per-run — it is the authorization identity —
so the memory owner needs its own channel.

```csharp
    stored.Value.Should().ContainSingle("the memory must land under the stable owner, otherwise the next run reads a different partition and cannot see it");
}
```

```csharp
namespace Thalos.Memory;

/// <summary>
///     Implemented by an <see cref="ISecurityContext"/> whose memory should be stored under an id other than
///     <see cref="ISecurityContext.Id"/>. Exists for callers whose authorization identity is deliberately
///     short-lived — a workflow run identifies itself per run so it stays auditable, but its memory must
///     outlive the run or nothing it learns is ever readable again.
/// </summary>
public interface IMemoryOwner
{
    /// <summary>Stable owner id for this caller's memories. Must be non-blank and must not be an anonymous id.</summary>
    string MemoryOwnerId { get; }
}
```

- [ ] **Step 4: Resolve it in `MemoryTools`**

```csharp
private string ResolveOwnerId(ISecurityContext caller) =>

        ? owner.MemoryOwnerId
        : caller.Id;
```

Apply it to the write path **and** the scope construction, so a caller reads the same partition it
writes. A fix applied to only one side is worse than none: the caller would write where it cannot
read.

### Task 2: Recall degrades instead of returning silence

**Files:**
- Create: `src/Thalos.NET.Memory/MemoryRecallTier.cs`
- Modify: `src/Thalos.NET.Memory/MemoryService.cs`, `src/Thalos.NET.Memory/MemoryTools.cs`
- Test: `tests/Thalos.NET.Memory.Tests/RecallTierTests.cs`

**Interfaces:**
- Consumes: nothing from Task 1.
- Produces: `public enum MemoryRecallTier { Semantic, Recency, None }`, and a `Tier` on the recall
  result — consumed by Daedalus for the turn record.

**Why:** Phase 2.2 observed every memory row stuck at `IndexPending = true` for a run's lifetime, so
semantic recall searched nothing and returned empty. The agent read that as "nothing to know" and
proceeded. Silence and knowledge were indistinguishable.

- [ ] **Step 1: Write the failing test**

```csharp

    await SeedAsync(owner: "o1", texts: ["older fact", "newer fact"]);

    var result = await service.RecallAsync(Scope("o1"), "anything", topK: 5, CancellationToken.None);

    result.Value.Tier.Should().Be(MemoryRecallTier.Recency,
        "an unavailable index must degrade, not return empty - 2.2 proved an empty recall is read as 'nothing to know'");
    result.Value.Records.Should().NotBeEmpty("the rows exist in the store regardless of whether they are embedded");
}
```

- [ ] **Step 2: Run it — expect FAIL** (no `Tier` member).

- [ ] **Step 3: Add the tier enum**

```csharp
namespace Thalos.Memory;

/// <summary>Which source answered a recall. Recorded so "the agent knew nothing" is visible rather than inferred.</summary>
public enum MemoryRecallTier
{
    /// <summary>Semantic search over the index.</summary>
    Semantic,

    /// <summary>Index unavailable or empty-handed: most recent in-scope rows, straight from the store.</summary>
    Recency,

    /// <summary>No rows in scope at all.</summary>
    None,
}
```

- [ ] **Step 4: Implement the fallback in `MemoryService.RecallAsync`**

Order: attempt semantic. If the index probe says unavailable **or** the search returns zero hits,
list the scope's partitions ordered by `UpdatedAt` descending, apply the same `TopK`/`MaxChars`
budget, and return `Tier.Recency`. Zero rows in scope returns `Tier.None` with an empty set.

Do **not** treat an index failure as a recall failure — that is the behaviour being replaced.

- [ ] **Step 5: Run — expect PASS**

- [ ] **Step 6: Add the semantic-still-wins guard**

```csharp
    result.Value.Tier.Should().Be(MemoryRecallTier.Semantic,
```
