# Phase 2.6 — Sandboxed Run Pods: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** An agent-written file can never execute on the API host.

- **Where a run lives.** Each manufacture run's worktree, its `workspace__*` tools, its Roslyn server
  and two new tools, `sandbox__build` and `sandbox__test`, live in a per-run Docker container. The
  container holds no secrets and can reach no network except NuGet.
- **What comes back.** The trusted API side publishes from a patch the sandbox exports. Before it
  applies the patch, it refuses any change to a protected path.
- **What this unlocks.** Once confinement holds, the write extension allow-list relaxes for sandboxed
  grants.

**Architecture:** There are two repositories, plus one security patch that ships first.

- **Part 0: Thalos.NET 0.12.1.** It stops every stdio MCP child from inheriting the host's environment.
- **Part A: Thalos.NET 0.13.0.** It adds the following:
  - prefix-capable protected paths, and an "any extension" ceiling;
  - a start point on workspace requests;
  - a public mirror store that fetches, bundles, reads files and applies patches;
  - the sandbox abstractions, plus three new packages: `Thalos.NET.Sandbox`, `Thalos.NET.Sandbox.Docker`
    and `Thalos.NET.Sandbox.Host`;
  - a run tool source that routes run callers to the run's remote MCP endpoint;
  - a sandbox-backed `IRunWorkspaceProvider` that parks a run at the gate, by exporting its patch and
    deleting its container, and hands a clean host worktree to publish.
- **Part B: Daedalus.** It adds:
  - the sandbox image, the gateway and egress configuration, and the AppHost wiring;
  - config and validation;
  - the starter, writer and publish changes;
  - test-result evidence;
  - process v7 and its skills;
  - the replaced allow-list tests;
  - an owner-checkpoint live proof on `daedalus-sandbox`.

**Tech Stack:**

- .NET 10 / C# 13, Thalos.NET 0.12.0 → 0.12.1 → 0.13.0.
- `ModelContextProtocol` 2.2.0, plus `ModelContextProtocol.AspNetCore` 2.2.0 (new).
- A Docker Engine API client. Spike SP decides between `Docker.DotNet.Enhanced`, which Testcontainers
  4.x already brings in, and the raw REST API.
- Testcontainers 4.14/4.15, the `git` CLI ≥ 2.32, `nginx` (gateway), `squid` (egress), Aspire 13.4.6.
- xUnit 2.9.3, AwesomeAssertions 9.6.0, NSubstitute.

**Spec:** `docs/superpowers/specs/2026-10-01-phase-2.6-sandboxed-run-pods-design.md`, approved by the
owner on 2026-10-01. Where this plan departs from it, the reason is under **Pre-plan findings**. Each
departure came from reading the code; none adds scope.

## Pre-plan findings

Settled by reading both repositories before any task was written. Every one of these shapes the tasks
that follow it.

### F1. Environment inheritance is real today, so Part 0 ships before the phase

`StdioClientTransportOptions.InheritEnvironmentVariables` defaults to `true` in ModelContextProtocol
2.2.0. Its own XML doc warns that `GITHUB_TOKEN` "will automatically flow into the server process".

Thalos never sets the option, at `McpToolSource.cs:121-129` or at `RunMcpServerRegistry.cs:744-753`.
So every stdio MCP child Daedalus starts receives `GITHUB_TOKEN`, `ANTHROPIC_API_KEY`, the Telegram
token and the database connection string. That includes the run-scoped RoslynCodeLens, which evaluates
repository MSBuild.

Today the `.cs`/`.md` allow-list stops an agent from planting a build file. A build file *already in* an
allow-listed repository would get every secret on first load.

**Fix:** `InheritEnvironmentVariables = false`. Seed the environment from the SDK's
`GetDefaultEnvironmentVariables()` allow-list, then layer the definition's `env`. Add an explicit
`passEnvironment` list for anything else a server needs from the host. This is a behaviour change, so it
is released on its own as 0.12.1 (Part 0) and adopted by Daedalus in its own PR. The rest of the phase
does not wait on it.

### F2. A run's tool schemas cannot come from the run's own server (spec §1 item 5 corrected)

Tools are resolved once per agent build and cached per `(AgentId, Revision)`
(`Thalos.NET/src/Thalos.NET/Runtime/AgentFactory.cs:87`, `:202`, `:235`). This happens before any run
exists. `RunScopedMcpToolSource.GetToolsAsync` takes its schemas from the host-wide `McpToolSource`
(`RunScopedMcpToolSource.cs:66`) for the same reason.

**Design:**

- **Roslyn.** The remote route keeps taking its schemas from the host Roslyn server, which keeps
  running on the host for the Architect and the scout. The sandbox image pins the same RoslynCodeLens
  version as `.mcp.json`. A Daedalus test asserts the two pins are equal (B2), so the schemas cannot
  drift.
- **`workspace__*` and `sandbox__*`.** Their schemas come from their own tool types, which are compiled
  into both the API and the sandbox host. They cannot drift either.

The hard-coded `C:/Projects/Prive/daedalus/Daedalus.sln` host path stays the host server's concern. A
missing path fails only that host server's start, the same as today.

### F3. The way out is a patch, not a bundle (spec §Run lifecycle corrected)

The spec has the sandbox export a bundle of its branch. But the sandbox never commits:
`OpenPullRequestAction` makes two commits on the trusted side, the code and then `AGENT.md`, with the
configured author and a message built from the work intent (`OpenPullRequestAction.cs:128-153`).
`tests/Daedalus.Tests.Integration/Workflow/OpenPullRequestActionTests.cs:137` pins that message.

A bundle would force the sandbox to commit, so the authorship and the message would move into the
sandbox. The design:

1. **The sandbox exports a patch.** It runs `git add -A`, then
   `git diff --cached --binary --full-index <base>`.
2. **The API checks the patch before applying it.** It lists the patch's paths, including both sides of
   a rename, with `git apply --numstat -z --summary`, and refuses any protected path.
3. **The API applies the patch.** It runs `git apply --index --binary` into a clean host worktree cut at
   the run's recorded base commit.
4. **The API checks again.** It re-checks the staged names with `git diff --cached --name-only -z`.
5. **Publish continues unchanged** from that point.

Bundles still carry code *in*, as the spec says. `git apply` writes regular files only, because the
worktree has `core.symlinks=false`, and it refuses `..` paths itself.

### F4. `ProtectedPaths` is exact-match only

`WorkspaceTools.IsProtected` (`WorkspaceTools.cs:897-913`) compares the whole relative path,
case-insensitively. So `.github/` would protect nothing. Task A1 adds a shared `ProtectedPathSet`:

- an entry ending in `/` is a directory prefix;
- any other entry is an exact file.

The sandbox host, the patch guard and `WorkspaceTools` all use it.

### F5. The run-scoped registry stays as it is; remote routing is a new tool source

`RunMcpServerRegistry` hard-codes stdio (`:591`, `Validate` at `:1049`), Windows process-tree cleanup
(`:919-970`) and a per-run process lifecycle. Bending it to HTTP would mix two lifecycles in one 1247-line
class. Instead:

- **On the API side**, a new `RemoteRunToolSource` in `Thalos.NET.Mcp` routes as follows:
  - a caller with no run claim goes to the host source, when there is one;
  - a caller with a run claim goes to the run's endpoint, which `IRunToolEndpointResolver` returns, over
    `HttpClientTransport` with Streamable HTTP and a bearer header.

  It reuses `RunScopedMcpToolSource`'s timeout and error shapes.
- **Inside the sandbox**, the host uses the existing registry unchanged, over stdio. That gives a local
  RoslynCodeLens with `reload: tool:rebuild_solution`.
- **Reload.** The sandbox's own `WorkspaceTools` call `OnFilesChanged` on the sandbox's registry, so
  reload stays where the files are. The API side never reloads anything.

### F6. Where a run's files are read today, and what replaces each read

Five consumers use `RunWorkspace.Root` as a host path. Each one is changed:

| Consumer | Today | Phase 2.6 |
|---|---|---|
| `WorkspaceTools` | runs in the API | runs in the sandbox host; on the API the same type only supplies schemas |
| `ManufactureRunStarter.ReadStandingInstructionsAsync` (`:210-222`) | `File.ReadAllText` in the worktree | `IRunBaseFileReader.ReadBaseFileAsync`; for the sandbox this is `git show <base>:<path>` against the mirror |
| `StandingInstructionsWriter.ApplyAsync` (`:105-111`) | writes into the worktree | writes into `IRunWorkspaceHandoff.CheckoutForPublishAsync`'s clean host worktree |
| `OpenPullRequestAction` (`:78`, `:193`, `:312`) | `FindAsync`, then commits in `ws.Root` | `CheckoutForPublishAsync`, then commits in that worktree |
| `ThalosPullRequestPublisher` | reads `origin` from the mirror's shared config | unchanged. Analysis below. |

**On the publisher's `origin`.** The publisher reads `origin` from the shared mirror, which an earlier
review flagged as surprising. It is consistent in practice, for three reasons:
- Every create retargets the repository's single mirror to that repository's *configured* remote.
- `OpenPullRequestAction` refuses unless the configured remote still equals `ws.Remote`
  (`OpenPullRequestAction.cs:109`).
- The publish worktree (A11) is created from that same mirror immediately before publish.

So `origin` is `ws.Remote` whenever publish gets past its own guard. Making it explicit would mean
changing `IPullRequestPublisher.OpenPullRequestAsync`, which is a Thalos signature, for no behaviour
change. It is dropped as not worth a breaking change.

The git provider implements both new interfaces trivially: it reads its own worktree, and its handoff
is `FindAsync`. That keeps a Docker-less mode, `Thalos:Workflow:Sandbox:Enabled=false`, for development
and for most tests.

### F7. When a run is parked: the sweeper, plus on demand

Thalos has a dispatch gate before task nodes (`IWorkflowDispatchGate`) but no hook for "the run reached
an await". So parking happens two ways:

- **On each sweep.** The one-minute `RunWorkspaceSweeper` tick parks every sandboxed run that is not
  `Running`, through a new optional `IParkableRunWorkspaceProvider`.
- **On demand.** `CheckoutForPublishAsync` parks first when a resume beats the tick.

Parking is idempotent.

### F8. Docker networking under Aspire needs a gateway

A container attached only to an `--internal` network has no published ports. A host-project API under
Aspire therefore cannot reach it directly.

**Default design, confirmed or overturned by spike SP:**

- **A gateway.** An `nginx` container on both the internal network and the default bridge publishes one
  loopback port. It reverse-proxies `/sandboxes/<id>/...` to `thalos-sandbox-<id>:8080` through
  Docker's embedded DNS. The id is constrained by a strict regex.
- **An egress proxy.** A `squid` container on both networks allow-lists the NuGet hosts.
- **Who owns them.** `DockerSandboxRuntime` owns the network and both containers. It creates or adopts
  them on first use, labels them, and pins the image digests. Aspire never manages them, so Thalos
  integration tests and any non-Aspire deployment get the same infrastructure.

### F9. Release mechanics for three new packages

Release-please needs no change: there is one version for every package (`release-please-config.json`).
CI's `pack-validate` job (`Thalos.NET/.github/workflows/ci.yml:172-213`) hard-codes the package list
and the count. Task A13 changes:

- the `expected=` list, from 15 to 18 packages;
- both count checks;
- `Thalos.NET.slnx`;
- `docs/release.md`;
- and gives each new package its own `<Description>`.

## Global Constraints

Every task's requirements implicitly include all of these.

**Repository and code style**
- Daedalus follows its `CLAUDE.md`:

  - Never throw for an expected failure.
  - Package versions live only in `Directory.Packages.props`.
- Thalos follows the same rules. Its interfaces return `Result<T, AgentError>` and `UnitResult<AgentError>`.
- Run `dotnet format` on touched files before every commit. Repo-wide drift is tracked in #295/#312,
  so do not reformat files you did not touch.

**Commits**
- Use conventional commits with a header of at most 100 characters.
- No nested parentheses in a commit body.
- No `claude.ai/code/session_*` URL anywhere.
- End every commit with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**Tests: falsifiability**
- Every assertion must have a named change that turns it red. Write that change in the test's doc
  comment as `Red: <change>`.
- Security assertions (S1–S6 below) are verified red once during their task's review, by actually
  making the change.

**Security invariants.** Each has a test that guards it.
- **S1:** A sandbox container's environment holds only the keys `SandboxSpec` lists. It never inherits
  the API's environment.
- **S2:** A sandbox reaches no host except through the egress proxy, and the proxy allows only
  `api.nuget.org`, `*.nuget.org` and `globalcdn.nuget.org`.
- **S3:** MSBuild in a sandbox runs only inside that container. The spike's vector 1 marker appears in
  the container and never on the host.
- **S4:** The API never evaluates MSBuild, runs restore, or checks out a tree a sandboxed process
  touched. It applies a patch into its own clean worktree.
- **S5:** A change to a protected path fails publish. The publish-side check is the control; the
  sandbox-side refusal is only a convenience.
- **S6:** A grant with no extension list is refused at boot unless `Thalos:Workflow:Sandbox:Enabled` is
  true.

**Shipped defaults**
- **Protected paths:** `.git/`, `AGENT.md`, `.gitattributes`, `.gitmodules`, `.github/`,
  `.gitlab-ci.yml`, `azure-pipelines.yml`, `.azure-pipelines/`, `.circleci/`, `Jenkinsfile`. `AGENT.md`
  means the configured `StandingInstructionsPath`.
- **RoslynCodeLens** stays at 2.18.1.

```csharp
    /// stdio only: names of host environment variables passed through to the child. A stdio server does not inherit the
    /// host's environment: it starts from ModelContextProtocol's curated defaults
    /// (<c>StdioClientTransportOptions.GetDefaultEnvironmentVariables()</c>: PATH, HOME/USERPROFILE, TEMP and the like),
```

```csharp
using ModelContextProtocol.Client;

namespace Thalos.Mcp;

/// <summary>
/// The environment a stdio MCP child starts with: the SDK's curated defaults, then the definition's
/// <see cref="McpServerDefinition.PassEnvironment"/> names read from the host, then its <c>env</c>, then a run's
/// <c>runScoped.env</c>. Never the host's whole environment (Thalos 0.12.1).
/// </summary>
internal static class StdioEnvironment
{
    public static Dictionary<string, string?> Build(
        McpServerDefinition definition, IReadOnlyDictionary<string, string?>? overrides, Func<string, string?> getHost)
    {
        var env = new Dictionary<string, string?>(StdioClientTransportOptions.GetDefaultEnvironmentVariables(), StringComparer.Ordinal);
        foreach (var name in definition.PassEnvironment ?? [])
        {
            if (getHost(name) is { } value)
            {
                env[name] = value;
            }
        }

        foreach (var (key, value) in definition.Env ?? new Dictionary<string, string>(StringComparer.Ordinal))
        {
            env[key] = value;
        }

        foreach (var (key, value) in overrides ?? new Dictionary<string, string?>(StringComparer.Ordinal))
        {
            env[key] = value;
        }

        return env;
    }
}
```

```csharp
// src/Thalos.NET.Abstractions/Workspaces/ProtectedPathSet.cs
namespace Thalos.Workspaces;

/// <summary>
/// Repository-relative paths a run may read but never write. An entry ending in <c>/</c> protects that directory and
/// everything under it; any other entry protects exactly that file. Case-insensitive, with <c>\</c> read as <c>/</c>.
/// Shared by the <c>workspace__*</c> tools, the sandbox host, and the publish-side patch guard.
/// </summary>
public sealed class ProtectedPathSet
{
    private readonly string[] _directories;
    private readonly HashSet<string> _files;

    public ProtectedPathSet(IEnumerable<string> entries)
    {
        ArgumentNullException.ThrowIfNull(entries);
        var list = entries.Select(Normalize).Where(e => e.Length > 0).Distinct(StringComparer.OrdinalIgnoreCase).ToArray();
        Entries = list;
        _directories = [.. list.Where(e => e.EndsWith('/')).Select(e => e.TrimEnd('/'))];
        _files = new HashSet<string>(list.Where(e => !e.EndsWith('/')), StringComparer.OrdinalIgnoreCase);
    }

    /// <summary>The normalised entries; directories keep their trailing <c>/</c>.</summary>
    public IReadOnlyList<string> Entries { get; }

    public bool IsProtected(string relativePath)
    {
        var path = Normalize(relativePath).TrimEnd('/');
        if (_files.Contains(path))
        {
            return true;
        }

        foreach (var directory in _directories)
        {
            if (string.Equals(path, directory, StringComparison.OrdinalIgnoreCase)
                || path.StartsWith(directory + "/", StringComparison.OrdinalIgnoreCase))
            {
                return true;
            }
        }

        return false;
    }

    private static string Normalize(string path) =>
        (path ?? throw new ArgumentNullException(nameof(path))).Replace('\\', '/').TrimStart('/').Replace("//", "/", StringComparison.Ordinal);
}
```

**Modes.** `Thalos:Workflow:Sandbox:Enabled` selects one of two modes:

| Mode | When | What a run gets |
|---|---|---|
| **sandbox** | `true` | Docker sandboxes, remote `workspace__*`, `sandbox__*` and `roslyn__*`, and extension-less grants. Shipped as the API default from B3 on. |
| **local** | `false` | Today's git worktrees and in-process tools, with extension-listed grants only. |

Local mode stays for development without Docker and for the many integration tests that do not need a
container. `Daedalus.Cli` has the workflow engine off and stays in local mode.

`WriteExtensionCeilingOrAny` sits next to the existing `WriteExtensionCeiling` (`:642`):

```csharp
    /// <summary>
    /// The sandbox's host-wide write ceiling: null (any extension) when any grant lists no extensions, which S6 allows only
    /// with the sandbox enabled; otherwise the union of the grants' lists, as WriteExtensionCeiling computes it. Each grant
    /// still narrows its own caller through the write-extensions claim.
    /// </summary>
    internal static IReadOnlySet<string>? WriteExtensionCeilingOrAny(IEnumerable<WriteGrantConfig> grants)
    {
        var list = grants.ToList();
        return list.Any(g => g.AllowedExtensions is null) ? null : WriteExtensionCeiling(list);
    }
```
