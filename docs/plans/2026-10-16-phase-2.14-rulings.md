# Phase 2.14 Rulings: Flux across the Web app

**Spec:** `docs/superpowers/specs/2026-10-16-phase-2.14-flux-across-the-web-app-design.md`
**Impact analysis:** `docs/superpowers/specs/2026-10-16-phase-2.14-flux-impact-analysis.md`

**Pattern as built:** `docs/development-guide.md`, "Web state with ZeroAlloc.Flux"

The phase ran subagent-driven: each task had a fresh implementer and a fresh reviewer. The owner chose that method on
2026-10-16. Every decision taken on the owner's behalf is listed below with what it costs if it is wrong, so it can be
checked and reversed. Where a ruling changed what the spec, the impact analysis or the plan says, those documents carry
a "Superseded by ruling" note that points here; their text is otherwise left as it was approved.

## Rulings

### Characterization and pre-existing bugs (Task 1)

1. **Two pre-existing bugs found by the characterization tests were fixed in Task 1, each with its red test.**
   - R8: the PRD generator read the generate and convert answers case-sensitively, so the API's camelCase PRD bound
     nulls and the review step threw on `Prd.Goals` (7dde3b4).
   - Schedules: on a page opened without a deep link, the first expanded row collapsed again on the next render
     (410237a).

   The owner's rule is that bugs in touched code are fixed, not filed, and Tasks 7 and 8 moved that code later.
   *Cost if wrong:* two small behaviour fixes inside a refactor phase, named in the commits and the PR.
2. **The brainstorm persistence bug got a bounded root-cause check before anything was filed, and was then fixed in
   Task 1.** EF treated `BrainstormMessage`'s client-set Guid key as store-generated, so a new message on a stored
   session was saved as an UPDATE of no rows, and `BrainstormService` ignored the failure while the API answered 200.
   The key is now `ValueGeneratedNever`, with no schema change, and the service returns each failed save (4e8d743). The
   same latent pattern on `Task.Executions` and `Project.Tasks` is filed as #377, not fixed.
   *Cost if wrong:* an Infrastructure change in a Web phase.
3. **Small fix rounds were re-reviewed by the controller reading the diff, not by a fresh reviewer.** This was ruled
   for Task 1's 7-line test-only round 1, and the same check was used for the one-to-three-line rounds of Tasks 2, 3
   (round 2), 4 (round 2), 5 (round 2), 7 and 8. Each finding was visibly addressed in its diff.
   *Cost if wrong:* nothing, if a reviewer would have agreed.

### Shared projects (Tasks 3 and 4)

4. **A load's start clears the last error in the shared `ProjectsState`.** Another page's failure must not show under
   a picker that is reading the list again.
   *Cost if wrong:* an error hidden for the length of a re-fetch that would state it again.
5. **A component shows the spinner only for a load it started; a background refresh renders silently.** A reconnect's
   refresh showed the Projects spinner, which broke the no-visible-change constraint. The rule then applied to every
   feature a hub refresh or another page can reload, in Tasks 5 to 9.
   *Cost if wrong:* a local flag per reader.
6. **The spinner decision is one pure helper the components call, `ProjectsView`.** No component renderer exists in
   the test projects, and a hub reconnect cannot be driven from the browser suite, so the decision had to be testable
   without either.
   *Cost if wrong:* a small helper type.

### Home (Task 5)

7. **A background re-fetch that fails keeps the card's last rows silently and logs a warning.** A read that showed the
   skeleton, on open or Retry, still shows the card's error, as in 2.13. The first implementation showed an alert and
   stopped live updates until Retry.
   *Cost if wrong:* stale rows until the next run change, while the API is down.

### Writes (Task 6)

8. **Writes return their own outcome, and the component that asked shows it.** The spec and the plan had the outcome
   as state, `LastSaved` or `LastRefusal`. Read from a store by its kind, an outcome could be toasted again for another
   write of the same kind, by a component that had not made it. One rule now covers Repositories
   and Projects alike, and later Schedules, Brainstorm and Agent: an effect returns `ProjectSave`, `RepositorySave`,
   `ScheduleResend`, `BrainstormOutcome` or `AgentOutcome`, or `null` when the session is being renewed or the caller
   is gone.
   *Cost if wrong:* a small signature change in `ProjectsEffects`, which was Task 4's code.
9. **`LastSave` was removed once writes returned their outcome.** Dead state would have kept two rules alive.
   *Cost if wrong:* about 15 rewritten tests.

### Costs and Schedules (Task 7)

10. **Two visible deviations during session renewal were accepted.** For the 1.5 seconds of the "Signing in again"
    notice, the Schedules run-history row shows its spinner instead of "No runs yet.", and a Costs estimate is kept
    instead of cleared. The old text was false, and the page is leaving to sign in.
    *Cost if wrong:* a 1.5-second spinner.

### PRD Generator (Task 8)

11. **Four error-text changes on PRD failure paths were accepted as improvements.**
    - A refused generate and a refused convert show the API's error string instead of the raw error JSON.
    - A refusal whose body is not JSON reads `API error: <status>`.
    - A transport failure reads `API error: …`.
    - An empty success body is an error alert instead of a crash on the review step.

    *Cost if wrong:* wording the owner may want back.

### Agent (Task 9)

12. **When the session read races a turn, the stored history now comes before the turn.** If a turn is sent before
    the session's history read lands, the history is placed before that turn; the old page appended it after the new
    turn. This is a correction.
    *Cost if wrong:* the order of a transcript in that race.

### Closing work (Task 10, final review, sweep)

13. **Runs and Tasks, on Flux since phase 2.12, were brought under this phase's rules in Task 10b.** They no longer
    store a renewal failure, they log failures, they check cancellation before dispatching, and `ProjectApiClient`
    catches only expected failures. The spec's goal is one state approach on every page.
    *Cost if wrong:* one extra task's worth of churn in two older features.
14. **Two pre-existing layout and accessibility faults found by the sweep were fixed here, because this phase moved
    those pages.** The project dialogs name every field by its label, and the Agent and Brainstorm pages fit the column
    above the footer through one `page-fill` class instead of `calc(100vh - 80px)`.
    *Cost if wrong:* none expected; both are pinned by browser tests at three widths.
