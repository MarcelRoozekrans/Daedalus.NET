## The three things worth remembering

**1. The manufacture process cannot reach review in production, by construction.** The live proof
ran once, and this is what it established. The implementer can never write: `roslyn__apply_*` is
bound to the `developer` policy, and a workflow turn executes as `WorkflowCaller`, whose only role is
`workflow`. So for any real change its only honest outcome is `blocked`. Process v5 routes `blocked`
to `adjudicate`, which is `terminal: failed`. `review`, the three lenses, `checked[]`, `retrospect`
and the gate cannot be reached, for any work intent, at any budget. Phase 2.3's single live turn also
ended `blocked`. Both runs were read as a budget or credit problem, and the routing was the real
cause both times. It was caught before a second, 1,000,000-token run was spent to reproduce the same
`Failed`.

**2. The budget decorator is not a spend cap.** In the live run the implement turn completed:
35 messages, **737,634 input and 8,298 output tokens**. The implementer verified its conclusion with
tool calls and recorded `blocked` through the outcome tool. `BudgetedSubagentRunner` then failed the
node with `SubagentBudgetExceeded` at 600,000 and discarded that recorded outcome. The tokens were
spent in full; the check fired after the turn, not during it. What it bounds is what the graph
accepts, not what the provider bills. This is also the second measurement of an implement turn,
358,703 in 2.3 and 737,634 here, so turn size is not stable enough to size a ceiling from.

**3. One suite nobody ran hid two regressions.** No task brief ran `Daedalus.Tests.Unit.Application`.
At close-out it had two failures, both from this branch: B3's new `manufacture` tool source had made
an expected source list stale, and B5's `StandingInstructionsWriter` needs an `IHostEnvironment` that
a bare test `ServiceCollection` lacks. Every task review was clean, because each task's diff was
right; the break was in a suite outside every brief. Briefs should name every suite that builds the
project they touch, not just the one next to the new test.

## Carried forward

1. **How a run may write.** Decide this before any further live proof, because it is what makes the
   process reachable at all. The options on record are:
   - 2.2's Option C: host code calls the publisher after the graph and a human decide.
   - A scoped write policy that grants `workflow` a narrow `roslyn__apply_*`.
   - Routing `blocked` to `review`, so a reviewer judges the blocked report instead of the run failing.
2. **Budget semantics.** Either make the budget abort mid-turn, or rename it for what it does. Resize it
   only after item 1, because a turn that cannot write explores until it runs out.
3. **Token sizing.** This is still open. Two implement turns measured 358,703 and 737,634 input tokens.
   The roslyn tool schemas, skill catalogue and variable block all land in that prompt.
4. **Cost aggregation.** This is still open: agent-turn usage is not aggregated into cost analytics.
5. **Where `AGENT.md` lives.** `StandingInstructionsPath` resolves against the host content root, so a
   run pins, and on approval rewrites, Daedalus's own standing instructions, not the target
   repository's. The owner deferred this decision until after the proof, and the proof never reached
   the write, so it is still open.
6. **Thalos 0.10.0 release notes** list only one of four breaking changes. The owner decided on
   2026-09-24 to leave them as they are.
7. **Prompt caching, raised by the owner on 2026-09-24.** `Thalos.NET.Anthropic`'s
   `AnthropicChatClientProvider` wraps the SDK with a plain `AsIChatClient` and sets no
   `cache_control`, so every model call in an agent loop re-bills the same prefix at full price:
   system prompt, tool schemas, skill catalogue, then the growing history. The 737,634-token
   implement turn was about 17 such calls. Caching the stable prefix bills repeat reads at roughly a
   tenth of the input price. This is a Thalos change and a Thalos release. Decide at the same time
   whether cached reads count toward `MaxTotalTokens`. A response cache such as Microsoft.Extensions.AI's
   `UseDistributedCache` is not a substitute. Requests almost never repeat exactly, and a replayed
   response is not a live proof; it belongs in tests.
8. **The plan's budget override named a key that does not exist.** It named
   `Thalos__DetachedRuns__MaxTotalTokens`, but the key is `DetachedRuns:MaxTotalTokens`, and the
   AppHost forwards only the variables it names. See the ruling below.

## A note for the next run

A live proof is only worth its spend if the path it proves is reachable. Before any live run, walk the
process graph by hand from the start node to the gate, and for each edge ask what the agent can
actually do under the caller's roles. Here that walk takes two minutes, and it would have caught
item 1 of this phase's findings before any credits were spent in either 2.3 or 2.4.
