## Rulings

1. Task 3's live steps run in the controller, not a subagent; any config or test-constant change it implies is
   dispatched to an implementer and reviewed — it handles secrets, spends owner-approved money and drives a running
   stack, which a fresh subagent cannot do safely.
   *Cost if wrong:* Controller context grows during the live step.

2. TurnBudgetsConfig.Agents is a get-only IDictionary<string,int> instead of the plan's settable Dictionary — the repo
   analyzers MA0016 and CA2227 fail the build on the plan's shape, and it mirrors PinnedLensModels.
   *Cost if wrong:* None at runtime; later tasks use For(name).

3. The redelivery test lives in integration NodeUsageUniqueIndexTests, not a unit NodeUsageRecorderTests — the dedupe
   needs the real unique index and the unit file does not exist.
   *Cost if wrong:* None.

4. A failed turn with zero tokens is not recorded — it spent nothing, and a 0-token entry would inflate the entry
   count on /costs.
   *Cost if wrong:* An entry count lower by such failures.

5. A turn that completed but whose outcome the dispatcher then rejects stays unrecorded in this phase, filed as an
   issue in Task 5 — the runner sees a success and cannot know the dispatcher will fail the run; closing it needs
   usage on Thalos' failure path, which the owner kept out of scope.
   *Cost if wrong:* Such a node's spend stays missing from /costs.

6. Task 2's ordering assumption, publish before return, is proven against real Thalos by Task 3 live check (b), not by
   a unit test — the scripted runtime mirrors it by construction.
   *Cost if wrong:* Task 3 (b) fails and Task 2 reopens.

7. The remaining measurement runs use a temporary 2,000,000 ceiling for every agent, set in API user secrets and
   removed after — a stopped turn only says the need is above 990493, so sizing needs uncensored turns; the plan's
   no-raise line was about making runs pass, not about measuring.
   *Cost if wrong:* A few extra dollars of spend on larger turns.

8. The remaining measurement runs also use DetachedRuns:DeadlineSeconds 900 and Thalos:Workflow:Dispatch:LeaseDuration
   00:30:00 in API user secrets, removed after — run1's implement took 287 of 300 s, and a deadline cut-off censors
   durations the same way a ceiling censors tokens.
   *Cost if wrong:* None beyond the measurement.

9. The sandbox build fix goes in this branch as Task 3a, a reviewed task, with a guard test — the owner allowed this
   phase or a small PR before it, and the re-measure depends on it.
   *Cost if wrong:* A slightly wider phase diff.

10. The 600 s deadline needs Thalos:Workflow:Dispatch:LeaseDuration above 600 s + the 10-minute readiness wait, so 25
   minutes ships with it in Task 3b — WorkflowDispatchTiming.Validate requires the lease to exceed both.
   *Cost if wrong:* A stranded run is noticed 5 minutes later.

11. The re-measure runs clone this branch, not main, by setting the daedalus repository's DefaultBranch to
   phase/2.15-token-budget in API user secrets, after pushing the branch — the sandbox build fix lives on this branch
   until the phase merges.
   *Cost if wrong:* None, the branch is this phase's own.

12. TurnBudgetStampTests reading 2000000 is the controller's temporary measurement user secrets leaking into the
   Development-environment test host, not a defect in 3a or 3b; it is re-run after the secrets are removed in Task 3
   step 6.
   *Cost if wrong:* A real failure is noticed one step later.

13. The re-measure runs use a temporary 4,000,000 ceiling, up from 2,000,000, so turns that would have stopped at 2.1M
   show their full size — about two dollars per turn at most.
   *Cost if wrong:* A few dollars.

14. One more Daedalus.NET run, then stop measuring, keeping the total near $22 inside the owner's EUR 15-25.
   *Cost if wrong:* A thinner Daedalus.NET sample than the five runs planned.

15. Completed turns from the build-broken first batch, 609040 and 1122644, count in the sample, and the stopped turns
   are recorded but not sized from — they are real implement turns, and a stopped turn only gives a lower bound.
   *Cost if wrong:* The ceilings stop a real turn above 2.9M on a large repository.

16. Live check (b) is met by run 376c1492 instead of a separate 20000-ceiling run — the stop and the cost record
   happened live on real Thalos.
   *Cost if wrong:* None.

### What stands, and why

- **`LogFailedNodeRecorded` logs input and output tokens only.** The log line says that a failed node was recorded;
  the full usage, cache reads and writes included, is in the record itself and on `daedalus.manufacture.tokens`.
  Adding two fields changes no behaviour.
- **The `MinimumTestProjects` floor.** It was set to the count of test projects when the guard was written, and its
  Red line, raising it to 8, names a real failure. The floor only proves the scan reached the test projects; a new
  project raises the count and leaves the guard as strong as it was.
- **The long doc-comment lines** in `ChannelOutboxServiceCollectionExtensions.cs`, `CliHostSchedulingWiringTests.cs`
  and `ApiThalosConfigurationTests.cs`. `dotnet format` accepts them, and rewrapping them is cosmetic. The outbox
  sentence, now at line 67, names the library's 5-minute default, and the same list item opens with the shipped
  20-minute lease.
- **The audit's "Closing the gaps" table.** The audit is the record of the milestone 2 audit as it ran; the owner
  decision written below the table supersedes its proposal, and the re-audit writes the new verdict.
- **The precondition guards without Red lines**, such as the squad-enabled check in `TurnBudgetDriftTests`. Each guards
  a test's premise, not a claim of the code under test; it fails only when the setup itself breaks, which the failure
  message names.
