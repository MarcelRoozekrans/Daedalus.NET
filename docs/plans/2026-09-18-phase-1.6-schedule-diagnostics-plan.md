# Phase 1.6 — schedule diagnostics implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer "a digest didn't arrive — where did it die?" across all five places it can die, through one diagnosis consumed identically by a Blazor page and an agent tool.

**Architecture:** One `IScheduleDiagnostics` in `Daedalus.Application`, implemented in `Daedalus.Agents` where both the scheduling stores and the outbox are reachable. It returns a **verdict**, not rows. A thin controller and a Radzen page consume it; a read-only `[ThalosToolType]` consumes the same interface, so page and tool cannot disagree.

**Tech Stack:** .NET 10, EF Core 10 + PostgreSQL, `ZeroAlloc.Outbox` 2.5.2, Blazor WebAssembly + Radzen.Blazor, Thalos.NET 0.5.0. Tests: xunit, NSubstitute, AwesomeAssertions, Testcontainers.

**Spec:** `docs/plans/2026-09-18-schedule-diagnostics-design.md`
**UI contract:** `docs/plans/2026-09-18-phase-1.6-ui-contract.md`
**Design system:** `docs/design/MASTER.md`

## Global Constraints

- **Domain stays framework-free.** `Daedalus.Domain` references only `CSharpFunctionalExtensions`.
- **Application must not reference Infrastructure.** Enforced by `CleanArchitectureTests`. The DTO and the interface live in Application; the implementation does not.
- **`Daedalus.Web` references only `Daedalus.Application`** — anything a page binds to must live there.
- **Time comes from injected `TimeProvider`.** No `DateTime.UtcNow` anywhere.
- **A store that writes an outbox row inside its own transaction is scoped** and injects `ApplicationDbContext` directly — never `IDbContextFactory`. Established in phase 1.5; `EfCoreOutboxStore`'s `UseTransactionAsync` requires connection identity.
- **Only ever add nullable fields to `ChannelMessageQueued`.** The outbox stores it as an opaque serialized payload; rows queued before a field ships deserialize with it defaulted.
- **Radzen only. Tokens only.** No second component library, no literal hex in a component, no new webfont — all product-wide decisions per `MASTER.md`.
- Conventional commits, free scopes. **Commit bodies must not contain nested parentheses** — release-please silently drops such commits.
- **Assume nothing is pinned until you have seen it fail.** Every test below has an explicit failing step; do not skip it because the implementation is obviously absent.

### Task 2: `FailedAtStep` on the execution

`Fail()` records that a run failed and why, but overwrites the step it was at. The only place "failed during the Writer step" survives today is the prose of an operator notice that may itself have dead-lettered — and this page exists to answer *where*.

**Files:**
- Modify: `src/Daedalus.Domain/Entities/ScheduledRunExecution.cs`
- Test: `tests/Daedalus.Tests.Unit.Domain/Entities/ScheduledRunExecutionTests.cs`

**Interfaces:**
- Produces: `RunStep? FailedAtStep { get; private set; }`, set by `Fail()`.

- [ ] **Step 1: Write the failing tests**

```csharp
[Fact]
public void Fail_records_the_step_it_was_at()
{
    var execution = NewExecution();
    execution.BeginScout(Now);
    execution.RecordFindings("three open PRs", Now);   // now at Writer

    execution.Fail("provider returned 529", Now.AddSeconds(3));

    execution.Step.Should().Be(RunStep.Failed);
    execution.FailedAtStep.Should().Be(RunStep.Writer,
        "the page exists to answer where a run died, and Step is overwritten by Fail");
}

[Fact]
public void FailedAtStep_is_null_until_a_failure()
{
    var execution = NewExecution();
    execution.BeginScout(Now);

    execution.FailedAtStep.Should().BeNull();
}

[Fact]
public void Fail_twice_keeps_the_step_of_the_first_failure()
{
    // the second Fail is called from Failed, so naively capturing Step would record Failed
    var execution = NewExecution();
    execution.BeginScout(Now);
    execution.Fail("first", Now);

    execution.Fail("second", Now.AddSeconds(1));

    execution.FailedAtStep.Should().Be(RunStep.Scout,
        "the step that actually failed is the one before the first Fail, not Failed itself");
}
```

The third is the one that matters. `Fail` is callable from `Failed`, so a naive `FailedAtStep = Step` on the second call records `Failed` — which is useless.

- [ ] **Step 2: Run and verify they fail**

Run: `dotnet test tests/Daedalus.Tests.Unit.Domain --filter FullyQualifiedName~ScheduledRunExecutionTests`
Expected: FAIL — `FailedAtStep` does not exist.

- [ ] **Step 3: Implement**

Add the property with a private setter and XML docs explaining why it exists. In `Fail()`, capture it **only when it is not already set**:

```csharp
FailedAtStep ??= Step;   // the first failure's step is the real one; Fail is callable from Failed
Step = RunStep.Failed;
```

- [ ] **Step 4: Run and verify they pass, then commit**

Run the same filter. Expected: PASS.


```csharp
[Fact] public async Task A_schedule_due_in_the_past_with_no_execution_is_Overdue()
[Fact] public async Task A_recently_updated_non_terminal_execution_is_Running()
```

The eighth is the one that would ship wrong: **absence of a dead letter must read as delivered.** Dispatched rows may be pruned, so "no row found" and "no dead letter found" are different questions, and conflating them reports every old successful run as undelivered.

The fourth needs `FakeTimeProvider` either side of the threshold, not only in the middle.

- [ ] **Step 2: Run and verify they fail**

Expected: FAIL — the type does not exist.

- [ ] **Step 3: Implement the verdict walk**

```csharp
private RunVerdict Classify(ScheduledRun schedule, ScheduledRunExecution? execution, DeadLetter? deadLetter, DateTime now)
{
    if (execution is null)
    {
        return schedule.NextRunAt > now ? RunVerdict.NotYetDue : RunVerdict.Overdue;
    }

    return execution.Step switch
    {
        RunStep.Failed => RunVerdict.Failed,
        RunStep.Done   => deadLetter is null ? RunVerdict.Delivered : RunVerdict.Undelivered,
        _              => now - execution.UpdatedAt > _options.StrandedAfter
                              ? RunVerdict.Stranded
                              : RunVerdict.Running,
    };
}
```

`DeliveryUnknown` is **not** produced here — it is produced by the caller when the outbox read throws, so this method stays a pure function of what it was given.

- [ ] **Step 4: Implement the outbox read**

Query `OutboxMessageEntity` through `ApplicationDbContext` — the library maps it there via its own `AddOutboxMessages()` and exposes the type publicly. Narrow in the database by `TypeName == typeof(ChannelMessageQueued).FullName` and dead-letter status and a `CreatedAt` window, then deserialize the survivors to match `ExecutionId`.

Record why, at the call site — a reviewer will ask why `IOutboxDashboardStore` was not used:

```csharp
// IOutboxDashboardStore is the intended seam, but its OutboxEntry carries no DeadLetterError — it can
// say WHICH messages died, never why, which is half of what this page reports. Neither route can filter
// by a payload field in SQL, so both must deserialize candidates; this one also returns the reason.
```

**Wrap the read so a failure yields `DeliveryUnknown` rather than failing the page.** Degrade, never blank.
