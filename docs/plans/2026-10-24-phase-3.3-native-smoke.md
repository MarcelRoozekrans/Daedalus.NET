# Phase 3.3: the native run of the CLI

The third runtime evidence of milestone 3, after `docs/plans/2026-10-17-phase-3.1-native-smoke.md` and
`docs/plans/2026-10-21-phase-3.2-native-smoke.md`. 3.3 replaced the Anthropic SDK and OllamaSharp with our own
`ZeroAlloc.Rest.Anthropic` and `ZeroAlloc.Rest.Ollama`, through Thalos 0.20.0. 3.2's CLI stopped at C3, the SDK's
reflection JSON. This records how far the natively published `Daedalus.Cli` now gets.

## How it was run

- **Commit:** `e1acb2ce` on `phase/3.3-own-llm-clients`, run on 2026-10-31. It is `7f612bc4`, the end of Task 21 and
  the second ratchet move, with `main`'s `0e0f8e74`, a CI retry, merged in.
- **Publish:** not on the agent VM. The `native-publish` workflow published the three targets in run 41175139481,
  on `ubuntu-24.04`, with the command 3.2 recorded. The `.dbg` files are dropped and `.mcp.json` is in the artifact.
- **Run host:** the agent VM itself, glibc 2.41. The binaries now link on Ubuntu 24.04, glibc 2.39, so the
  `ubuntu:26.04` run image of 3.2 is no longer needed.
- **Stack:** the Postgres of `eng/measure/`, under the harness's container name, network and port, started by hand.
  The CLI needs no Keycloak. The schema was applied with the JIT runner, `dotnet run --project src/Daedalus.Migrations
  -c Release`, as `stack_up` does: EF Core's migrations and the workflow engine's 13.
- **CLI** ran as `measure-cli.sh` runs it: in the directory of the binary, with a stdin that stays open and never
  delivers a line, `ConnectionStrings__daedalus` set to the harness's `PG_CONN`. Logging was Information for every
  category, not just `Microsoft.Hosting.Lifetime`, so the stop shows. No `ANTHROPIC_API_KEY` and no
  `ConnectionStrings__ollama` for the boot.

## Run result

The CLI did not reach "Application started". C3 is gone. The first stop is now EF Core, which 3.5 owns.

| Target | Got as far as | Failure | Owner |
| --- | --- | --- | --- |
| CLI | `Host.StartAsync`, the hosted services' `StartingAsync` | C4, EF Core model building | 3.5 |

### C3: gone

3.2's run stopped while `Host.StartAsync` resolved the hosted services, in `AnthropicChatClientProvider`'s
constructor. This run resolved all of them, the Thalos chat client provider included, and went on to call their
`StartingAsync`. Before the stop it logged the start banner and the Thalos skill and memory notices. Those report no
embedding generator, as expected without `ConnectionStrings__ollama`. Then the Rag.NET memory schema was created.

### C4. CLI: EF Core still refuses to build its model

- **Exception:** `System.InvalidOperationException: Model building is not supported when publishing with NativeAOT.
  Use a compiled model.` "Hosting failed to start", exit code 1. "Application started" was not logged.
- **Top of the stack:**

  ```text
  Microsoft.EntityFrameworkCore.Internal.DbContextServices.CreateModel(Boolean) + 0x1d9
  Microsoft.EntityFrameworkCore.Internal.DbContextServices.get_Model() + 0x1a
  Microsoft.EntityFrameworkCore.DbContext.DisposeSync(Boolean, Boolean) + 0x1b0
  Microsoft.EntityFrameworkCore.DbContext.<DisposeAsync>d__82.MoveNext() + 0x143
  Daedalus.Agents.Skills.PostgresSkillStore.<ListAsync>d__8.MoveNext() + 0xe5
  Thalos.Skills.SkillSyncService.<SyncAsync>d__13.MoveNext() + 0x45b
  Thalos.Skills.SkillSyncService.<StartingAsync>d__7.MoveNext() + 0x28a
  Microsoft.Extensions.Hosting.Internal.Host.<ForeachService>d__17`1.MoveNext() + 0x104
  Microsoft.Extensions.Hosting.Internal.Host.<StartAsync>d__14.MoveNext() + 0x2c8
  ```

- **Why at boot:** Thalos' `SkillSyncService` syncs the skills directory into the store in `StartingAsync`, and the
  Daedalus store, `PostgresSkillStore`, is EF Core. It is the same cause as M1 in the native Migrations runner,
  reached from the CLI for the first time.
- **Predicted by:** IL2026 on `PostgresSkillStore`'s constructor, through `ApplicationDbContext`'s constructor, "EF
  Core model building; removed with EF Core in milestone 3 phase 3.5". The same key names the other EF Core stores
  the CLI builds: `PostgresConversationMap`, `PostgresRoleCharterStore`, `PostgresMemoryStore`,
  `PostgresAgentSessionStore`, `AgentSessionCrashRecovery` and `WorkflowRunRecordStore`.
- **Local unblock:** none was tried. A turn through the console channel goes through the conversation map, the
  session store and memory, all EF Core, so getting past the skill sync would only move the same stop.
- **Owner:** 3.5, which replaces EF Core with ZeroAlloc.ORM.

### The native turn: not attempted

The plan's Step 3 is one native turn through the console channel with the key set. The host never started, so there
was no channel to send it to. On 2026-10-31 the owner moved "reaches Application started" to 3.5 and ruled that the
turn is not attempted, so none of the approved spend was used. The 3.3 design's finish line records the amendment.
The native evidence for our Anthropic client is Thalos' `NativeProbeTests` in Thalos CI. The probe runs
`AnthropicChatClient` natively, sync and streaming, over recorded fixtures with no network, and it checks the text,
the finish reason and the four usage numbers.
