# UI Design Contract: Navigation and flow review

**Phase:** 2.13
**Date:** 2026-10-15
**Design spec:** `docs/superpowers/specs/2026-10-15-phase-2.13-navigation-and-flow-design.md`
**Inputs:** `docs/regression-report-2026-10-13-1033.md`, issues #347 to #351 and #354

This contract is what `ui-review` audits the phase against. It changes existing pages more than it adds new ones, so most
sections name the component that changes and how.

## Design System

Design system sourced from `docs/design/MASTER.md`; the CSS (`src/Daedalus.Web/wwwroot/css/daedalus-theme.css`) wins
where the two disagree. No new tokens, gradients, fonts or component libraries are introduced.

### Colors

Only `--rz-*` tokens. The severities this phase uses:

| Use | Token |
|---|---|
| Primary action (New task, Create, Sign in) | `--rz-primary` |
| Awaiting approval, needs attention | `--rz-warning` |
| Failed run, refused form | `--rz-danger` |
| Running, informational | `--rz-info` |
| Succeeded, pull request opened | `--rz-success` |
| Muted (cancelled, no outcome) | Radzen `Light` badge |

**One badge shade everywhere (regression minor):** status badges use Radzen's solid `BadgeStyle` with `IsPill="true"` on
both Tasks and Runs, through `RunStatusBadge`. Tasks stops styling its own.

### Typography

Radzen `TextStyle` only, as MASTER.md describes. Every page has the shared page header: an `H4` title and a `Body2`
caption, with no icon beside the title.

### Spacing

`RadzenStack` with explicit `Gap` in `rem`, following the existing pages. The content column keeps the single width 2.12
set.

### Component Library

Radzen.Blazor 8.7.5 only. Material icon names in the menu and on actions only.

## Status mapping

Unchanged from MASTER.md, with these two fixes:
- A timeline step whose outcome is `none` and whose kind is not one of the always-shown kinds renders **no badge**. Today
  it shows a NONE badge.
- `RunStatusLabels` stays the only mapping. `failureReason` text, defined below, never replaces the badge; it goes in the
  Failed alert.

## Components

### Component: `SignedOutLanding` (new, `Pages/Home.razor` when anonymous)

- **Purpose:** what a visitor who is not signed in sees at `/`.
- **Content:**
  - the product name;
  - one sentence on what Daedalus does, taken from the README's opening line;
  - one primary **Sign in** button that starts the OIDC login and returns to `/`.
- **Not shown:** menu, counts, data or illustrations.
- **States:** none, because it is static.
- **Visual:** centred in the content column on the body background, with no gradient.

### Component: `NeedsMePanel` (new, `Pages/Home.razor` when signed in)

- **Purpose:** what needs the signed-in person, in order of urgency.
- **Sections, each a `RadzenCard` with a `H6` heading and a count:**
  1. **Awaiting approval**: runs with `Awaiting` / `human_approval`. Each row shows the task title, the time it has
     waited and an **Open gate** link to `/runs/{id}`.
  2. **Running**: runs in progress, with their task title and current node.
  3. **Failed in the last 7 days**: task title plus `failureReason`, linking to the run.
  4. **Recent pull requests**: the 5 most recent runs with a `prUrl`, each with its task title and a link to the PR.
- **Primary action:** one **New task** button (primary), which opens `TaskCreateDialog`. The four coloured
  quick-action buttons and the icon beside "Quick Actions" are removed.
- **Data:** `GET /api/workflow-runs` (status filters) and the tasks it carries. There are no new endpoints. If a filter
  is missing, the plan adds it to the existing endpoint.
- **States:**
  - Loading: a skeleton line per card.
  - Empty card: one muted line, for example "Nothing waiting for approval."
  - Error: a `RadzenAlert` (Danger) with the reason and a Retry button. Each card fails on its own.

### Component: `TaskCreateDialog` (changed)

- **Fields, in order:**
  1. **Project**: a required `RadzenDropDown`. Each option shows the project name with its repository as secondary
     text. It is filterable and replaces the GUID box. With exactly one project, it is preselected.
  2. **Title**: required.
  3. **Description**: required, multi-line.
  4. **Priority**: optional, default Medium.
  5. **Complexity**: optional, default Medium.
  6. **Prompt**: optional, collapsed under "Advanced". When empty the API uses the description.
- **Removed:** Phase, Parallel Group, Dependencies and Files to Modify.
- **Actions:**
  - **Create** (secondary): creates the task and closes the dialog.
  - **Create and manufacture** (primary): creates the task, starts its run and navigates to `/runs/{id}`.
  - **Cancel**.
- **States:**
  - Submitting: both buttons are busy and disabled.
  - A field error is shown under its field.
  - A refused create shows a `RadzenAlert` (Danger) inside the dialog with the API's ProblemDetails `detail`. The
    dialog never closes silently.
  - If manufacture is refused after the task was created, the dialog closes onto the Tasks page with an alert naming
    the reason. The task exists, and Manufacture can be pressed there.

### Component: `TaskEditDialog` (changed)

The same fields as Create and the same ProblemDetails alert, with no manufacture button.

### Component: `TasksGrid` (changed, `Pages/Tasks.razor`)

- **Columns:**
  - **Title**, which takes the free width;
  - **Project**;
  - **Status** (`RunStatusBadge` linking to the run, as 2.12 did);
  - **Pull request** (a "#N" link to the PR, or "—");
  - **Priority**;
  - **Updated**;
  - **Actions**.
- **Removed:** Prompt and Iterations.
- **Actions:** **Manufacture** gains a visible text label "Manufacture" beside its icon and the accessible name
  "Manufacture". It shows for the statuses 2.12 defined.

### Component: `RunHeader` (changed)

- "Started by" shows `startedByName` and falls back to "unknown". It never shows a subject GUID.
- The pull request link is a `RadzenLink`, styled with the primary token and an external-link icon.
- When the status is Failed, the Failed `RadzenAlert` shows `failureReason`. When the reason is missing, it shows "The
  run failed; the reason is in the timeline."

### Component: `ReviewVisits` (new, replaces the latest-only view of `ReviewEvidence` on `RunDetail`)

- **Purpose:** every review visit of a run, newest first.
- **Per visit:**
  - a header with the visit number, its verdict badge (Approved / Rejected) and, if rejected, the rejecting lens;
  - per lens, a collapsible list with `checked` and the findings, each finding as `file:line` and its scenario;
  - beside a rejected visit, implement's `review_response` for the turn that answered it, under the heading "How
    implement answered". If there is none, it says "No response recorded".
- **Data:** a `reviewVisits` list on the run view (new). `review_response` is shown to the operator only. It stays
  withheld from the reviewer's own dispatch.
- **States:**
  - No review yet: "No review has run yet."
  - Unreadable records: the view's error text, in an alert, as 2.12 did for deferred findings.

### Component: `MainLayout` (changed)

- **Menu groups:**
  - **Home, Tasks, Runs, Projects**;
  - divider, then **PRD Generator, Agent**;
  - divider "Operations", then **Schedules, Costs**;
  - divider "Admin" (admins only), then **Git Repositories**.
- **Removed:** Executions.
- **The Runs awaiting-count badge** stays as it is.
- **Signed out:** no sidebar and no menu toggle. The header shows only the logo and **Sign in**.
- **Below 768px:**
  - the sidebar overlays the content (it does not push it), with a dimmed backdrop over the page;
  - it closes on navigation, on a backdrop tap and on Escape.
- **Header, compact below 768px:** the logo, the menu toggle and a user icon button that opens a menu with the name and
  **Log out**. The name and Log out never wrap.

### Component: `PrdGenerator` (changed)

All content is constrained to the column, with no horizontal overflow at 375px. Long PRD text wraps, and preformatted
blocks scroll inside their own box.

### Component: `Agent` page header (changed)

The shared page header gains the `H4` title "Agent" and a `Body2` caption.

### Component: loading screen (changed, `wwwroot/index.html`)

The full-viewport gradient is replaced by the body background, the product name and a Radzen-styled progress
indicator in `--rz-primary`.

### Changes to existing components

- `Pages/Executions.razor` is deleted with its menu item.
- MASTER.md's "Data-heavy pages" reference moves from `Executions.razor` to `Runs.razor`, which follows the same
  conventions.

## Layout Specification

### Desktop (≥1280px)

The 2.12 chrome is unchanged: a 260px sidebar open, a header and one content column.

```
Home (signed in)
┌──────────────────────────────────────────────────────┐
│ H4 Home                                  [New task]  │
│ Body2 caption                                        │
├──────────────────────────┬───────────────────────────┤
│ Awaiting approval (n)    │ Running (n)               │
├──────────────────────────┼───────────────────────────┤
│ Failed in last 7 days(n) │ Recent pull requests      │
└──────────────────────────┴───────────────────────────┘
```

The Run page has the 2.12 layout. The Review tab holds `ReviewVisits`.

### Tablet (768px–1279px)

The sidebar starts collapsed, as today. Home's cards stack in one column, ordered awaiting approval, running, failed,
pull requests. The Tasks grid hides Priority and Updated.

### Mobile (<768px)

- **Single column.** The sidebar is an overlay with a backdrop, closing on navigation. The header is compact, with a
  user icon menu.
- **No horizontal page overflow on any page at 375px.** Grids scroll inside their card, as 2.12 established.
- **Dialogs:** `TaskCreateDialog` is full-width, with its buttons stacked: primary on top, then Create, then Cancel.

## Interaction States

### Page-level states

| State | Behaviour |
|---|---|
| Signed out, any data page | Redirected to Keycloak sign-in by `AuthorizeRouteView`, then returned to the same page |
| Signed out, `/` | `SignedOutLanding` |
| Session expired (token refresh fails) | The stored user is cleared, then a redirect to sign-in, returning to the same page. No "Please log in" alert anywhere. |
| Loading | Skeleton or spinner per card or grid, never a blank page |
| Empty | One muted sentence saying what is empty and, where it applies, the action, for example "No tasks yet. New task" |
| Error | `RadzenAlert` (Danger) with the API's reason and Retry, scoped to the failing section |

### Form behavior

- Required fields are validated on submit and on blur, with errors under the field.
- An API refusal shows ProblemDetails `detail` in the dialog's alert, and the form keeps its values.
- Success: Create closes the dialog and the new task appears at the top of Tasks. Create and manufacture navigates to the
  run.

## Accessibility Requirements

- Every icon-only control has an accessible name: the menu toggle, the user menu, and the Manufacture button (which
  also gets visible text).
- The overlay sidebar:
  - is `role="navigation"`, labelled "Main";
  - traps focus while open;
  - returns focus to the toggle on close;
  - closes on Escape.
- The dialog has focus on Project when it opens. The submit buttons say what they do: "Create", "Create and
  manufacture".
- Status is never colour alone: badges keep their text, and failed runs keep the reason as text.
- Contrast is at least 4.5:1 for text and 3:1 for controls. The sidebar toggle test from 2.12 stays.
- `ReviewVisits`' collapsible lens sections are buttons with `aria-expanded`.
